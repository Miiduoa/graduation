# 社團幹部後台試辦

網頁從「我的社團」的「社團後台」進入。沿用群組的 `owner`（會長）、`admin`（幹部）、`member`（社員），每次請求重新確認目前學校與社團的有效身分。會長可以設定或解除幹部；會長交接沿用既有群組交接流程。其他既有角色在後台僅有社員能力。

所有開關預設關閉。開放單一社團時，伺服器需設定 `CLUB_ADMIN_ENABLED=true` 與 `CLUB_ADMIN_GROUP_ID=<試辦群組識別碼>`；網頁需設定 `NEXT_PUBLIC_CLUB_ADMIN_ENABLED=true`，手機需設定 `EXPO_PUBLIC_CLUB_ADMIN_ENABLED=true` 並重新建置。只有客戶端開關不會取得伺服器權限。此變更未開啟任何環境的開關。

## 操作與資料

- 會長與幹部可建立活動、查看私人名單、下載 CSV，並於活動期間核對已報名社員後簽到。社員於活動開始前可報名或取消自己的報名。
- 活動位於 `groups/{groupId}/clubEvents/{eventId}`，每人報名位於其 `registrations/{uid}`。沿用既有 Firestore 與伺服器函式，不新增服務或關聯式資料表；無 migration，不需搬移或刪除既有資料。
- 建立、報名與簽到皆使用交易。客戶端重送建立時沿用同一活動識別碼；一個社員在一場活動只有一份報名文件，重複簽到保留首次時間。
- 名單姓名優先取目前學校的既有公開目錄，缺少則使用群組社員姓名；仍缺少時顯示「未提供姓名」。學號、電話只提供給會長／幹部，取群組社員欄位或學校相符的既有使用者資料；缺少時顯示「未提供」。不建立或補造個資。
- 社員回應不含其他人的原始帳號識別碼、學號、電話或逐人報名紀錄。規則另阻擋社員直接讀取他人社員文件，以及任何客戶端直接讀寫活動／報名文件；非社團群組讀取行為維持原狀。
- CSV 包含同一份伺服器快照的社員欄位與各活動報名／簽到人數，使用 UTF-8 BOM、引號跳脫及公式字串防護；僅會長與幹部可下載。
- 統計依目前有效社團社員的有效報名計算，離社及取消者不列入；簽到人數來自這些報名中的已簽到文件。簽到率為簽到人數除以報名人數，零報名顯示「尚無報名」。活動數為已保存活動數，無虛構趨勢或成長率。

## 範圍與限制

網頁提供完整操作；手機在社團詳情提供唯讀社員姓名、角色、活動時間與報名／簽到人數，不提供私人欄位、建立、報名、簽到或匯出。原有手機社員管理頁受新的社團隱私規則限制，一般社員請使用社團詳情的唯讀名單；群組討論維持既有入口。

試辦上限為 500 位有效社員、100 場活動、每場 1,000 份歷史報名文件。超過時拒絕完整報表，不截斷後呈現錯誤數字；目前未做封存或分頁。先採幹部現場人工核對簽到，不含 QR、代簽自助機制、活動編輯／刪除、預算核銷與簽核。畫面採手動重新整理與操作後重讀，不宣稱即時訂閱或離線成功。匯出時畫面採用與 CSV 相同的交易快照；之後其他人的操作需重新整理才會顯示。

## 驗證與回滾

權限與計數單元測試使用合成交易資料；規則與交易整合測試僅連本機模擬器，專案識別碼固定為 `demo-nuni-club`，未設定模擬器位址時立即拒絕執行。Web／Mobile 元件測試使用合成回應，另回歸既有群組畫面與群組授權測試。

回滾先關閉伺服器與兩端開關，隱藏入口並拒絕操作；保留已建立的活動與報名資料。若需回退程式，撤回本次提交即可，不需回退資料結構；請保留或另行審核社團社員個資的讀取限制，避免重新開放私人欄位。此提交未部署規則、函式或客戶端，也未執行 migration。
