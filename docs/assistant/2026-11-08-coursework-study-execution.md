# 從 nuni 作業建立準備行程

## 使用者可以完成的事

手機課表助理查到 nuni 課堂作業後，可按「安排準備時間」，選定作業並填寫日期、開始與結束時間。也可接著說：

> 幫這份作業明天 19:00 到 19:30 安排準備。

助理沿用已查到的課程、作業名稱、確切作業識別與參考期限，先顯示完整預覽。使用者按「確認建立準備行程」後，助理重新查詢原作業；資料仍符合預覽時，才透過既有個人行程執行器保存，並讀回同一筆行程核對。成功卡可直接開啟該筆個人行程。

這個操作記錄使用者安排的準備時段。作業的提交狀態仍由 nuni 課程服務提供；來源卡可直接回到原作業。手機通知是另外的明確設定。

## 分工與現有功能相容

- `nuniCourseworkStudyIntent` 只選取剛才查到的來源與使用者明確指定的時間，不產生行程寫入權限。
- `NuniCourseworkStudyAction` 提供精確作業選擇、時間輸入、預覽、確認與停止操作。
- `nuniCourseworkStudy` 保存當次預覽的完整來源，負責確認前重查及執行交接。
- `assistantCalendarExecution`、操作紀錄與回執仍負責行程去重、保存、讀回、結果不明與重新開啟後的核對。

本次不重做其他分支的自動空堂與讀書計畫演算法。時段由使用者明確指定；畫面說明仍需核對課表。既有個人行程執行器會檢查個人行程重疊。

## 來源條件

一份可預覽的來源必須同時具備：

1. 目前有效的 nuni 帳號及所選學校；Firebase 身分不混入此流程。
2. 一堂可核對的已存課程，以及原 workspace 綁定或使用者已選定的課程。
3. 原清單中的唯一作業 ID、來源查閱時間、作業名稱與明確截止時間。
4. 作業仍開放，來源未見本人繳交紀錄。
5. 有效且含時區的期限，以及 `現在 < 開始 < 結束 <= 期限` 的明確時段。

同名作業會顯示分開的選項與期限。序號依畫面中的順序解讀，不依另一份完整清單重新排序，也不因標題相同而選第一筆。

## 真正寫入前的核對

確認動作使用原 assignment ID 重新執行 `answerNuniCoursework`。下層既有 resolver 重新核對已存課表、課程連結、有效學生身分與指定 workspace；不會用同名課程替換失效來源。

準備行程橋接再核對同一份作業的名稱、精確期限、開放狀態與本人繳交紀錄。任何變動或讀取失敗，都不開始新的行程操作。新資料必須重新呈現供使用者核對，不能偷偷改動已預覽的時段或名稱。

每個非同步邊界保留目前帳號、學校與工作狀態檢查。停止、離開畫面、登入 context 置換或來源異動會使尚未開始的後續操作失效。來源查詢有等待上限；逾時後才返回的來源不能啟動寫入。

來源查詢和本機行程保存是不同服務的動作。畫面分開呈現來源核對時間與行程讀回時間；前者是建立前的觀察，不表示原作業會持續同步。

## 去重、結果不明與恢復

預覽只存在這次對話的記憶體中。完整來源保存在私有映射，公開草稿與事件固定後不可變。將草稿轉為 JSON 再還原，不會恢復確認權限。預覽階段不建立 generic 行程 proposal，也不向操作紀錄登記嘗試。

同一份草稿已嘗試後，後續操作只會核對原 operation ID。保存回應遺失或讀回失敗時，結果保持待核對；不產生新的 ID 重做。

全新來源草稿如果遇到同名、同時段的既有行程操作，會要求先核對個人行事曆。現有通用行程紀錄沒有 assignment 來源證明，因此不能把另一份同名作業的回執當成這份作業的新成果。並行的相同事件草稿也不能同時取得新的執行機會。

重新開啟 App 後，已嘗試的行程沿用既有操作紀錄找回並讀回核對。未確認的來源預覽不會自動恢復成可執行工作。停止操作也不會宣稱撤銷已經保存的行程：已送出原生儲存的操作保留原 ID 核對卡；來源在途中更新時，仍提供唯讀的行程紀錄核對入口。

## 對話分派與資料處理

來源式指令在一般單筆與批次行程 parser 之前處理。「這份作業」或作業序號不能降級成普通事件標題。日期不完整、來源不存在或來源已更新時，只顯示修正或重新查詢入口。

完整的普通事件名稱，例如「明天 19:00 到 20:00 安排英文作業複習」，仍走原有一般行程流程。

包含 `courseworkRead`、作業準備選取或個人行程的對話卡，以及各自前一則使用者問題，均排除在後續一般模型歷史之外。準備行程只保存必要的行程欄位；不將作業內容、來源識別或聊天全文藏入 `source.rawText`。
