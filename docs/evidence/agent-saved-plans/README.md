# 校園計畫保存與續做

## 學生流程

校園帳號在手機助理取得今日或七日學習計畫後，可按「儲存這份計畫」。回到助理時，從「繼續已儲存的計畫」或「校園工具」查看，逐步記錄「我已處理」、開啟課程／課表／公告核對，也可刪除計畫。nuni 平台帳號則在「課業助理」取得計畫，從「已儲存計畫」分頁接續。計畫與進度留在本機，依帳號種類、帳號與學校分開保存，登出時清除。

保存的是原問題、計畫、逐日安排及最多五個摘要步驟的個人進度。勾選不是繳交回執，逐日安排內的全部課程與作業也不會因此標為完成。上限十二份，不自動刪掉舊計畫。

「依目前資料重新規劃」重新同步可授權的資料，再使用現有手機規劃流程；原計畫與勾選保留。原問題中的「明天」「本週」會依當下日期重新解讀，畫面明示這會建立新計畫。未送出的聊天草稿不受影響。讀取保存版本本身不會要求模型或網路。

## 重新規劃時核對變動

新計畫前會顯示「這次調整了什麼」，列出原內容、本次內容與需要核對的原因。已確認的提前截止會排在新增待辦之前，長清單先顯示五項，可展開完整內容。學生可直接開啟原計畫，確認後再另存新計畫；不自動覆寫或移植個人勾選。

- 作業使用授權讀取結果的課程與作業識別配對，保存所有已讀取項目，不依前三項摘要的排序猜測。期限以實際時間點比較，等價的 UTC 與台灣時區表示不會被當成延期。
- 部分讀取、來源不可用、識別缺少或重複都會顯示無法核對的範圍。完整摘要不再列出某項作業也只表示「本次未列出」，不判定已繳交、取消或完成。
- 課表只比較共同的台灣日期，以整天清單呈現節次、名稱與教室差異。規劃日期前移不當成停課；同名課程及重複筆數仍保留。
- 重新整理時間與真正的來源同步／課表保存時間分開。沿用同一次同步會明示；來源比原計畫更舊時，不推論作業異動。
- 舊版計畫仍可讀取。沒有保存來源識別時，只顯示可核對的課表差異，並說明作業部分無法對照。

## nuni 平台帳號的今日與七日規劃

「課業助理」新增「整理今日重點」「規劃未來七天」，也可直接輸入規劃問題。資料由目前登入的 nuni session 與所選學校核對，不借用 Firebase uid、校園摘要或雲端模型；不需下載 GGUF 模型。讀取已保存課表可在手機完成，核對 nuni 作業仍需要網路。

- 課表使用 `readAssistantTimetable` 的完整 records，包括只匯入課表、尚未建立手動課表的情況。按台灣日期展開，保留單日停課、調課、週日補課及跨夜上課的實際鐘點。
- `CampusAgendaDay.scheduledClasses` 保存明確時區的起訖時間。它與舊計畫的 `courses` 節次欄位分開，不能把分鐘換成虛構節次；課間時段與重疊從這份鐘點快照推導，不額外保存一份可能過期的計算結果。
- 作業只查課表明確連結的 nuni 課程，重新核對 active/student membership 與課程來源；不依同名課程自動配對，也不把未連結的工作區當成本校作業。
- 未連結課程、來源讀取失敗或達來源筆數上限時，會說明不能完整確認的範圍。沒有出現在這次計畫中不代表已繳交或已取消。
- 規劃、保存、個人勾選與重新比對沿用相同流程。按鈕規劃與重新規劃保留未送出的草稿；取消或失敗可重試原請求。
- 平台計畫的服務入口只導向 nuni 課程或個人課表。歷史作業識別只供比較，不能當成 Firebase 課程、提醒或提交的授權。

平台路由的 session 失效時，不回落到同一手機仍登入的 Firebase 帳號。平台登出接入保存計畫清理；本機清理失敗仍保留待完成登出狀態，可重試，不能因伺服器已撤銷 session 就忽略尚未清除的計畫。

本輪未更改校方資料擷取、模型下載或任何正式寫入開關。

## 從即時計畫開啟指定作業

nuni 帳號剛產生的計畫，可從優先事項、逐日截止清單及規劃日期範圍外的作業按「查看這份作業」。入口保留該筆作業的帳號、學校、學年、學期、工作區與作業 ID；同名課程與同名作業不會以標題配對。跨學期連結不一致時不產生精確入口，一般課程入口仍可使用。

按鈕出現不代表沿用規劃時的權限。每次點擊都會重新讀取目前課表連結、指定工作區的學生身分與課程來源，以及該工作區的作業清單；讀取結束再確認連結未被替換或移除。只有同一份作業仍可核對時，才交給正式 `NuniWorkspace`／`NuniCourses` 接收畫面，重新載入該作業與繳交區域。重新命名、改期或已繳交的同一 ID 仍可開啟核對；目標不見時不改選同名項目。

核對期間鎖住連點，帳號、學校、登入狀態、目標或畫面改變會中止舊請求，遲到結果不得跳轉。讀取或導覽失敗時，留在計畫卡片並提供「重新核對這份作業」；重試會重新檢查來源。此操作不提交作業、不建立提醒或行事曆事件，也不清除聊天草稿。

離開助理時，navigation blur 會撤銷該次開啟；助理仍留在導覽堆疊也不例外。即使先返回助理、舊結果才回來，仍須重新點擊才開始新核對，舊請求不能覆蓋新選擇或新請求的等待狀態。

精確入口使用的 `nuniSource` 僅存在即時計畫。保存與還原都明確丟棄這個欄位；即使舊資料被加入同名欄位也不恢復導覽資格。歷史卡片不呼叫即時作業 renderer，只保留固定服務入口與重新規劃功能。用於比較的歷史識別維持原用途，不能拿來還原私人作業導覽。

## 鐘點課間與作業準備建議

鐘點課表不只列出課程，也標示兩堂已知課程之間的時段與課程重疊。`campusClockAvailability` 先核對日期與明確時區的時間，將跨夜課程裁切至當日，再合併占用區間。課程包含另一堂課、兩堂課緊接，或同時有多堂重疊時，都不能產生虛構空檔。首堂課之前、末堂課之後與沒有課的整天，不會被推論為可安排時間。

來源不明、時間非法、單日超過 80 堂或尚有未定位課程時，不推導時段。本期未填上課星期的課程會列入 `ignoredCourses`；舊學期的未排課紀錄不會影響本期計畫。卡片與語音使用相同計算；歷史計畫只依當時保存的課程顯示，仍須核對現在的課表與私人行程。

nuni 規劃對前三項優先作業提出準備建議，使用下列固定範圍：

- 只有仍開放、未繳交且具備未來明確截止時間的作業，才會建議準備時段。逾期或期限不明的作業維持核對提示。
- 只取課間的 08:00–22:00，課前後各留 10 分鐘，開始時間向上取至五分鐘刻度。每項先給完整 30 分鐘，結束不晚於截止時間；這不是作業工時估計。
- 依期限順序分配，已使用的時段從剩餘範圍扣除，避免多份作業排到同一時間。找不到符合條件的時段會直接說明，不延長截止時間或填滿整個空白日。
- 重疊時段會另列為優先核對步驟，但不擠掉逾期與 24 小時內截止的作業；準備建議避開所有已排課程。最多仍為五個摘要步驟，完整逐日清單保留。
- 建議只保存在計畫文字中，不建立行事曆事件、不提交作業。通勤與私人行程仍須由學生核對。重新規劃會重算建議，原計畫與勾選保留。

[PR #509](https://github.com/Miiduoa/graduation/pull/509) 另外提供今日／明日空堂的自然語言查詢。本輪沿用現有 `scheduledSavedClasses` 解析來源，僅補齊計畫與歷史鐘點快照的分析，不重做該 PR 的問句與追問入口。合併該 PR 時，可讓其來源解析後的 `savedClassGaps` 委派此純函式，保留同一套半開區間語意。

## 保存資料的一般邊界

- 保存時間、原規劃日期及原整理時間各自顯示。歷史優先順序標為「規劃當時」，不用保存時間冒充資料更新時間。
- 歷史卡片只提供帳號種類允許的固定服務入口，不恢復當時的授權摘要，不直接建立提醒或跳轉至保存的私人作業目標；nuni 平台帳號不開啟 Firebase 校園公告或課程頁。
- 帳號種類、帳號 ID、學校 ID 使用完整 tuple 作鍵值，並在資料內再次比對。對話、憑證與完整授權 snapshot 不會一併保存。
- 同範圍讀寫依序處理。相同快照重存保留進度；不同快照另存，不以 `assignment-0` 這種排序位置繼承勾選。
- 格式檢查只還原明確欄位，限制路由、日期、筆數及 UTF-8 大小。毀損或無法讀取的資料不會當成空清單覆寫。
- `comparisonBasis` 只供歷史展示，不能還原作業導覽、提醒或寫入權限。原計畫保留 200 KB 內容額度，另給比較資料 350 KB 的有界額度，整個儲存區仍限制 900 KB；超額會保留原資料並回報失敗。
- 登出開始即撤銷儲存 session、清空畫面，再等待已接受的寫入結束後刪除。登出失敗時舊 session 不會復活，學生可以明確重新載入。
- 正在重新規劃的讀取也綁定同一儲存世代；撤銷時中止並清除比較內容。取消、換帳號、換學校與延遲回應不能重新帶回原計畫資料。
