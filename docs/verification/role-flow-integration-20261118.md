## 整合後的使用流程

| 情境 | 實際行為 |
| --- | --- |
| 尋找功能 | 五主入口分清課務、生活與交流；所有服務預設呈現常用項目，搜尋可找到收合項目。 |
| 同時修課與授課 | 首頁依真實課程、門市與平台資格顯示工作；已顯示的教師課程不再重複查詢或列三次。 |
| Google 使用者開啟 App | 先進課程、訂單、帳號或今天的安排；課程按鈕固定帶 `tab: courses`。 |
| 工作區重入 | 新的明確導航重新套用目標；原 route key、同帳號草稿及結果未知時的核對流程保留。 |
| 訪客找服務 | 生活／交流可只列免登入服務；公開餐廳不會因其點餐父入口需要帳號而消失。 |
| 店家申請與日常營運 | 依待審、補件、準備門市、營運或核准未指派狀態呈現下一步；既有門市優先進工作。 |
| 教學與校方申訴 | Google 課班、學校課程與課務申訴使用各自的實際來源；舊管理入口有可用出口。 |
| 返回或讀取失敗 | 保留合法的搜尋、分類、展開與草稿；帳號／校園改變及撤權後隔離舊內容。 |

所有角色的工作、完成條件及現有服務範圍集中於 [ROLE_WORKFLOWS.md](../ROLE_WORKFLOWS.md)。角色名稱不替代課程、棟別、門市或平台的實際授權。
