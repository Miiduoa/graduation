# 公開交流、學校資訊與跨功能查詢接續

## 本輪結果

延續 PR #631 的課務、活動與地圖流程，加入兩項可以直接回覆來源資料的服務：所選校園的平台公開交流，以及教育部學校聯絡資訊。既有 task plan 會分別顯示每項結果；準備行程仍需原有確認與讀回，查詢結果不算寫入完成。

| 使用者需求 | 實際行為 |
| --- | --- |
| 查公開貼文 | 以目前 Platform session 讀取所選校園的公開動態，顯示看板、作者顯示名、時間與摘要。 |
| 查學校地址，查學校電話 | 分別保留地址與總機的查詢投影；附官方來源與資料快照日期。 |
| 查未交作業，安排今天下午讀書30分鐘，查公開交流，查學校資訊 | 讀取課務、核對同步課表與個人行程、準備原有簽章讀書卡；公開交流與聯絡資料獨立讀取。 |
| 查清大公開課程，查學校地址 | 公開課程使用明確指定學校；學校地址仍使用目前已選校園，畫面標出校別。 |
| 來源失敗後只重試該步驟 | 重新讀取失敗的公開來源，不重建或送出原有讀書／餐點卡。 |

能力目錄仍有 45 項服務，其中 **18 項有資料讀取、5 項可準備待確認操作、27 項維持入口**。5 項 prepare 已包含於 18 項 read；這是程式契約，正式可用性仍依登入權限、來源及既有部署開關。

## 公開交流來源

沿用 `/social` 現有的 Platform 公開來源：`GET /v1/auth/platform/social/feed`。`tenantId` 固定為本題已驗證的 `schoolId`，最多五篇，沿原本 Platform session、取消訊號、四秒子請求與共用 API 額度。沒有使用 Firebase UID、私人學校社群、訊息、發文或其他寫入端點。

來源必須符合原 feed schema，且逐篇校別、識別、時間、版本與欄位長度通過驗證。跨校回應、重複識別、超額回應、額外私人欄位與格式錯誤會拒絕。下一頁保留為部分結果；成功空清單、404 未接通、503 暫時不可用各自分開，401／403 不會降級成空資料。正式 reader 不自動重試、不換帳號或來源。

貼文只以來源摘要顯示；本文、作者與看板名稱不送入模型 context，也不進下一輪模型歷史。模型只收到讀取狀態與筆數。以「照第一篇」「把這篇」等未驗證貼文推導行程或訂單時，提議工具會阻擋；使用者獨立明確指定的讀書安排仍可準備。

## 學校資訊來源

使用原學校資訊頁的 `getPublicSchoolInfo` 目錄，涵蓋 138 個正式校園 ID。資料來自教育部 115 學年度公開資料，快照日期 **2026-10-24**。查詢時間只表示讀取快照，不代表當天已向學校查核。

只接受 overview、address、phone、website 四種投影，固定所選校園；沒有其他學校的預設回退。每次結果解析重新核對原目錄的全部聯絡欄位、快照日期與來源網址。系所、個人電話、即時營運狀態與其他校名不會被當成總機查詢已完成。

## 查詢、重試與確認

明確完整語句不需要模型決定工具順序，使用既有跨功能圖與來源格式化。包含未知要求時，仍先讀取完整辨識的公開子句；模型失效或捏造數字不會覆蓋來源事實。其他活動／公開課程 reader 的來源失敗、部分資料與活動選取提示同時保留。

這輪也修正一項既有公開課程重試缺口：續接時工具的問句原本為空，導致精確查詢驗證失敗。現在只把已核對簽章內的原始問句提供給讀取來源驗證；執行問句保持空白、`writes=false`，且重試圖只容許原簽章的唯讀節點。原學校、關鍵字、星期、學分及綁定都需吻合，不重送已完成的寫入。

首頁取消查詢的回歸 fixture 也已修正：session context 使用正式的 43 字元格式，並把一般 `/ask` 與新的 `/map-read` 取消流程分開驗證。原草稿、新草稿、取消訊號與晚到回覆都保留實際斷言。

## 驗證與後續範圍

本輪測試涵蓋真實 adapter transport、來源校別／參數與回應篡改、取消／晚到身分變更、API 額度、資料格式化、模型上下文、跨功能讀書確認與冪等、未完成來源重查，以及原課程重試缺口。精確通過數與最新提交的遠端 CI 結果見 PR body。

這些自動測試使用合成帳號與來源；未以真人帳號發文、建立正式訂單或送出校方作業。通知、私人訊息、請假及宿舍私人紀錄仍需要可驗證的 Platform ↔ Firebase 學校身分連結。沒有新增套件、資料遷移、Firestore 規則或部署旗標；正式發佈仍依儲存庫規則與指定 App 審查。
