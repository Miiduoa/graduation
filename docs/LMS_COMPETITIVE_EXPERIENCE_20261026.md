# LMS 學習工作台改造 — 2026-10-26

## 設計目標

學生打開「課務」時，應立即理解 **現在要做什麼、什麼時候截止、從哪裡完成**。不必先猜資料藏在哪個課程群組。教師則需獨立的發布、批改、點名和通知工作流程，不混入學生的待辦 UI。

參考 [UniTable：準點課表](https://apps.apple.com/tw/app/id6745899492) 的課表、截止管理、Widget、好友空堂及 AI 助理等能力，但不複製競品外觀。Campus One 的核心差異是能追溯至有權限的校務與課程資料來源，並串接實際教材、作業及教學流程。

## 既有系統資料邊界

| 系統 | 用途 | 現況與限制 |
| --- | --- | --- |
| Firebase 課程群組 | 正式版課務入口、作業、測驗、教材、簽到 | 必須以登入者學校與已加入課程為範圍；實際發布/繳交狀態不得推測 |
| 校方 TronClass | 靜宜校方課程 | 需校方授權及有效 session；不能假設第三方資料和 Campus One 雙向同步 |
| Supabase LMS v2 | 新版課程模組與教學工作流 | 目前主要由開發示範旗標啟用；其 courseId 與舊群組 groupId 並非可任意互換 |
| 個人匯入課表 | 學生自行管理、好友比對、行事曆 | 應清楚標註資料為個人匯入，不能冒充學校正式課表 |

**禁止**將沒有授權的課程填入假資料、將未驗證的作業視為已繳交、將參考時間誤當校方禁止補交的政策，也不可在切換學校／使用者後保留前一個人的課業資料。

## 本次已實作的入口改善

- 行動端學習首頁：顯示修課數、未來七天到期、逾期數；支援全部／七天內／作業／測驗／點名切換；排序先看進行中的點名、逾期，再看即將到期事項。
- 每門課的入口保留現有教材、課程動態、成績導覽，並提供真實作業、測驗及未讀數量。
- 行動端課程內作業：不再只停在文字公告，而是直接打開現有 HomeworkSubmit 流程；已關閉作業只作查閱，不列為本週可執行任務。
- 網站版課程：增設教材、作業、近期到期摘要和分段跳轉，便於手機及桌面快速到達。
- 台灣時間處理：截止時間及日期使用 Asia/Taipei，避免跨午夜造成錯誤標籤。
- 測試：涵蓋校園／課程範圍、截止時間、過期／關閉作業、詳情導覽和網站捷徑。

## 下一階段必須完成的真實能力

1. **統一課務事件模型**：明確區分正式截止、學生自行提醒、作業繳交回執、教師評分及校方同步時間；顯示資料來源和最新更新時間。跨來源合併採唯一 ID，避免重複。
2. **課表與課務整合**：真實下一堂課、異動、補課、教室、教材、作業，統一「今天／本週」與課程詳細頁；課表先預覽才匯入，提供衝突提示和復原。
3. **作業生命週期**：教師發布與編輯、學生草稿／附件／送出／重送、明確回執、逾期政策、評分與回饋。每個寫入需實際後端回應，不能按了就顯示成功。
4. **測驗及討論**：題型、答題暫存、考試限制、交卷回執、討論、公告已讀、通知去重；學生和教師皆需端到端測試。
5. **多校適配**：各校官方系統、學期、節次時間、權限與資料可用性分別配置，無來源則顯示尚未支援，而非套其他學校資料。
6. **智能操作**：只能以已取得的課程證據提供提醒與摘要；不確定課程時先確認；寫入、刪除、寄信、提交作業前需人為確認。

## 視覺與操作驗收標準

- 不以彩色圖示方格代替資訊架構。採一致的層級：任務優先級、課程名稱、剩餘時間、明確行動。
- 同一類頁面共享字級、間距、圓角、分隔、互動樣式；主要強調色盡量單一，逾期與危險狀態用語意色。
- 操作區至少 44pt，支援字體放大、VoiceOver、Dark Mode、載入／無資料／失敗／權限不足和網路重試狀態。
- 查詢最近作業最多 2 次點擊；進入明確的作業詳細與繳交介面最多 3 次點擊。
- 不用未經證實的「百分之百完成」、「AI 自動完成」等宣稱取代實際狀態。
- 不在未經驗證前直接部署正式網站或合併 main。
