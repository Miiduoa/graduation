# Campus One 介面規範

Campus One 使用暖白底、深綠主色與清楚的文字層級。Nuni 課程空間、學校服務與其他整合保留各自必要的帳號說明，共用同一套介面。

## Web

- 頁面使用 `SiteShell`，共用主要內容地標、跳到內容、離線提示、頁尾與安裝提示。需要不同帳號操作的頁面以 `header` 傳入頁首，不另建外框。
- 頁寬與留白由 `--page-width`、`--page-padding-inline`、`--page-padding-block` 控制。標題使用 `--page-title-size`；窄螢幕不依賴固定卡片寬度。
- 主動作用 `--brand` / `--on-brand`，錯誤、成功與警示使用對應的語意色。連結按鈕必須保留前景色，不能被外框的連結預設樣式覆蓋。
- 表單採用共用 `Input`、`Textarea`、`Select`、`Button`。標籤需連接欄位，錯誤需連接說明文字，所有控制項保留鍵盤焦點與至少 44px 觸控高度。
- 自動、淺色、深色與使用者選定主題都遵循同一組變數。助理元件沿用品牌色，沒有獨立的裝飾色盤。

## Mobile

- 色彩、間距、圓角由 `ui/theme.ts` 提供。實心按鈕的文字使用 `onAccent`、`onDanger` 或 `onSuccess`，避免在深色模式固定使用白字。
- 讀取全域主題的共用元件必須訂閱主題更新；使用 `useThemeVersion` 或 `useThemeStyleSheet`，不能只讀取模組載入時的樣式。
- 可操作卡片的無障礙名稱需包含任務內容，不能只剩「查看」等通用動作。

## 內容與驗收

- 文案先說明使用者能做的事。助理入口使用「詢問助理」等具體動作；資料來源、不確定性與重要操作確認仍須清楚呈現。
- 沒有真實資料時顯示適當的空白或未開通狀態。測試資料不得當成正式服務成果。
- 每次修改共用樣式，檢查桌面與 320px 窄螢幕、淺色與深色、鍵盤操作，以及登入中／失敗／無資料狀態。認證、授權與繳交行為需維持既有回歸測試。
- Web 本機建置與元件測試不取代實機、正式環境或商店審核驗收。
