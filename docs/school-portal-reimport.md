# 校務資料再次匯入：差異核對與原子更新

## 操作

在 PR #290 的校務預覽完成修正與選列後，選「核對重複與更新既有資料」。原有「確認匯入」仍只新增、不覆寫。新入口讀取本帳號與本校園的本機 ledger，列出新增、相同、資料有變更與無法唯一配對。

每筆差異必須選擇保留或更新，不預選覆蓋。無法唯一配對只允許保留，不由陣列順序猜測；缺少班別、同名重複資料與一課多時段可能需要返回原預覽補充或分批處理。沒有出現在這次擷取中的舊紀錄不會刪除。

確認前顯示新增／更新／保留筆數；相同的資料列不重寫來源。新資料未提供的可選 metadata 保留舊值；新的時間範圍取代舊時間整組，避免錯配時刻。零分與小數學分保留，空學分不當作零，文字成績不換算學分。資料仍為個人參考，不變更校方資料、學籍或修課權限。

## 一致性與撤回

新 service 沿用 personalImports.ts 的 per-owner/school 鎖與一次 checkpoint。確認時重新計畫，不信任 UI 傳入的配對結果，並與預覽前 records/batches 完整比較；若期間有編輯、同步或另次匯入，整批停止，要求重新核對。

更新保留原 record ID、importedAt 及 personal linkedCourseId，使用新的 revision batch 所有權，避免舊批次撤回刪掉更新紀錄。新增仍使用原 planPersonalImport 驗證／去重／上限。新增與更新只提交一次 ledger，任一錯誤均不局部提交。

完成畫面的二次確認撤回會恢復這次更新前的值及移除這次新增。receipt 僅保留於本次畫面記憶體；關閉或繼續下批後不提供這份 receipt。撤回前要求目前 records/batches 與本次結果完全一致，任何後續修改或同步都使撤回停止，不覆寫新版本。sync metadata 保留目前版本，未建立新的雲端同步或校務背景登入。

## 驗證界線

新增比較核心、真實 ledger 交易及 UI 測試；只 mock AsyncStorage、WebView 等原生介面，沒有替換 planner、service 或整合畫面。專項工作流程保留全部既有測試並加入新案例。完整測試結果以本次 head 的 CI 與 JSON 產物為準，不沿用前次綠燈。

本功能不是六校真實帳號驗收、背景同步或上線。原生 WebView、鍵盤與大型字型仍需真機測試；不以程式測試數宣稱已超越競品。
