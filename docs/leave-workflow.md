# 請假與課程核閱｜Campus One

## 使用者流程

學生：選擇學校與學校帳號 → 開啟「請假」→ 選日期／上午／下午／全天 → 從個人課表自動預勾，亦可手動增減 → 選假別、說明 → 建立站內請假紀錄 → 查閱各門課核閱進度與回覆 → 需要時在所有課程尚未核閱前撤回。

教師：開啟「請假核閱」→ 只看所屬學校、已指派課程的請假 → 按課程分別同意或不同意 → 不同意必須填原因 → 每門課獨立記錄處理人、時間與結果。學校管理者可核閱校內課程。

**重要邊界：Campus One 站內核閱不是校方正式准假，也不會自動修改正式出缺勤紀錄。** 尚未取得靜宜大學或其他校方學生請假系統的寫入 API 與簽核授權；不得在正式網站聲稱「已向學校送出請假」或「學校已核准」。使用者仍需依學校規定完成正式程序。

靜宜大學公告：<https://osacsc.pu.edu.tw/p/412-1063-5627.php?Lang=zh-tw>。其中有學生請假辦法與正式系統使用說明。

## 實作範圍

| 能力 | 目前狀態 |
| --- | --- |
| 學校帳號、切換校園時資料隔離 | 以既有 Firebase Auth、school membership 與所選校園限制 |
| 請假起訖日期與時段 | 日期合法性檢查，一次最多 31 天；假別依校方規定另行確認 |
| 個人課表帶入 | 僅採本人所選校園課表；有節次設定的校園會依日間時段預選，未確認節次的學校不憑空排除課程 |
| 申請與重試 | Functions transaction、UUID 去重；站內資料獨立標記 source=campus-one |
| 待處理、部分核閱、已核閱、撤回 | 由後端維護狀態；已處理的單一課程不允許第二次核閱 |
| 授課教師權限 | 對應 schools/{schoolId}/courseTeachers/{offeringId}；每次提交與核閱從伺服器確認 |
| 拒絕說明與異動紀錄 | 不同意要求理由；每次處理記錄 actor、timestamp（留在站內，不代表學校審核） |
| 其他請假系統歷史資料 | 站內讀寫只限 source=campus-one，舊正式紀錄不修改 |
| 校方正式送件與核准 | **尚未接通** |
| 醫療與公假證明上傳 | **未開放**，需正式授權、儲存控管與文件隱私政策 |
| 站內通知與提醒 | 尚未接上通知中心與逾期警示 |
| 學校逐項政策及期限 | 尚未以校方來源做機器可驗證的校別決策引擎 |

## 相對其他請假系統的競品差距

比較公開流程可觀察到若干正式系統能力：
- 靜宜大學：公開提供學生申請與教師審核操作說明及請假辦法。
- 義守大學：網路假單包含節次、佐證文件上傳、確認傳送、審核關卡、退件補件與郵件提醒。
- 國立臺灣海洋大學：官方教學務系統使用假單編號及相關行政流程。

相較之下，本版聚焦 **手機版更少步驟、自動預選課程、跨校隔離、每門課的狀態清楚可查**。與正式校務系統的校規驗證、附件、核准關卡、正式校方身分及通知仍存在落差，不宜稱為同等替代品。

## 發布前檢查

1. 執行 web 的 typecheck、lint、Vitest 與 build；Functions 的 Jest、lint，檢視 CI 結果。
2. 使用正式 Firebase 專案前，新增並確認 Firestore 合成索引已完成建置（含 schoolId、uid、source、createdAt 欄位）。
3. 部署四支 Functions：submitLeaveRequest、withdrawLeaveRequest、reviewLeaveRequest、listLeaveReviewQueue；Fly Functions 映射應確認與 callable client 相同，且沒有未授權存取。
4. 驗證三類帳號：學生、授課教師、學校管理者；拒絕跨校資料、冒用課程、代替其他學生、重新核閱、刪除中帳號與撤回已核閱案件。
5. 驗證手機 375px、390px、平板、桌機、OLED 深色模式、鍵盤與 VoiceOver；確認跳頁與重新整理不會發出重複假單。
6. 校方正式請假連結仍需逐校查證；不得把站內作業結果同步呈現在正式出缺勤紀錄。

本功能分支預設不自行部署正式站。未經 CI 與實際身分測試，不應合併進 main 或直接發布。
