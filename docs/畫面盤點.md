# nuni 畫面盤點

盤點範圍：`apps/web`（Next.js App Router）與 `apps/mobile`（Expo／React Navigation）。平台新頁接回既有 Campus One session，補齊 BFF 路由、工作階段隔離與安全登入返回；伺服器端權限、token／cookie 簽發規則、環境變數、Firestore 規則、資料庫與 migration 維持既有設計。Campus One 登入進門頁與舊站 HTML 轉發見「舊站 HTML 轉發」。

判定：

| 判定 | 意義 |
| --- | --- |
| **A 刪除** | 沒有站內入口或僅剩死碼；或新版已提供同樣功能且舊檔不再被導覽使用。本 PR 刪除。舊網址若可能被書籤則保留 redirect。 |
| **B 已決** | 產品已定案：刪頁／併頁／只調查。本輪依定案處理。 |
| **保留** | 現行產品畫面，有入口且仍在使用。 |
| **redirect 保留** | 舊網址已改成導向新頁，本 PR 維持 redirect、不刪網址。 |
| **待新版取代** | Campus One 尚無對等頁；現役功能仍轉發舊站。沒有替代前不可從轉發名單拿掉，否則等於刪功能。 |

## 舊站 HTML 轉發

先前 nuni-web 用 catch-all `/:path*` 把 Campus One 沒有檔案路由的路徑（含 HTML）轉到 loopback 舊站。這份進門頁清理**拿掉 catch-all**，有新版替代的舊畫面不再轉發、舊網址導新頁；沒有替代的現役功能仍轉發舊站，**待新版取代**。

| 路徑 | 誰在用 | 判定 | 處理 |
| --- | --- | --- | --- |
| `/auth/account` | 未登入進門 | 保留 | Campus One 新頁；舊示意卡不再轉發 |
| `/auth/find-school` | 舊找學校頁 | redirect 保留 | 307 到 `/auth/account`；找學校改在進門頁內用信箱／校名查找 |
| `/auth/platform` | 課班／教學入口會經過的平台登入殼 | 待新版取代 | 仍轉發舊站 |
| `/auth/platform/class-workspace/join` | 進門頁「課班／教學」 | 保留 | Campus One 新頁，舊網址不變 |
| `/auth/platform/class-workspace/new` | 開課班 | 保留 | Campus One 新頁 |
| `/auth/platform/class-workspace/cw_*` | 加入後的課班工作區 | 保留 | Campus One 新頁，舊網址不變 |
| `/auth/platform/ops` | `/admin`「開啟完整管理台」 | redirect 保留 | 307 到 `/admin/ops` |
| `/auth/platform/school-review` | `/admin`「審核學校申請」 | redirect 保留 | 307 到 `/admin/school-review` |
| `/privacy/deletion-status` | 商店或刪除回條可能用過的狀態頁 | 待新版取代 | 仍轉發舊站 |

其餘舊產品 HTML（`/academics`、`/staff`、`/learning` 等）Campus One 沒有對應頁時改 404。`/auth/account/token`、`/auth/session`、`/auth/platform/*` 端點與登入回調行為不變。

## `/lms-admin` 調查（本輪不改程式）

沒有獨立的 Next.js `/api/lms-admin`。子頁用瀏覽器 Supabase client 在 **page 元件** 裡 `from()`／`rpc()`；layout 用 `RequireAdmin` 包住 children。

`RequireAdmin` 行為（測試已鎖定）：

- **未登入**：顯示「請先登入學校帳號」，不 mount 子頁，不呼叫 `getSession`／`from()`。
- **已登入（含學生）**：永不 mount children；顯示「教學管理尚未完成帳號連結」（或未設定時「教學管理尚未開放」）。不讀另一套身分、不查管理資料。
- 因此學生或未登入直打 `/lms-admin` 及其子頁：**進不到管理內容，也讀寫不到課程／成員／成績彙總等資料**。畫面看得到「教學管理」殼與說明，看不到連結清單與表格。
- 子頁若被掛載，會在 `RequireAdmin` 外層就 `useEffect` 查表；現行 layout 擋住，所以這條路徑現在不會跑。資料最終仍受 Supabase RLS 約束（本輪未改）。

## 舊站三頁功能盤點（本輪已做成新頁）

權限與資料仍由 nuni-api 決定。閘門與寫入都走 Campus One 的 `__Host-campus-platform-session`（`/api/nuni`、`/api/platform-admin`），不再混用舊站 `__Host-campus-bff-session`。新頁沒有新增或放寬權限，也沒有改 token／cookie 名稱、session 簽發、環境變數、Firestore 或資料庫。Campus One BFF 以明確路徑與 body 白名單轉呼叫既有 v1 端點，授權沿用 platform-admin／nuni 的伺服器端檢查；請求保留 `X-Campus-Session`、同源檢查與 `redirect: 'error'`。

### 1. 課班加入與工作區

舊頁 `/auth/platform/class-workspace/join`、`/new`、`/cw_*`。

| 舊功能 | 狀態 | API（伺服器端授權不變） | 新頁 |
| --- | --- | --- | --- |
| 誠實說明橫幅（課班不是學籍／請假／證件／點餐）＋「知道了」 | 保留 | sessionStorage `nuni-class-honesty-banner` | 三頁都有 |
| 邀請碼 6–24 字、加入並進入課班 | 保留 | `POST /api/nuni/class-workspaces/join`（既有 BFF，後端同 class-workspaces/join） | `/auth/platform/class-workspace/join` |
| 未登入或 401 | 保留 | 不放寬 | 導 `/auth/account?returnUrl=…` |
| 開課班、建立後產生 100 人邀請碼、`?invite=` | 保留 | `POST /api/nuni/class-workspaces`；邀請 `POST /api/nuni/class-workspaces/:id/invites` `{maxUses:100}`（上限 100） | `/auth/platform/class-workspace/new` |
| 工作台：找不到課班／暫時打不開 | 保留 | GET class-workspaces/:id | `/auth/platform/class-workspace/cw_*` |
| 課堂開始／結束／簽到／名冊（出席、缺席、遲到） | 保留 | `/api/nuni/class-workspaces/:id/classroom-sessions`；名冊 GET `…/:sessionId/roster` → `{sessionId,present,absent,late}`；進行中 `state=open`；無碼簽到與結束 POST `{}` | 課堂簽到分頁 |
| 學生補簽申請／教師核准或拒絕 | 保留 | 僅限課堂 `state=closed`；學生 POST `…/:sessionId/makeup-requests` `{}`；教師從名冊 `absent` 成員的 `makeupRequestState === 'pending'` 取得待審項目，再 POST `…/:sessionId/makeup` accept／reject；沒有 GET `makeup-requests` | 課堂簽到分頁 |
| 章節、教材、作業、測驗、繳交與回饋 | 保留 | 既有 `/api/nuni` 課程 API | 課程內容分頁（沿用 Campus One 課程元件） |
| 邀請學生 maxUses 100 | 保留 | `POST /api/nuni/class-workspaces/:id/invites` | 邀請區 |
| 成員名單 | 保留 | GET `/api/nuni/class-workspaces/:id/members` → `members` | 成員分頁 |
| 掛靠班次申請（tenantId、sectionId、說明） | 保留 | GET `affiliation`／`affiliation-applications`；POST `class-workspaces/:id/affiliation-applications` | 掛靠分頁 |
| 教師／學生按鈕依 `memberRole` 顯示 | 保留 | 後端仍拒絕未授權操作 | 前端只做顯示 |

GET 課堂清單回 `{sessions: [...]}`；POST `check-in`、`end`、`makeup-requests` 直接回傳單一課堂物件，不包在 `{session: ...}` 裡；教師 POST `makeup` 決策回名冊。空參數的操作仍傳 JSON `{}`，已有簽到或尚未結束的課堂不提供補簽。

建立、加入與工作區都以帳號／context 隔離，工作區另以課班 ID 重建。登入載入、登出中或收到拒絕授權時清除對應私有內容；切換後的舊回應不能更新名冊、發出後續邀請或導頁。

### 3. 完整管理台

舊頁 `/auth/platform/ops` → 新頁 `/admin/ops`。`/admin` 的「審核學校申請」「人員、店家與課班」改指新頁。

| 舊功能 | 狀態 | API | 新頁 |
| --- | --- | --- | --- |
| 未登入／非營運人員 | 保留 | 不讀管理資料 | 與 `/admin` 同一套門：請先登入／沒有管理權限 |
| 分頁：學校／人員／店家／課班掛靠／紀錄 | 保留 | 學校、人員讀取、店家讀取、紀錄走既有 `/api/platform-admin`（後端仍是 ops/*） | 同分頁 |
| 開通、關閉（關閉後找校看不到，請假／證件／點餐一併停） | 保留 | 既有 schools open／suspend | 學校分頁（AdminSchools） |
| 加人：先有 school_admin，才可加 school_staff | 保留 | `POST /api/platform-admin/people/bind` → nuni-api `ops/people/bind`；body 為 `tenantId`、`email` 或 `personId`、`role`、`idempotencyKey`；同校狀態確認 `hasRoleAdmin` 後才開放 staff | 人員分頁「加人」；已 open 學校須有有效代操作，否則引導至學校分頁（AdminSchools）明確啟用，不自動授權 |
| 店家意向審核 | 保留 | GET `/api/platform-admin/merchants` → `interest`／`applications`／`catalog`；POST `/api/platform-admin/merchants/interest/:mpi/decision` `{decision, reason, idempotencyKey}` | 待審店家＋原監督列表 |
| 店家進件審核 | 保留 | POST `/api/platform-admin/merchants/applications/:tenant/:fma/decision` `{decision, reason, expectedVersion}`，不帶 `idempotencyKey` | 成功後重載；409 先重載供操作者確認最新資料，不自動重送 |
| 課班掛靠核准／拒絕 | 保留 | GET `/api/platform-admin/class-workspace-affiliation-applications` → `applications`；POST `…/:id/decision` `{decision, reason, idempotencyKey}` | 課班掛靠分頁 |
| 操作紀錄 | 保留 | 既有 audit | 紀錄分頁 |

舊 HTML 進 `/auth/platform/ops/:tab` 會 307 到 `/admin/ops?tab=:tab`。新頁沒有端點再打舊站 `/auth/platform/*` BFF。

加人先以 `GET /api/platform-admin/people?tenantId=…` 讀取該校授權狀態，成功回應也必須通過同校的完整狀態解析；已 open 學校的代操作另讀 `GET /api/platform-admin/schools/:tenantId/proxy`，到期即停用送出。店家清單使用既有嚴格投影解析器，進件決策帶目前 `version` 作為 `expectedVersion`。管理頁與表單依帳號／context／校別隔離，載入或登出中不繼續私有操作，舊請求的回應不影響新範圍。
