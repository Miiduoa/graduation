# 單次調課與一致時段

含資料庫變更：Mobile 將單次安排獨立存於 `users/{uid}/schools/{schoolId}/personalTimetable/exceptions`，內容為 `schoolId`、`classExceptions` 與 `classExceptionsRevision`。每週基準仍存 `current`，真正舊版的整份 set 保存不會觸及例外文件。沒有例外的舊資料等同沒有單次調整；沒有批次 migration。既有嵌入例外僅在正常保存時，以同一 transaction 保全至獨立文件並移除基準文件內的副本；規則要求保全成立才允許移除。Web 仍依現有政策只寫本機；Mobile 沿用本機與既有個人課表雲端寫入。不新增資料表、索引或背景服務。

課表上方的日期清單顯示實際安排；下方週格保留每週基準。選原上課日期及課程後，可只停一次、改期補課或只換教室。補課可另選起訖日期、時間及教室，最長一天，跨午夜須明填隔天結束日期。重疊可保存，但在保存前與實際課程清單均提示。可用「恢復原安排」移除例外。

`buildPersonalToday` 統一使用台北日期、學校節次表與明確鐘點，輸出起訖時間戳記。Web／Mobile 指定日期課表、今日卡、小工具快照與課前提醒均消費此結果。跨午夜補課會在兩天清單顯示，同一快照與提醒只保留一次。

人工調整獨立於匯入帳本保存，只包含白名單投影的原會次、原上課日期及穩定會次識別；不包含匯入來源原文、檔名或任意擴充欄位，完整來源仍留在個人匯入紀錄。更換匯入批次或列識別碼不會抹除例外。重新匯入改變會次時，無法配對的例外保留並提示待核對，不猜測套用到別堂課。教室來源更新後，人工單次換教室仍優先。每份課表最多保留 200 筆調整，需自行整理不再需要的紀錄。整份課表另有 UTF-8 JSON 200,000 bytes 保存預算，超量會在任何寫入前拒絕。

Mobile 課前提醒由使用者選擇開啟，需通知權限。開啟、前景恢復、課表或匯入變動時，先取消此功能舊通知，再依未來七天的實際課程安排課前 10 分鐘通知，最多 48 筆。關閉、換帳號、換校與登出會清除此功能通知；不取消其他功能的通知。舊讀取／排程請求不得重新填入已登出的通知。沒有背景連線，不保證未開 App 時得知其他裝置修改；七天後需再次開啟更新。未記錄的校方假日與學期終止仍需使用者核對。

例外編輯以 transaction 讀取最新版本，僅明確修改單次安排才遞增 revision；一般課程與分享保存保留最新雲端例外且不遞增版本；歷史來源快照若需投影清理，內容確實改變時才另遞增一次。過期編輯會拒絕並提示重載。離線 transaction 不會排隊或自動重送：草稿保留在此帳號／學校本機的獨立 `:draft` key。恢復連線重載以雲端安排為準，不以裝置時間覆蓋版本；提醒與小工具共用此讀取流程。可按「重新讀取雲端課表」取得目前安排，再按「檢視這台裝置未同步草稿」預覽後核對儲存；重載可回到雲端，明確保存單次安排成功後清除草稿。一般分享保存不會清除草稿。

## 驗證

使用合成資料驗證單次停課、另日補課、換教室、重疊、跨節、夜間、跨午夜、重新匯入與來源保留、各入口時段一致、通知停用與登出競態，以及兩條路徑真正舊版整份保存／恢復空例外後保存仍保留獨立例外文件。通知測試使用替身，不發出真實通知。沒有讀取環境檔、連線正式資料庫或執行 migration。

仍需實機確認 iOS／Android 通知權限、背景與前景更新、登出取消、系統通知額度；iOS 小工具離線／跨午夜／改課後重載與直達課表；兩端日期輸入、深淺色、大字體與小螢幕鍵盤操作。

## 回滾

未部署時先修正並完成 emulator 驗證，再由發布者安排規則先於新版用戶端上線；本次沒有部署。獨立文件需先有規則保護才可保存，不能先發布會寫入它的用戶端。

已發布時，先在新版關閉課前提醒並確認系統通知取消，再退到能讀取獨立例外及保留版本的相容版本。保留獨立文件、嵌入舊副本與本機草稿，不批次刪欄位、不還原整份使用者資料。原始舊版可在已分離後保存每週基準，但不顯示日期例外，不能當作完整功能的安全回滾版。尚未分離的歷史嵌入文件仍受防抹除規則保護，真正舊版整份保存會被拒絕，須先用相容版本正常保存；不可為此放寬防抹除規則。

規則回滾須保存目標版本，先以 emulator 驗證兩路徑舊版普通保存、獨立例外保留、嵌入例外保全、過期版本與刪除拒絕，再經發布者核准部署。完整撤回保護會重開例外覆寫／刪除風險，不能單獨撤規則。規則回滾不會恢復已覆寫資料。歷史來源原文不會因規則更新自動消失，應依核准方案處理；本次未執行資料清理或 migration。
