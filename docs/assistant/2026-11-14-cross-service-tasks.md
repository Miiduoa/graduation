# 跨功能任務：來源查詢、相依執行與結果核對

## 這輪解決的問題

原本 Web 助理按問題選最多八項工具；讀書規劃的選擇分支會排除部分其他服務，複合需求容易只做其中一段。手機的單一已學技能也可能在分析完整問題前直接回傳。這輪把可明確辨識的複合需求拆成有限、有順序與來源依賴的任務，並保留每一步的結果。

接續開發把清大／暨大的公開課程查詢接入同一條 Web 任務流程，修正公開查課捷徑吞掉後半句需求的問題，也讓複合查詢讀到的作業可以在下一輪接著找空檔、準備讀書行程。

程式從 `e4446262880c3d8188e0741f185d7aeebc3f944f` 的 main 開始；沒有將 #616 尚未合併的 TronClass writer 或 #590 的手機離線摘要修改混入本輪。

## 可實際接續的例子

| 使用者需求 | 這輪的處理 |
| --- | --- |
| 查今天課表，查未交作業，找相關教材，安排今天下午讀書30分鐘，查餐廳，查公車 | 查原課務 → 依已讀課程識別找教材 → 核對同步課表與個人行程 → 找空檔 → 產生原有簽章行程卡；餐廳、公車各自取得資料 |
| 查未交作業，安排今天15:00到16:00讀書 | 保留指定日期與一小時區間，從本次讀取的待辦選來源；確認前沒有新增行程 |
| 查今天作業，找今天30分鐘空堂 | 只查課務與空堂，不提升成建立行程，也不要求建立行程權限 |
| 查未交作業，安排今天下午讀書30分鐘，再點上次一樣的午餐 | 讀書與餐點各自準備確認內容；保留不同類型逐項確認，不能一個按鈕混成全部執行 |
| 查課表，開啟宿舍報修，查圖書館 | 課表回實際資料；尚未接到資料／執行器的服務明確標為需開啟接續，不當成報修或圖書館操作完成 |
| 查清大星期三3學分的資料庫與人工智慧課程，另外查公車 | 保留完整課名、星期與學分條件查清大公開來源；公車仍用目前綁定的校園，各自顯示結果與來源 |
| 查清大資料庫課程，查暨大人工智慧課程，查明天課表 | 兩校公開開課分別查詢；私人課表保持原帳號、原校園與明天日期 |
| 查未交作業，查公車 → 幫這份作業明天找30分鐘 | 下一輪帶回原作業與課程的精確識別；重新查原來源與空檔後準備確認卡，不從模型文字猜是哪一份作業 |

安排後沿用既有確認、來源重查、權限、版本比較、冪等與讀回回執。正式點餐 adapter 目前仍要求付款，因此本輪不開放免付款下單；測試中免付款 fixture 的送出與重送只用來驗證原卡片契約。

## 執行架構

`crossServiceRequest.ts` 將全句拆成可完整辨識的子需求。未知子句、命名作業、互相矛盾的日期／時段、否定、條件句或多段無法完整保留的安排，都回原有對話流程，不能只看到一個關鍵字就吞掉其餘要求。公開課名中的引用、逗號與「和／與」保留為查詢文字；其他引用仍不自動當成操作指令。

`crossService.ts` 只呼叫原本的 `createTools`，不直接呼叫寫入 API。讀書安排先依序核對課務、課表、個人事件與空檔，再把本輪觀察到的精確作業 ID 交給原提議工具。教材使用課務結果中的課程 ID。單一已觀察到的公車站點可以接續到站查詢；多個站點保留選擇入口。

- 同一句的省略日期可以繼承唯一明確日期，分別指定的日期保持分開；有歧義時不猜。
- 作業／測驗篩選與每次查詢期間保留到後續安排，不從整個工具快取任意挑第一筆。
- 同一識別如果在不同課程或作業／測驗中重複，拒絕自動安排，避免工具快取選到另一個來源。
- 任一必要來源讀取失敗、不完整、缺少同步課表，依賴該來源的安排停止；餐廳等獨立查詢繼續。
- 最多十六個任務節點、十六次工具呼叫；維持原 adapter 的每題十二次 API 額度與五十五秒請求期限。額度不足保留部分結果，不默默聲稱全數查完。
- 首頁／聊天既有寫入流程與設定旗標不變；這條流程不新增排程、背景執行、永久任務記憶或跨裝置自動接續。

這些明確複合流程不需要模型決定工具順序，不把資料送往模型，回應標為 `dataRead` 以免下一輪外送私人結果。聊天入口仍使用原本的登入、同源、session、同意與配額控制。

## 公開課程與私人任務共用流程

公開課程使用既有 `executePublicCourseOperation` 與校方公開快取，僅支援已核對的清大、暨大來源。查詢只傳學校、最多八十個 Unicode 字元的關鍵字與可選的星期／精確學分條件；不向公開來源傳帳號、session、歷史對話或私人資料。使用者指定的公開學校不會改變其他任務綁定的私人校園，畫面會在必要時標出私人查詢的校名。

`publicCourseCompoundRequest` 先保留各子句與原查詢條件。明確複合要求直接進跨功能執行器；包含未知任務時，整句保留給既有對話流程，提供 `get_public_courses` 工具。模型呼叫仍須精確符合本輪使用者已指定的學校、關鍵字與篩選，不能自行換校、改關鍵字或省略條件。課名中的「規劃」、日期或餐點詞不會觸發私人行程、取餐時間或額外私人預讀。

對話流程返回前，會逐筆核對完整的校別、關鍵字與篩選，在原額度內補查模型遺漏的公開來源。公開混合回覆由已驗證的資料產生，模型自行宣稱的課程筆數、學分或兩校已查完不會直接呈現；尚未完整核對的其他子句保留原文並明示未完成。模型服務失效仍可在剩餘期限內完成這些明確讀取；整題超時可以保留已驗部分，但使用者主動取消後不交付晚到結果。

公開課程沒有與私人課程 workspace 的可信對應，因此「查公開課程，找相關教材」會保留教材步驟為未完成，不以私人全部課程代替。若同輪另有已核對的私人作業來源，則沿該來源查對應教材。

公開工具算入每題十二次 API 額度，單次等待上限十二秒，且仍受整題五十五秒期限與取消訊號限制。個別使用者取消只停止自己的等待，不取消其他使用者也可能在等的匿名公開快取；已取消的題目不能再交付晚到結果。

伺服器與畫面共用結果核對：學校、來源網址、operation 回執版本、星期與學分條件都必須吻合。無效或明示不完整但不符合契約的來源不顯示為成功；合法的截斷與無法判定筆數標為部分完成。公開課程卡保留資料時間、來源、篩選及原有「帶入課表核對」入口。這是公開開課資料查詢與原匯入流程，不代表已選課、取得學分或完成校方選課。

純公開查課保留原本免模型同意的匿名入口；混合私人任務使用既有 Web V2 同意、session 與權限。手機及舊入口共用辨識器，遇到混合要求會保留需拆開處理的提示；本輪沒有宣稱手機已接上 Web 的公開課程複合執行器。

## 複合課務查詢後的接續

每個作業查詢節點只從自己的成功來源建立下一輪可用目標，保留原課程、作業／測驗類型、查詢日期與截止時間。重疊查詢會去重，最多保留十二個目標。已繳交、已截止、缺少有效截止日期，或同一識別對到不同課程／內容的結果，不提供自動安排。

任一相關課務來源不完整時不產生這組接續目標；獨立的公車或餐廳來源失敗不會清掉已完整核對的課務。這一輪若已準備讀書或重新點餐確認卡，也不另外提供可能造成重複準備的快捷安排。點選安排與自然語句接續都重讀原來源，使用既有權限、簽章、確認與冪等紀錄；私人結果不加入後續模型歷史。

## 能力目錄與畫面

`packages/shared/src/assistantTaskPlan.ts` 為現有服務目錄逐項標出目前 Web V2 的讀取、準備與入口能力。能力是描述，不是授權；服務本身仍檢查帳號、校園、角色及每筆來源。正式環境未接通的通知、訊息、宿舍、請假、學生證等不能因為有入口就當成可讀或可操作。

回應的任務清單採用共用解析器，限制版本、服務、節點數、欄位長度、相依順序及站內網址。畫面區分已完成、待確認、部分完成、尚未完成、開啟服務；無效資料退回一般回答。細節只在任務清單呈現一次，避免手機出現重複長段落。

卡片必須對應同一回覆中的操作識別。個人行程只有在精確回執再次核對通過後才顯示已完成；缺卡、錯誤回執、未知結果、保存未同步與取消仍保留各自狀態。備餐或導航入口不計為交易完成。來源標題以文字呈現，不能變成新的工具指令。

## 手機改善

`autonomousQuery` 先分析本輪全部意圖，再決定能否重用單一讀取技能。捷徑僅限工具與完整參數一致的單筆讀取；複合任務、寫入與需要重新查來源的操作走完整流程。

前置查詢按工具加完整參數快取，成功與失敗都只在本輪保留。必要來源失敗時不隱性重查或換用另一個篩選結果，也不接續相依寫入。回覆分別列出成功讀取與未完成項目；只有成功寫入且不是草稿，才可在摘要標為操作已完成。
