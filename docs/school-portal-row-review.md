# 校務匯入：逐筆欄位修正

延續 PR #290 的本人校務瀏覽與連續匯入。這次不新增另一套登入／儲存服務，不將入口配置冒充跨校私有資料驗收。

## 操作

表格擷取 → 選表格 → 整理預覽 → 每筆「修正欄位」→ 套用或取消 → 選擇要匯入的資料 → 最後確認儲存。

- 課表可修改課名、學期、課號、班別、學分、星期、節次、教室、教師。成績可修改課名、學期、課號、班別、學分與原始成績。
- 原始來源可展開核對，修改不覆寫 source.rawText、原始行號、校園、資料 ID 或修課關聯。不將手動修正變成校方認證。
- 已設定的校園以實際節次標籤換算起訖時間；表單會明示這項操作。未設定校園只保留原始節次／時刻，不套用靜宜的節次。
- 使用共用驗證規則。空學分不轉成零，文字成績、零分與小數學分保留；不猜測成績或放寬既有週末／時間規則。
- 修正後只移除該列已由表單重新確認的欄位錯誤；跨校、欄位數、引號結構及其他資料列的錯誤不會被清除。重複列提示依修正後資料重新計算。
- 全選／全不選／只選可匯入資料均為本人明確操作，涵蓋尚未展開的資料列。錯誤列不被默默刪除；修正被排除的列不會自動將其選回。
- 編輯中不能儲存、換列或重解析原文。套用後保留原始文字但鎖定避免覆蓋，重新整理需確認放棄逐筆修改。
- 仍使用既有帳號／校園隔離、儲存鎖、明確確認、去重、撤回及錯誤重試。沒有新增網路請求、模型費用、背景校務登入或權限。

## 驗證

新增共用核心與原生完整流程測試，並加入原有 School Portal Checks；保留先前所有測試，不降低門檻。涵蓋零值、空值、特殊分數、數字格式、節次對應、原始證據不變、錯誤重驗、結構與跨校錯誤保留、取消、批次選取、重新解析確認、切換帳號、儲存失敗重試。

本機僅完成 TS／TSX 語法轉譯及修改前主元件的 Git blob SHA 核對。完整執行結果以本提交的 CI 與測試 JSON 為準；Mock 校務網站與 WebView 不代表六校真實帳號登入或真機畫面驗收。

## 競品對照與尚待驗收

2026-10-27 查閱 UniTable 開發者 App Store 說明，已包含課表匯入預覽、行事曆同步與通知／小工具等能力：https://apps.apple.com/tw/app/unitable-ai-academic-partner/id6745899492 。本次只補齊「資料辨識不完全正確時，能在表單修復並安全完成匯入」這段流程，不宣稱已具備所有競品能力。

仍需六校授權帳號真實欄位核對、iOS／Android 真機鍵盤與大型字型測試、端到端結果、背景同步／通知及部署驗證。未放寬學校來源白名單，也不自動提交校方表單。
