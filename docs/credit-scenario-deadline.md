# 指定學期的修課比較

延續主線既有 CreditPlanScenarios／CreditPlanScenarioCard，不新增第二套情境控制或備份格式。在原規劃與比較方案下，選擇未來第 1～8 學期末，查看期限前排定學分、個人目標缺口、分類缺口及排在期限後的課程。個人每學期負擔提醒可以設定 1～40 學分，不代表學校上下限。

共用 creditScenarioDeadline 只接受相同已確認學分、目標、分類與非學分條件的方案；未來課程僅可改排學期或不排入，不能偷偷改變學分與課程內容。以百分之一學分的整數計算期限合計，不變更來源；未分配學期的 extra 不計入期限。整份完成後達總量與指定期限前達總量分開顯示。

分類資料未完整設定時保持未知；個人清單勾選不是校方認列。數學餘量不保證開課、先修、選課成功或畢業。條件僅存於元件記憶體，不新增雲端資料、授權或背景同步；期限與負擔提醒不寫進原本 JSON。原規劃更新時沿用既有比較失效保護。

## 可重現驗證

Credit Deadline Checks 以 PR 精確 head 執行核心嚴格型別編譯、Node 測試、Web 元件及既有情境控制整合測試，再用真正 Chrome 與專案 CSS 檢查 320／390／1440px、深色模式、延期、期限、無效輸入、分類缺口、容量與原資料不變性。資料是合成的，沒有校務帳號或雲端連線。原生元件測試由完整 Mobile Tests 執行。所有數字以這個 commit 的報告為準；沒有把未執行的真機測試當通過。
