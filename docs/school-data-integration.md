# 校務資料與 WOW Class 連線

## 資料來源

| 畫面 | 來源 | 可以表示的內容 |
| --- | --- | --- |
| 我的課表 | 靜宜 e 校園選課紀錄 | 校方回傳的課名、修別、學分、時間與教室 |
| 成績紀錄 | 靜宜 e 校園歷年修課明細 | 已讀取的學期、成績、學分及校方提供的平均、排名、操行 |
| 校方學分累計 | 靜宜 e 校園學分試算表的「修習學分累計」 | 校方列示的小計、畢業應修總學分與六個類別；小計不等於畢業採計 |
| 學分規劃 | 修課明細與個人規劃 | 成績推算的通過學分、手動規劃；不代表校方畢業審核 |
| WOW Class 課程 | 靜宜 TronClass 課程 API | 課堂、授課教師、學期與課堂連結；不代表正式選課或畢業學分 |

WOW Class 與 e 校園使用相同帳密，但使用不同的登入狀態。只有一個來源成功時，另一個來源應呈現待連線或暫時無法讀取，不可寫成成功的空資料。

校方說明：

- [WOW Class 登入方式](https://tdcenter.pu.edu.tw/p/406-1061-45102%2Cr1105.php?Lang=zh-tw)
- [新生 e 校園與學分試算表說明](https://freshman.pu.edu.tw/p/404-1118-9928.php?Lang=zh-tw)
- [學分試算表操作手冊，110 學年度起適用](https://c026.pu.edu.tw/var/file/59/1059/img/446/student01-110.pdf)：第 6 頁提供累計欄名及小計的語意；範例系所的門檻不能套用所有學生。

## Web 讀取流程

1. 學號登入驗證成功後，伺服器建立本人校務 session；成功建立的 WOW Class session 與這次校務 session 配對。
2. 瀏覽器以 Firebase ID token 呼叫同源 `/api/fn/getMyAcademicRecords` 或 `/api/fn/getMyTronClassCourses`。請求不含學校密碼、Cookie、學號或可選擇他人資料的 session ID。
3. 伺服器確認 token、學校、有效校籍及帳號狀態，選擇本人尚有效的 session，讀取指定來源。
4. 校方回應後再次確認帳號與 session；回傳帶有 owner、來源及讀取時間的必要欄位。來源錯誤不改寫成空陣列。
5. 前端核對來源與當前登入，忽略切換帳號或重新登入之前發出的回應。45 秒整體期限涵蓋 token、網路及 JSON 解析。

校務讀取與學號登入共用 Web 伺服器，不再要求瀏覽器另有 Cloud Functions 網址才能讀取成績。既有 `_puSessions` 的 `ownerUid + expiresAt` 索引繼續適用。

學分累計使用 `getMyAcademicRecords` 的 `creditOverview` 類型，沿用本人身分、校籍及有效校務 session 的前後檢查。來源僅讀取固定 `/grade_review/tab_1.php`，每次 HTTPS 請求有 10 秒／4 MiB 上限，最多跟隨一次受信任重新導向；不從成績總和推算校方欄位。Web 與 App 的學分頁獨立讀取此資料，成績讀取失敗不會擋住它。更新失敗可保留同一登入範圍內上次成功的數字，必須顯示原時間及更新失敗提示；失效連線與權限錯誤會清除舊結果。

TronClass 的「已結束」畫面狀態為 `completed`；伺服器 adapter 轉換為校方 API 的 `ended`。課程學期支援字串，以及校方 `{ name, code, id }` 物件格式。

## 原生 App

原生登入的課表、成績、學分與 WOW Class 分別回報讀取筆數與狀態。新登入清除舊校務快取；登出或更換帳號後，先前的網路請求不能重新填入快取。

登入同步回執在首頁與「我的」的學校帳號區持續顯示，不依賴登入畫面仍然掛載。它只代表該次登入同步，包含進度、來源摘要、時間及課務頁入口；沒有保存密碼、token、原始資料或 session ID。回執綁定 Firebase User 實例、UID、學校與登入次序，登出、換帳、換校或 token 過期立即失效。它只保留於本次 App 執行期間，不新增背景重試或磁碟儲存。

主要課表可讀取本人校方課程、預覽所有來源列，再透過既有重匯入差異確認與版本鎖寫入個人課表。原有手動紀錄保留，完成後切至來源學期，今日頁也能讀到相同紀錄。星期六日和精確鐘點可持久化；缺少學期或時間、非連續節次的資料保留原文，需本人補齊草稿再確認，不以當前日期或推估節次代填。重複資料沿用既有比對規則，無法唯一配對時不猜測覆蓋，並提供兩段確認撤回。

既有 Cloud Functions 學號登入端點只有在明確回傳 HTTPS 404 時，才轉至固定的 `https://nuni.tw/api/fn/signInPuStudentId`。此備援限於 `campus-one-tw` Firebase 專案，模擬器和本機測試登入不會送往正式網站。身分驗證、流量限制、登入關閉及其他正式拒絕都會停止流程，不繼續改走原生登入。

網站登入回傳的 custom token 必須成功交換成 Firebase 使用者，而且實際 UID 必須與回應相符，才建立 App 校務狀態、更新快取並保存已驗證的連線。從送出登入請求、交換 token 到資料同步，都會檢查目前帳號與登入次序；登出後才返回的 token 不得恢復先前登入，較早的請求也不得清除較新的使用者。

網站登入完成後，課表與成績直接使用本人授權讀取；App 重啟後也能帶 Firebase ID token 請伺服器尋找本人校務 session。資料端點採同樣的明確 HTTPS 404 備援規則，並核對回應的 owner、學校與來源。登入資料沒有 WOW Class 連線時，回報尚未連線，不因舊端點失效而自動反覆送出學校密碼。

WOW Class 課程清單亦可讀取網站端配對的本人 LMS session；已結束課程在原生 API 使用 `ended`，網站介面使用 `completed`。課表不能代填成 TronClass 課程，也不補造學分、教師 ID 或修課人數。課程連線開關關閉時，略過該來源並顯示停用狀態。

原生學分試算解析器保留小數學分、校方小計與文字成績。校方小計未取得時，不以歷年分數加總代填。只有原生 Cookie、沒有伺服器本人來源證明的資料，不應標示為經驗證的本人校務成績。

新增的 `creditOverview` 能力目前由 Web 服務提供。正式 `campus-one-tw` App 在非模擬器、非本機測試且 HTTPS 設定合格時，直接選用固定網站端點；其他專案及本機環境保持其設定端點，不轉送正式服務。這是該功能的初始路由選擇，不在 400、401、403 或其他正式拒絕後換端點重試。開啟學分頁才會讀取此總覽，因此登入回執中的學分結果不能代表此後總覽的最新狀態。

## 資料完整度

- 已讀取的筆數和學期數只描述本次回應，不宣稱已涵蓋全部修業期間。
- Web 後端的表格漏列會帶 `coverage.skippedRows` 並顯示部分讀取；無法辨識的頁面、登入頁或維護頁視為讀取失敗。
- 空白成績、0 分、0 學分、小數學分與文字成績均有個別語意，不以真假值互相代換。
- Web 的通過學分摘要帶 `source: derived-from-grade-rows`、`officialAudit: false` 及 `totalRequired: null`。它不處理完整的系所畢業門檻、抵免、重修採計或所有學制及格標準。
- 「校方正式採計學分」未取得時保持未知。WOW Class 課堂與課內成績不可用來填補此欄。
- 校方試算總覽的八個欄位只接受明確累計區塊與欄名，排除本學期資料、隱藏節點及其他區塊。缺值為 `null`，校方明示的 `0` 保留為零；所有欄位缺失、重複值衝突、登入／維護頁或無法辨識的格式均視為失敗。類別可能重疊，不自行相加，也不從小計推斷是否達到畢業條件。

## 驗證與實際環境

自動測試涵蓋 Cookie 輪替、重導、表格格式、小數與文字成績、TronClass 分頁、來源故障、帳號隔離、來源撤銷、請求逾時、快取清除、登入返回及頁面搜尋／切換。App 整合測試從學號登入、Firebase token 交換一路驗證至本人資料同步，另檢查每個等待階段的切帳與登出。

正式 Web 建置與 Docker standalone 執行檢查亦需通過，並檢查瀏覽器 bundle 沒有 Admin SDK 或服務帳號內容。兩種 Web 映像的建置範圍以精確清單帶入所需校務讀取、解析及日期模組，包含新增的學分累計解析器，不複製 Functions 服務入口或憑證。

這些測試使用合成資料與受控回應，不能取代真實學校帳號驗證。實際驗收須在登入開關已允許的環境中，核對學生自己的課表、各學期成績及 WOW Class 課程。不要在 issue、測試資料或日誌放入真實帳密、Cookie 或完整成績 HTML。

學分累計解析器的欄名依官方公開手冊建立，測試未使用真實學生成績；尚未以當前登入後 DOM 驗收。實際版型不符合識別條件時回報無法取得，不以公開範例中的學生數字填補。驗收時須另核對八欄、時間、學年系所適用範圍及校方「小計不等於畢業學分」的說明。

後端以 HTML 樹解析處理巢狀版面表格、五／六欄成績及合併儲存格。原生直連仍沿用非巢狀表格解析，這次涵蓋的測試格式為課表、五欄歷年成績及學分試算區塊；不能由後端測試推定原生解析器具有相同格式覆蓋。

舊校務 session 可能沒有這次新增的 WOW Class 配對欄位，需要重新連線。伺服器仍須能連到校方網站；網路或校方服務不可達時，重登不保證成功。老師僅有 LMS session 的流程不由本次學生校務配對讀取涵蓋。

本次不啟用學校登入開關、不變更 Firestore 權限，也不直接發布正式環境。部署應依專案現有流程，以經 CI 驗證的確切 commit 進行。
