# 校園計畫保存與續做

## 學生流程

校園帳號在手機助理取得今日或七日學習計畫後，可按「儲存這份計畫」。回到助理時，從「繼續已儲存的計畫」或「校園工具」查看，逐步記錄「我已處理」、開啟課程／課表／公告核對，也可刪除計畫。計畫與進度留在本機，登出時清除。

保存的是原問題、計畫、逐日安排及最多五個摘要步驟的個人進度。勾選不是繳交回執，逐日安排內的全部課程與作業也不會因此標為完成。上限十二份，不自動刪掉舊計畫。

「依目前資料重新規劃」重新同步可授權的資料，再使用現有手機規劃流程；原計畫與勾選保留。原問題中的「明天」「本週」會依當下日期重新解讀，畫面明示這會建立新計畫。未送出的聊天草稿不受影響。讀取保存版本本身不會要求模型或網路。

## 重新規劃時核對變動

新計畫前會顯示「這次調整了什麼」，列出原內容、本次內容與需要核對的原因。已確認的提前截止會排在新增待辦之前，長清單先顯示五項，可展開完整內容。學生可直接開啟原計畫，確認後再另存新計畫；不自動覆寫或移植個人勾選。

- 作業使用授權讀取結果的課程與作業識別配對，保存所有已讀取項目，不依前三項摘要的排序猜測。期限以實際時間點比較，等價的 UTC 與台灣時區表示不會被當成延期。
- 部分讀取、來源不可用、識別缺少或重複都會顯示無法核對的範圍。完整摘要不再列出某項作業也只表示「本次未列出」，不判定已繳交、取消或完成。
- 課表只比較共同的台灣日期，以整天清單呈現節次、名稱與教室差異。規劃日期前移不當成停課；同名課程及重複筆數仍保留。
- 重新整理時間與真正的來源同步／課表保存時間分開。沿用同一次同步會明示；來源比原計畫更舊時，不推論作業異動。
- 舊版計畫仍可讀取。沒有保存來源識別時，只顯示可核對的課表差異，並說明作業部分無法對照。

這次接入目前能產生 `CampusEvidencePlan` 的校園帳號流程。nuni 平台帳號原有課表／課業助理不因此新增完整七日規劃；未更改校方資料擷取或任何正式寫入開關。

## 資料與行為邊界

- 保存時間、原規劃日期及原整理時間各自顯示。歷史優先順序標為「規劃當時」，不用保存時間冒充資料更新時間。
- 歷史卡片只提供三個固定服務入口，不恢復當時的授權摘要，不直接建立提醒或跳轉至保存的私人作業目標。
- 帳號種類、帳號 ID、學校 ID 使用完整 tuple 作鍵值，並在資料內再次比對。對話、憑證與完整授權 snapshot 不會一併保存。
- 同範圍讀寫依序處理。相同快照重存保留進度；不同快照另存，不以 `assignment-0` 這種排序位置繼承勾選。
- 格式檢查只還原明確欄位，限制路由、日期、筆數及 UTF-8 大小。毀損或無法讀取的資料不會當成空清單覆寫。
- `comparisonBasis` 只供歷史展示，不能還原作業導覽、提醒或寫入權限。原計畫保留 200 KB 內容額度，另給比較資料 350 KB 的有界額度，整個儲存區仍限制 900 KB；超額會保留原資料並回報失敗。
- 登出開始即撤銷儲存 session、清空畫面，再等待已接受的寫入結束後刪除。登出失敗時舊 session 不會復活，學生可以明確重新載入。
- 正在重新規劃的讀取也綁定同一儲存世代；撤銷時中止並清除比較內容。取消、換帳號、換學校與延遲回應不能重新帶回原計畫資料。

## 驗證

本輪以 Node 22.23.4 驗證規劃器、儲存層、純比較、助理對話、保存介面與比較卡片，**6 組、194 項測試全部通過**，涵蓋 400 筆作業保存／還原、不同來源同名作業、期限與日期視窗、部分資料、重試及 session 撤銷。新增測試已納入 Mobile Agent Regression。完整手機 TypeScript 檢查通過；異動檔案 ESLint 無錯誤，原助理畫面仍有兩項既有的 effect dependency 警告。完整 CI 與最新精確提交的數量以 PR 驗證紀錄為準。

`Assistant Plans Browser` 工作流程使用正式 React Native 元件和主題，在 Chromium 檢查 390px 淺色與 320px 深色，包含長課名、過期計畫、台灣跨午夜時間、鍵盤展開、勾選、服務路徑、刪除取消、重新規劃、差異展開／收合、來源不足、回到原計畫、44px 控制區與水平溢出。只使用虛構計畫和明示的合成比較資料；提醒及私人作業導覽的原生元件若被誤啟用會使檢查失敗。結果與截圖保存為 `assistant-plans-browser` artifact。執行：

```sh
node scripts/qa/saved-campus-plans/build.mjs
python scripts/qa/saved-campus-plans/check.py
```

本輪本機 fixture 建置通過；Chromium 因 UNIX socket 限制未能啟動，尚未產生畫面，因此以 GitHub 的 `Assistant Plans Browser` 工作流程確認新版本結果。本機如已安裝相容的 Chromium，可設定 `QA_CHROMIUM_EXECUTABLE` 指定路徑；不設定時維持 Playwright 預設。瀏覽器檢查不能取代 iOS／Android 原生真機、正式帳號及實際資料來源的驗收。
