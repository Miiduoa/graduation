# 服務探索、返回與表單操作

延續 [介面品質改版](./2026-11-18-interface-quality.md) 與 PR #708，本輪把設計重點放在完成一段操作後仍能接著做事。工作分支已合入 `main` 的 `f4303c78bd00b2bcb89c2e49d8ca41e29b63ad37`；本輪新增變更限於 Web 介面、相關回歸與驗收腳本。

## 使用者看到的改變

| 情境                 | 原本的中斷                                    | 現在的行為                                                                         |
| -------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------- |
| 找校園服務           | 前兩筆資料自動成為大卡片，新增項目會改變主次  | 等權重的服務列按用途分組；桌機兩欄、手機單欄，名稱、用途、入口沿固定位置排列       |
| 搜尋後進入服務再返回 | 搜尋與分類只存在元件內，返回或重整會消失      | 查詢與分類保留在網址；輸入更新目前歷史項目，返回、前進、重新整理可接續操作         |
| 中文輸入             | 路由同步可能在組字尚未完成時覆寫內容          | 組字中的草稿保留於輸入框，完成後再同步網址，組字中的 Escape 不清空內容             |
| 重新進入今天         | 無條件套用全域舊捲動位置，可能跳過摘要        | 移除全域捲動快取，保留 Next 與瀏覽器的導覽及歷史位置處理                           |
| 短視窗開啟更多服務   | 固定控制區擠壓清單，面板可能蓋住頁首          | 根據實際頁首與底欄配置空間；短視窗整個面板可捲動，最末服務與關閉鍵皆可到達         |
| 放大文字填寫表單     | 部分標籤與欄位固定 px，手機 16px 覆蓋較大偏好 | 輸入框、標籤、提示、錯誤與按鈕共用字級設定；手機保留至少 16px 的輸入字級           |
| 小螢幕閱讀長對話視窗 | 固定標頭與操作列可能將內容裁掉                | 對話視窗以單一區域捲動，保持原生焦點限制，所有內容與按鈕均可到達                   |
| 閱讀長篇確認訊息     | 初始取消焦點可能把畫面直接捲到最下面          | 依實際幾何範圍決定初始位置；短訊息仍聚焦取消，長訊息從標題開始，Tab 再到取消與確認 |

服務連結持續使用既有校園參數白名單。目錄的 `q`、`category` 與錨點不會被錯當成目的服務的篩選條件。既有登入條件、點餐開關、帳號權限與資料來源維持原本契約。

## 動效與排版決定

搜尋工具列與分類呈現為同一組控制；清單使用分隔線、灰綠圖示與短說明來區分資訊層級。主次不再由資料陣列的前兩筆決定，也不為每個服務加入不同裝飾。

只在完整目錄與篩選結果切換時使用一次短進場，打字更新結果不逐列延遲播放。服務列保留按壓底色與箭頭回饋；對話視窗使用全站動效時間，關閉不等待動畫。系統及站內減少動態設定均停止位移與轉場。強制色彩模式保留選取、邊界與焦點指示。

## 驗收來源與界線

- 元件回歸：生活頁、頁首、服務選單、今天、共用欄位、Modal 與實際使用 Modal 的檢舉視窗。
- `scripts/campus-visual-smoke.py`：在正式 Next build 上實際搜尋、進入服務、返回、前進與重新整理；檢查原有校園範圍及新的篩選保留。
- `scripts/qa/interface-design/`：使用實際產品元件與 CSS，僅以合成來源替換帳號、學校、網路與 Next 路由邊界；此路徑用於版面與原生對話視窗測試，不用來證明真 Next 歷史導覽。
- 介面情境包含桌機、390px、320px、深色、200% 根字級、站內大字與兩種減少動態設定。另檢查 390×320／640×360 的服務面板，以及 360px 高視窗下的長表單。
- 原生 Tab 必須逐一到達輸入框、密碼顯示、選擇器、備註及兩個操作按鈕；Escape 關閉後回到開啟按鈕。長確認訊息必須先呈現標題，取消先於確認。
- 每份介面產物包含截圖、檢查結果及來源 SHA-256，結果以對應 head／merge checkout 的 GitHub Actions 為準。上一個 head 的通過紀錄不套用到本候選。

本輪本機 Chromium 因 socket 權限無法啟動；連線瀏覽器也無法存取這份本機預覽。因此瀏覽器驗收由既有 GitHub Actions 執行，未把本機啟動失敗算作通過。組字事件測試檢查 React 處理流程，沒有聲稱操作真實 OS 輸入法；手機版面也不等於 Safari／iPhone／Android 真機驗收。

## 參考

- [Apple — Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/)：保留脈絡、資訊層級與操作一致性。
- [Apple — Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：短促、有目的、可取消的回饋。
- [Next — Linking and Navigating](https://nextjs.org/docs/app/getting-started/linking-and-navigating)：原生 History API 與 `useSearchParams` 同步。實作另外核對本專案鎖定版本的 App Router，避免將 Next 內部 history state 當成外部更新傳回。
