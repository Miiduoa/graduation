# nuni 手機展示流程

這份流程以 **AI 校園助理如何幫學生完成一件事** 為主線，約 5–6 分鐘：整理課業、保存計畫、為指定作業安排準備時間，再開啟實際保存的行程核對結果。

內容核對於 2026-11-08，對應 main `040957b6b36f41c9f5558c1b8bbc61d3a9a5a7f7`。展示前仍需確認使用中的 App 版本、登入方式與服務設定；程式已合併不代表該版本已發布到所有裝置。

## 展示前準備

- 使用專用測試帳號與合成課程資料，先確認目前選定的學校。錄影時避開個人學號、私人訊息、帳號憑證及真實繳交內容。
- 主流程使用已驗證的 **nuni 平台帳號**，準備已加入的學生課程，以及一份仍開放、尚未取得本人繳交紀錄且期限在未來的作業。個人課表必須明確連結這門 nuni 課程。
- 在適用學期的課表中安排兩堂可核對鐘點的課，中間留出至少 50 分鐘，供助理找出 30 分鐘準備時間及前後緩衝；確認個人行事曆沒有占用該時段。找不到符合條件的時段時，可改用畫面的手動輸入。
- 確認裝置日期與台灣時間。當場讀不到課程來源時，改用下方「明確行程」流程展示本機執行，保留原本的來源錯誤提示。

上述課表查詢、nuni 課業規劃及明確行程執行不必先下載自由問答模型。一般模型對話與校園即時資料則依各自的模型、網路及服務設定運作。

## 手機入口

校園工作區的學生主導覽有五個入口。其他角色的課務入口名稱與可見操作依授權調整。

| 入口 | 展示重點                                           |
| ---- | -------------------------------------------------- |
| 今天 | 今日課程、近期課業與接續操作的入口。               |
| 課務 | 課表、課程、作業及學習相關功能。                   |
| 生活 | 依所選學校尋找地圖、公車、圖書館、餐飲與住宿服務。 |
| 訊息 | 通知與私人對話；依目前帳號確認可讀取的內容。       |
| 我   | 帳號、個人資料、外觀與相關設定。                   |

**公開入口、nuni 平台工作區與校園私人工作區各自驗證身分。** Google 平台登入不會自動取得校籍或全部校務權限。平台帳號可從 nuni 工作區上方的「問課表」開啟課業助理；不要為了展示五個分頁而假造學校登入狀態。

導覽依據：[App.tsx](App.tsx)、[公開與平台入口](src/screens/PreAuthStack.tsx)、[帳號與學校資格](../../docs/ACCOUNT_AND_SCHOOL_ACCESS.md)。

## 主流程：從課業計畫到已保存的準備行程

### 1. 整理目前課業｜約 1 分鐘

進入課業助理，按「整理今日重點」或「規劃未來七天」。展示目前課表、作業與測驗的期限排序，以及來源尚未取得時的說明。

可搭配這段介紹：

> nuni 先讀取我有權查看的課程和已保存的課表，整理現在要處理的事。每個待辦都有對應來源，我可以直接回到那份作業或測驗。

點一次「查看這份作業」，確認進入的是同一門課、同一份作業，再返回助理。這一步展示精確交接，不需要實際提交作業。

### 2. 保存計畫，之後可以接著做｜約 45 秒

按「儲存這份計畫」，到「已儲存計畫」展開內容，勾選一項「我已處理」，再回到清單確認進度仍在。

按「依目前資料重新規劃」，展示重新核對的來源與「這次調整了什麼」。沒有變動時就展示實際結果，不臨時編造改期或繳交紀錄。接下來的安排操作使用**新產生的即時計畫**；歷史計畫要先重新核對來源。

> 這份計畫和個人進度會留在這台手機。回來時可以接著做，也能重新整理資料；原來的計畫不會被直接覆蓋。

「我已處理」是個人進度，作業是否繳交、測驗是否作答仍看課程服務的紀錄。

### 3. 為指定作業找準備時間｜約 1 分鐘

在即時計畫中，按「安排『作業名稱』的準備時間」。也可以在查到課堂作業後，按「安排準備時間」→「幫我找 30 分鐘空堂」，或接著輸入：

> 幫這份作業找 30 分鐘準備時間。

有多份或同名作業時，先選定確切來源。助理核對目前課表與個人行程，最多列出三個候選時段。選一個後，停在預覽，讓觀眾看清楚作業名稱、參考期限、安排日期、起訖時間與來源核對時間。

候選只來自兩段已知上課時間之間，並避開已存個人行程、保留緩衝。選擇候選還沒有建立行程，也不會保留該時段。沒有候選時，使用者可明確填寫時間後再核對。

### 4. 確認後執行，再讀回結果｜約 1 分鐘

按「確認建立準備行程」。助理重新核對原作業與選定時段，保存到目前帳號、目前學校的手機個人行事曆，再讀回同一筆行程。

看到已核對的回執後，按「查看已建立的行程」，展示行事曆中的實際名稱、日期與時間。

> 我確認之後，nuni 才真正建立行程。它會再讀一次保存結果，確認名稱和時間都相符，才告訴我完成。

若來源已變、時段衝突或結果待核對，展示畫面上的原因與「重新核對行程」。不要把等待或模型回答當成保存成功，也不要另開相同請求重做。

### 5. 返回後核對原操作｜約 45 秒

離開助理再返回，或在同一台裝置重開 App，保持相同帳號與學校。從「找回的行程紀錄」重新核對原行程，再開啟行事曆確認沒有多建立一筆。

這裡恢復的是行程操作紀錄，不會自動恢復完整聊天，也不會因重新開啟就再執行一次。展示時以當場看到的恢復結果為準。

### 6. 接續其他校園服務｜約 30 秒

輸入「開啟圖書館頁面」或「打開校園社群」，展示助理提供的服務入口。開啟後核對學校與帳號；若目前沒有原生入口，依畫面選擇「在網頁開啟」。

服務入口讓學生接著辦事。借書、下單、付款、報名或訊息發送，仍需在目的服務完成各自的操作並取得結果。

## 延伸展示：連續調整空堂條件

在有已存課表的助理對話中，先問「明天下午有一個半小時的空堂嗎？」，再接「改成下午三點半以後」或「那後天有哪些空堂？」。每輪會保留適用的前一個條件、重新讀取目前帳號與學校的課表，並列出這次生效的篩選。

這條是唯讀空堂查詢，不會建立行程，也未排除私人行程與通勤；要建立作業準備行程，使用前面的獨立預覽、核對與確認流程。詳細條件見 [空堂追問](../../docs/evidence/agent-class-gap-followups/README.md)。

## 不依賴課程資料的明確行程

若展示帳號還沒有可連結的課程，可先用這個完整句子：

```text
幫我明天 19:00 到 20:00 安排英文讀書
```

核對預覽後按「確認加入個人行事曆」，讀回成功才開啟該筆行程。這條流程使用明確的日期與鐘點，不會猜測缺少的時長。展示前先確認該時段沒有既有行程。

需要展示多步執行時，可使用 2–4 筆完整安排，例如：

```text
幫我安排以下行程：
明天 19:00 到 20:00 英文讀書
後天 18:00 到 19:00 資料庫複習
```

讓觀眾看完整預覽，再按「確認加入 2 筆行程」。助理逐筆保存並讀回，遇到結果不明會停止後續；核對完成後，需再次明確確認才會接續尚未開始的項目。停止後續不會刪除已建立的行程。

## 展示結果如何說明

| 畫面上的結果               | 可以說明的成果                                                                 |
| -------------------------- | ------------------------------------------------------------------------------ |
| 已儲存計畫、個人勾選       | 同裝置、同帳號與學校的計畫和個人進度已保存；不等於已交作業。                   |
| 行程已保存且讀回相符       | nuni 手機個人行事曆已建立該筆行程；不代表同步 Apple／Google 行事曆或排程推播。 |
| 作業或測驗已有本人紀錄     | 本次成功讀到的 nuni 課程紀錄；校方 LMS 的提交仍回原系統核對。                  |
| 開啟圖書館、餐飲或其他服務 | 已交接到對應入口；業務結果依該服務實際回覆。                                   |
| 合成資料或瀏覽器元件展示   | 展示介面與受控流程；不能當成正式帳號、真實交易或原生實機驗收。                 |
