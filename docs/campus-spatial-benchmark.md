# 校園地圖與課表導航比較基準

資料核對日：2026-11-07。範圍是學生從課表找到正確建築、理解校園位置並前往目的地。這份文件定義可重跑的比較方法，不是已完成的競品排名。

目前沒有在相同裝置、校區、帳號條件下實測 Google Maps、Apple Maps 與 UniTable，因此不宣稱 Campus One 已超越它們。官方文件可以證明產品描述過哪些功能，不能替代靜宜大學特定建築的覆蓋率、定位準確度、步數或速度實測；找不到文件也不代表競品沒有該功能。

## 官方資料能確認的功能

| 產品／任務 | 原始來源已描述 | 尚不能據此確認 |
| --- | --- | --- |
| Google Maps 室內地圖 | 在有提供室內地圖的地點，放大後可看樓層平面圖、切換樓層及選取內部地點；部分地點另有 360 度相片。[G1] | 靜宜各棟建築是否有樓層圖、教室編號、可走的室內路線，必須逐棟實查。 |

| Apple Maps 步行 | 官方指南描述詳細步行指引、海拔預覽，以及避開山坡、階梯或繁忙道路的選項；部分功能受地區限制。[A2] | 特定校園路線是否正確、是否涵蓋通行時段與電梯狀態，仍需現地確認。避階梯不能直接等同全程輪椅可通行。 |

Campus One 的空間圖目前表示公開地點座標的相對位置，不包含已驗證的建築外觀、室內樓層、走廊、可通行道路或即時人流。比較時應把「立體總覽」與「室內導航」分開記錄。

## 五個可重現的學生任務

### 1. 從下一堂課找到正確建築

使用同一份人工核對過的課表清單，至少包含建築全名、校內簡稱、同名建築、跨校區同名、只有教室編碼，以及未知教室。每筆先列出學校、校區、課表原文、可確認到的最細層級與核對來源。沒有室內資料時，成功終點只能寫「建築」，不能算已找到教室門口。

分別記錄初次設定成本與日常使用成本。UniTable 等產品若需要先標記教室，應按官方正常流程設定並單列耗時；日常輪次使用完成設定後的狀態。所有產品從同一任務起點計時，例如顯示下一堂課的畫面；需要跨 App 的步驟也計入。

記錄成功／失敗、錯誤建築、無法確認、人工介入次數、操作次數與完成秒數。遇到多義或未知資料時，正確顯示不確定性可以算正確處理；自動導向未經支持的建築必須記為錯誤，不能因為畫面完成而算成功。

**本專案可由測試證明：**解析及校別邊界的單元回歸，與真實 Chromium 中 `MapClient` 接收 `schoolId=pu&query=主顧303` 後選主顧樓、導航 href 的座標、3D／2D 選取銜接；兩個同名測試候選必須等使用者選取；`PH303` 顯示未知並提供校方核對連結。[I1]

**仍需補的證據：**正式登入狀態下從 Today 到 Next.js 地圖頁的完整流程、真實課表涵蓋率，以及競品相同輸入的逐筆結果。元件 fixture 不等於完整路由或正式環境測試。

### 2. 判斷現在出發能否準時到課

固定至少三組經現地核對的起終點、步行方式、上課時間與出發時間。各組實際走三次，記錄可通行路線與耗時，再比較顯示的路線、估計到達時間與實際結果。同時測試定位被拒、定位逾時及無路線資料。

分開記錄直線距離、依速度換算的粗估時間與路線引擎估計時間。對同一種估計才計算中位數絕對誤差與範圍；不可拿直線距離的換算值直接當作完整導航 ETA。若未取得使用者位置，不得把校門或任意預設點標成「我的位置」。

**本專案可由測試證明：**外部導航連結指定正確目的地與步行模式，沒有捏造使用者起點。瀏覽器驗收不會開啟外部導航，因此不能證明外部服務回傳的路線或時間準確。[I1]

**競品基準：**UniTable 已描述課程上的距離／時間，Apple 已描述步行路線能力；各自的實際誤差和 Campus One 的體驗差距尚未量測。[U1][A2]

### 3. 從入口找到樓層、教室或設施

對同一棟建築使用可取得的校方樓層圖與現場標示，指定入口、樓層、教室或洗手間。記錄每個產品能確認到建築、入口、樓層、房間的哪一層；沒有資料的建築也要納入。若測試路徑涉及樓梯、電梯或門禁，另記開放條件及資料日期。

**本專案目前邊界：**只能驗證已有地點的選取、文字、座標、來源及不確定提示。3D 圖釘或到建築的外部導航連結，都不能作為室內路線成功證據。

**競品基準：**Google 與 Apple 官方都描述室內樓層功能，實測前要逐棟查核是否可用；不能預先把它們記為不支援。[G1][A1]

### 4. 使用輔助工具完成查找與操作

把介面可操作性與實體路線可通行性分成兩張記錄。前者在相同裝置測試鍵盤、VoiceOver、放大文字、減少動態、直向捲動及橫向手勢；後者需要獨立確認坡度、階梯、門檻、電梯與開放時間。UI 通過無障礙檢查不等於實體路線適合輪椅。

**本專案可由 CI 驗證的範圍：**320／390px 版面、44px 目標、200% 根字級、深色、原生對話框焦點、場景鍵盤控制、觸控模擬、減少動態，以及 GPU 故障後仍可取得地點資訊。這些必須附成功 run、commit SHA、結果 JSON 和截圖；它們不涵蓋實機 VoiceOver、Safari、手機 GPU 或耗電。[I1]

**競品基準：**Google 官方已描述 VoiceOver 和語音步行指引；Apple 的避階梯選項也應納入實查。不能用本專案的自動化通過紀錄推定競品較差。[G2][A2]

### 5. 無網路時仍能辨識目的地

分兩種條件：首次使用且完全沒有快取，以及事先按產品正常流程下載／快取後斷網。給各產品相同準備機會，記錄資料日期、下載範圍與大小，再分別驗證地點名稱、地圖、目前位置、步行路線和 ETA 是否可用。限制與過期資料必須清楚標示。

**本專案目前未證明：**本機 fixture 使用可連線的本機伺服器及替代底圖；拒絕對外請求不等於正式 App 可離線。WebGL context-loss 備援也不是斷網驗收。正式離線模式需另建網路中斷、快取與更新測試。[I1]

**競品基準：**Google 與 Apple 的官方離線步行能力描述不同，應依實際產品、版本與地區記錄，並測試校園覆蓋。UniTable 未量測，保持未知。[G3][A3]

## 結果如何記錄與解讀

每次量測至少保存下列欄位，使用經授權的測試帳號與不含個資的課表資料。

| 欄位 | 記錄要求 |
| --- | --- |
| 環境 | 日期、裝置、OS、瀏覽器／App 版本、語言、網路、定位授權、螢幕閱讀器與文字大小。 |
| 任務 | 學校／校區、課表原文、人工確認的目的地、來源日期，以及原本就未知的部分。 |
| 前置狀態 | 首次設定或日常使用、已有標記、已下載內容、登入狀態；不得省略競品正常支援的設定。 |
| 結果 | 成功、失敗或資料不足；錯誤目的地、手動介入、步數、秒數；估計時間與實際時間分欄。 |
| 證據 | 操作錄影／截圖、資料來源；本專案另附 commit SHA、CI run 與 artifact。 |
| 證據等級 | 官方文件已描述／實測通過／實測失敗或受限／未實測或資料不足。四者不可混用。 |

正式比較應交錯產品順序，以免後測者受益於記住路線。報告重複次數、中位數與範圍，保留失敗樣本；小樣本結果只適用於已測任務，不外推成整體產品排名。若要說某項體驗更快，必須同時列出同條件步數或耗時與錯誤率；若正確率較差，不能只用速度支持較好的結論。

開發優先順序是先確保「下一堂課 → 正確校區 → 可確認的建築 → 地點資訊 → 步行導航」完整且沒有錯誤導向，再以空間總覽協助認識校園。攝影級建築效果不能補足缺少的入口、教室或道路資料。
