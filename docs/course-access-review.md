# 課班比對、加入申請與教師人工核對

狀態：功能分支候選，尚未正式部署。不得將測試資料、平台管理員審核或個人課表辨識說成校方認證。

## 接續範圍

以 `e8bc6426b1f9cdc66ee4f970bb9b5a3d8b941f26` 為基準，沿用 PR #37 已合併的個人匯入、確認、重複檢查、編輯、撤銷及空堂計算。沒有重新建立匯入儲存層。

現行匯入連結的是 Nuni platform class workspace，不是 Firebase group。實際 Nuni 原始碼保存在已封存的私有 `Miiduoa/nuni-prod`；本倉庫以 `deploy/nuni-api/source.json` 固定來源與既有補丁。因此新增服務以本倉庫的 **選擇性候選擴充** 接進相同 API、帳號 session、PostgreSQL transaction 與 workspace 資料表，不另設登入系統或第二份課班資料庫。預設建置及已部署來源宣告保持不變。

## 使用流程

Web 與 App 的每筆課表編輯區新增「查找課班與申請加入」。先完成學校代號、學年度、學期，再查找候選。只傳送學校／學年／學期／課號／課名／教師／班別，不傳原始截圖、完整辨識文字、姓名或成績。

ROC 與西元年度、全形字、空白及學期常見寫法會正規化；不猜學校別名、不模糊比對課號或教師姓名。學校、學年、學期是硬性界線。課號或課名相同才能成為候選，教師與班別用於排序及顯示衝突。單一候選也不自動選取；多候選、缺漏、差異都須人工核對。候選超過上限時不得送出申請，須補齊條件重查。

學生選擇並確認後只建立 `pending` 申請，不新增成員。管理員獨立核對本人的修課授權後核准，交易內只寫入 `student` 成員資格。核准後重新載入匯入頁的課班清單，再沿用原本的手動連結與成員檢查；此版不自動改寫已儲存的個人課表連結，也不代表完成校方選課。

申請可查詢、分頁及撤回。重複操作使用綁定帳號與完整請求內容的重試鍵；不同內容不得重用同鍵。核准、拒絕、撤銷均有版本檢查及交易內稽核。重新登入、切換帳號／學校／課程欄位後，畫面會丟棄原候選與舊請求回應。

## 教師核對不是自行取得教師身分

`owner-teacher` 是既有個人工作區的管理角色，本身不是學校教師資格；匯入區顯示為「管理者（未代表教師認證）」。本次不建立全域 `teacher` 或任何校務職員角色。

授課者可在 Web／App 選擇自己管理的有效工作區提出申請。核准須同時滿足：

1. 既有 `class_workspace_affiliations` 已經由平台管理員審核通過，綁定相同學校及非空正式 `section_id`。本功能不取代或自動核准原本的學校掛靠流程。
2. 與申請人不同、具有有效 `platform-operator` 指派的管理員，透過獨立管道核對申請帳號、本人的身分及本學期授課授權，確認課號／課名／教師／班別與正式班次相符，填寫審核說明及可追溯的內部證據案件編號。
3. 工作區仍有效且仍由申請人管理；初次發布前只能有該名管理者，不能把既有未審核學生／共同管理者一併變成正式課班成員。有舊成員時須先逐案處理，系統不自動遷移。

審核介面放在 Web 匯入頁，僅向平台營運帳號顯示；伺服器仍重新檢查權限，前端標記不構成授權。App 提供申請與狀態查詢，不提供管理員審核操作。

管理員核對後的目錄標記是 `administrator-reviewed`，不是 `school-verified`。可接受的正式依據須由學校提供或授權核實，例如透過校方既有聯絡管道確認的授課名冊、能識別本人及職務的正式 IdP 聲明。單純擁有信箱、教師名錄同名或課表截圖都不夠。文件本體不得貼到公開課班或公開 GitHub，API 僅保留內部案件參照。

學校尚未提供可用正式來源時，申請維持待審或拒絕；不能以測試 OAuth、假名冊或假證明完成正式認證。共同授課者的獨立核對、校方 SSO／課務 API 串接及自動同步授課名冊不在這次實作範圍。

## 權限與資料界線

既有平台 session 決定操作者，請求 JSON 不得指定帳號、角色、學籍或認證結果。管理員身分只查既有伺服器資料表，不新增自行授權入口。推薦目錄只回傳經核對的課程欄位；不回傳其他學生、名冊、證據或帳號。目錄允許登入帳號依學校搜尋；這不是跨校讀取私人課班內容的權限。

自己的申請只能由自己讀取／撤回。管理員佇列按指定學校分頁，管理員是既有平台全域營運角色，不偽裝成校方管理員。審核者可見申請帳號識別碼及說明，用於獨立核對；證據參照只儲存於後端，不流入目錄。

資料庫觸發器封住舊邀請碼、舊成員角色更新等旁路：已核對課班新增有效學生必須有當前核准申請；不得用舊路徑升為共同教師。退出或移除成員會撤銷舊核准，舊邀請碼不能重新啟用。教師授權撤銷、學校掛靠變更、學校關閉或教師帳號關閉會撤銷目錄並封存課班。撤銷後不能用舊 API 將課班重新啟用。尚未發布的私人工作區保留原有邀請行為。

Web BFF 沿用同源／session context 驗證，嚴格列出可用路徑，拒絕任意代理及查詢字串；後端使用相同 platform session、8192-byte 上限及速率限制。SQL 全部參數化；申請與核准使用交易、列鎖、版本及重試鍵，狀態衝突應重新讀取而非假裝成功。

另對舊 Firebase 路徑做防護：`createGroup` 不再相信客戶端 `verification`；Firestore client 不得更改群組認證或成員角色，群組存取須仍有該校成員資格。這不是把 Firebase 群組接到 Nuni 教師核對服務；兩者未被當成同一套權限。Firebase Admin SDK 寫入仍須靠函式自身檢查。

## 測試與驗收層次

`node scripts/test-course-access.mjs` 先嚴格編譯共享契約、客戶端及實際 SQL service，再執行政策與 API 回應驗證測試。有 `COURSE_TEST_DATABASE_URL` 時才執行 PostgreSQL 測試；沒有資料庫時會清楚列為 skipped，不能算通過。

`.github/workflows/course-access-review.yml` 使用隔離的 PostgreSQL 16 service、合成帳號與最小既有資料表契約，執行真實 SQL、交易、觸發器、重試、撤銷及隔離測試。這些測試 **不是** 完整私有 Nuni migrations、Fastify 整合測試或正式身分認證。測試工具裝在 runner 暫存目錄，沒有修改應用相依套件或使用正式資料庫／憑證。

候選安裝器的 Python 測試驗證來源錨點、單次插入及失敗封閉；既有 `nuni-course-source`、`nuni-course-api-boundary` 測試檢查原本固定來源與 API 界線。Web／App 的完整 typecheck、瀏覽器／手機互動、Firestore emulator 與完整後端測試，應分別查看各 CI 結果，不可用共享契約編譯代替。

## 尚未正式部署：必要發布門檻

選擇性候選建置：`python3 deploy/nuni-api/build.py --course-access-candidate`。此命令在隔離的固定來源 checkout 套用既有審核補丁，再拷貝本功能來源，檢查整合錨點；僅建立候選映像，不部署、不執行 migration、不啟用功能。原 `source.json` 不會被修改成已上線狀態。

正式開放前，維運須先在有權讀取私有來源的環境完成下列驗收，而非直接切換環境變數：

- 對完整固定 Nuni 來源編譯、執行既有全部 migrations 及新增 migration 277，驗證 Fastify session／限流／BFF／原生 App 的端到端流程。
- 依原本規則重新產生並審核 runtime permission inventory、資料庫角色 grants 與 migration manifest，驗證 enforce 模式；本次沒有猜測或放寬正式資料庫權限。確認 SQL 觸發器不破壞既有退出、移除、邀請及校方掛靠流程。
- 通過完整 Web、App、Firebase 函式／Firestore emulator 測試與手機實機操作；比對 main 最新來源並更新候選固定 tree／checksum。
- 安排備份、migration 277、具備新表權限的候選映像、撤銷／封存演練。回退時也必須保留相容的 migration manifest 與觸發器；不能直接使用不認得 migration 277 的舊映像。
- 建立正式管理員指派及學校獨立核對作業、證據保管與保存期限，確認第一批課班的授課／修課授權。沒有正式依據就不核准。

僅通過以上門檻後才評估 `CAMPUS_COURSE_ACCESS_ENABLED=true`。預設不啟用；舊後端回 404 時 Web／App 明確顯示尚未開放，不影響個人匯入，也不建立任何假成功的成員或教師紀錄。
