# 站內座位預約的確認內容與回執一致性

本批從 main `5f9646ded786bc22e7c46c14d0db15cc9bd58880` 開始，不依賴已關閉的 #631，也不帶入 #683／#684 的整合基底。

## 實際問題

舊 resolver 只取第一個時間，再固定加兩小時。因此明示 `14:00 到 16:30` 會變成 `14:00–16:00`，半小時需求也會變成兩小時。未指定座位時，「任一席」會被替換為固定的 `lib-3F-A01`。舊回執驗證僅比較座位與日期，錯誤的起訖時間仍可能被認為成功。

確認前的草稿必須保留使用者明確提供的資料。無法可靠辨識時先請使用者補充，不能把不確定內容轉成另一個可執行選項。

## 行為邊界

- 僅接受能完整辨識的單一日期、唯一確切座位及同日起訖時間／明確時長。不默選座位，不預設兩小時；跨午夜、歧義、否定或不支援的表示方式先澄清。
- 座位編號不允許截短成另一個編號，編號中的數字也不能變成日期來源。座位專用解析不變更洗衣、報修或其他工具的解析政策。
- 這是 Firebase 校園即時模式的站內預約草稿。解析到座位 ID 不代表讀取過可用性；確認執行時仍由既有交易核對同校座位、衝突、配額及權限。
- 來源是既有 `schools/{schoolId}/librarySeats` 與 `seatReservations`，沒有新增館方 API、Platform／Firebase 身份橋接，不能宣稱完成館方訂位。
- 成功回執必須有 reservation ID，且座位、日期、有效起訖時間與已確認 input 完全相同。回執不符保留原有 `unverified` 與 claim 防重機制，不宣稱成功、不自動重送。
