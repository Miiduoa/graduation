# nuni：首頁、探索、助理與服務的接續整合

日期：2026-11-25（台灣時間）

## 這一輪解決的問題

新版首頁與探索提供了更多開始任務的方式，但分開的入口若各自建立對話，使用者換頁後仍要重述需求；手機助理若只說「從下方開啟」，卻沒有對應控制，流程也會中斷。這輪把既有工作區、課務追蹤與重新設計的導覽整合起來，讓同一件事可以持續做下去。

本輪沿用原來的服務、身分核對與操作確認機制。工作情境是提問與服務的情境，不能當作教師、店家或管理權限。

## 使用者會看到的改變

| 操作 | 接續行為 |
| --- | --- |
| 從「今天」開始提問 | 使用同一個工作區；範例和新入口只帶入問題，仍由本人送出 |
| 到「探索」選擇另一項任務 | 在本分頁的同一段對話帶入新問題；已有草稿時先選擇保留或取代 |
| 有待確認、執行中或待核對的操作 | 原引擎的鎖定規則繼續有效，不讓新問題或角色切換覆蓋原操作 |
| 從探索開啟實際服務 | 保留校園、篩選與來源卡片；返回時恢復原本的探索位置與焦點 |
| 直接開啟助理網址或使用新分頁 | 保留 `q`、`taskProfile` 與校園資訊；同分頁使用現有工作區，新分頁獨立建立。明確課程／群組深連結保留原本的資料範圍 |
| 遠端已存檔，但本機或追蹤尚未完成 | 顯示尚待核對，不把安排列為全部完成；保留既有唯讀恢復方式 |
| 手機助理回覆服務選項 | 顯示實際可點選的服務，網頁服務帶入所選校園 |
| 手機從助理前往原生服務 | 可由「接著問 nuni」回到原本仍掛載的助理；不新增草稿識別碼、不自動重送 |

帳號、session 或校園真正改變時，不接續上一個範圍的私人內容。原生來源畫面已卸載或作用範圍失效時，返回入口撤除。

## 整合時保留的既有行為

- 課務追蹤仍依序核對精確 receipt、本機行程、原簽章來源及追蹤保存結果；追蹤成功後才清除恢復 journal。
- Today 接收同帳號、同校園的更新後重新讀驗資料，不能以通知本身取代來源驗證。
- 匯入編輯仍先驗證再判斷是否真的改動；未修改時不重寫批次與匯入時間，取消等待與過期修改保護仍在。
- 公開課程的時效提示仍依原擷取時間計算，不為更新提示重新擷取或改寫時間。
- 地圖保留精確校園範圍、公開校園 catalog、primary → catalog → alias 比對順序，以及 Apple 步行導航與暫時失敗後的深連結恢復。
- 樓層範圍 `3F-4F`、`B1F B2F` 等不會誤當成教室；一般館名與官方代碼兩個路徑都套用相同防護。
- 手機顯示被截短的長作業標題時，仍以完整來源比對原始作業；有歧義的預覽不能選錯作業或更改另一份作業的提醒。

本輪修改的 Web TSX 範圍 lint 為 0 errors、1 warning：直接入口只有在外部工作區確實接受問題後才標記 consumed，因此保留該 effect 更新狀態的提示，沒有停用規則。Native 範圍的 5 個新 lint 提示已修正，修正的兩個檔案再以 `--max-warnings=0` 通過；原有 `CampusAssistantScreen` 的 2 個 hook 提示仍在。課務匯入測試也有既有 React `act` 提示，因此本輪不宣稱「零警告」。

此輪瀏覽器 fixture 增加真正的 Explore、DirectoryVisitProvider 與 ServiceBreadcrumbs，供同一工作區與服務返回流程驗收。登入、校園、傳輸回覆與目的地服務內容仍是合成資料；fixture 的來源雜湊不等同真實登入、正式後端寫入或部署證據。

### 實際 Next 正式建置的瀏覽器驗收

以下操作在本輪正式建置的本機預覽，以未登入、選取靜宜大學的狀態完成；不是合成登入 fixture 的結果。

| 操作 | 觀察結果 |
| --- | --- |
| 首頁輸入「圖書館」，開啟任務，再前往探索 | 原草稿留在同一個工作區 |
| 探索搜尋「地圖」，選「試著問 nuni」 | 出現原草稿與新問題的選擇；選「保留目前任務」後，草稿仍為「圖書館」且工作區數量為 1 |
| 再次選範例並取代草稿 | 帶入「開啟校園地圖」，顯示可用的地圖服務入口；不自動送出問題 |
| 以學生情境、探索校園分類開啟地圖，再按「返回探索」 | 保留搜尋「地圖」、工作情境與分類；焦點回到原來的地圖服務卡片 |
| 從側欄重新開啟助理工作區 | 仍為「開啟校園地圖」，只有 1 個工作區 |
| 將實際探索卡片的助理連結開在新分頁 | 初始化期間先顯示「保留的問題」；準備完成後預填相同問題，只有 1 個工作區；回到首頁後草稿仍保留 |
| 桌面與窄版排版 | 桌面文件 clientWidth／scrollWidth 均為 1357 CSS px；400% 瀏覽器縮放下的約 340 CSS px 視窗，首頁與開啟的助理文件寬度均為 334／334，未出現水平溢出；五個底部導覽入口可見 |

窄版檢查使用桌面瀏覽器縮放，不能據此宣稱手機實機或軟鍵盤已驗收。地圖在這個環境顯示「校方地點資料暫時讀不到」並呈現 34 個可用地點；本輪確認的是可見的來源降級與返回接續，沒有宣稱正式地圖來源已恢復。瀏覽器擷取的尾端 console 訊息包含擴充功能傳遞 metadata 失敗，未將其寫成產品的零錯誤證明。

本輪只重新建置合成瀏覽器 fixture 與核對來源雜湊，沒有在本輪重新執行其既有的 8 個自動瀏覽器情境；舊版本的 CI 結果不列入以上實際驗收結果。

重建後的 370 個來源檔案雜湊與凍結的產品程式完全相符，0 個不符。可稽核紀錄：[驗證摘要](./evidence/workspace-continuity-20261125/validation.json)與[fixture 來源雜湊](./evidence/workspace-continuity-20261125/source-sha256.json)。

## 發布條件與限制

本輪不變更 main 的審查規則。合併仍需要精確候選版本的檢查與指定 GitHub App 的「審查通過」。本機測試、舊提交的 CI 成功、PR 可合併狀態，都不取代這項條件。

原生元件與導覽測試不等於 iPhone／Android 實機驗收；合成瀏覽器情境不等於真實校務／Google 登入或正式服務可用性。PR 的最新 head、遠端檢查及發布狀態以 PR 即時資料為準。
