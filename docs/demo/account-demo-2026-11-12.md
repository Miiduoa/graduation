## 介面與操作

- `/demo/account`：登入本人帳號後讀取展示資料，管理 12 個展示功能及保存情境進度。
- 設定頁：只有取得本人有效展示配置時，才顯示展示工作區入口。
- `/student-card?campus=pu`：Google 平台帳號可查看本人展示卡、暫時出示 DEMO 學號及 60 秒展示 QR。
- 課程資料使用原本 `/classroom` 的讀寫與成員權限。
- 課表、行程、成績使用原本的 personal-imports 同步引擎。首次使用裝置需在展示頁按「同步我的課表與行程」，既有資料有衝突時先核對，不自動覆寫。

工作區的訂餐、請假、報修、社群與訊息動作只更新本人合成展示紀錄，不產生正式交易或對外通知。正式校籍 QR、校方服務與真正的 AI 代辦權限仍使用其原有授權；本次沒有變更 Firebase 規則或開啟萬用開發帳號。

## 帳號與資料保護

`/api/nuni/account-demo` 每次重新核對上游 session principal，只讀寫該 account ID。Web 使用 cookie/context，App 使用 Platform bearer。關閉、過期或停權的配置不可執行。更新使用 revision CAS，核對資料庫回傳與再次讀取的相同結果才回報成功；遇到競態或不明結果需重新讀取。

`nuni_account_demos` 開啟 RLS。既有 Web runtime 只能讀取可用展示列、更新 permissions/state/revision/updated_at；不能建立或刪除配置，也不能更改帳號、profile、啟用狀態或到期日。用來序列化帳號停權的 row lock 只追加 `platform_accounts.updated_at` 的欄位權限。帳號真正刪除時，展示配置以外鍵 cascade 清除。

學生證會在切換帳號、session、學校、離頁或到期後清除出示內容。展示 QR 使用獨立前綴，不會成為校方驗證 token，也不會呼叫 NFC 門禁。

- 將 `/demo/account`、`/student-card`、`/ai-assistant` 納入精確的平台登入返回路徑。Google 登入完成後保留原路徑、校園參數與錨點，不再被當成僅能連線學校帳號的頁面。

### 帳號專屬店家與取餐單

工作區新增學生與店家兩個視角，使用同一份已儲存的展示訂單。固定餐點為「小日子食堂（示範店家）」的香煎雞腿飯一份、展示金額 95 元、12:10 於學生餐廳取餐櫃檯取餐。

1. 在學生端核對菜單、份數、金額與取餐時間，按「建立訂餐」並確認。
2. 切換「店家接單」，查看本人訂單與備餐狀態。
3. 店家按「標示可取餐」並確認，學生取餐單會顯示更新後結果。
4. 重新整理或重新登入後，從帳號 API 讀回同一份進度。

`/merchant`、`/merchant/workspace` 及 `/food` 現在會為有有效展示配置的帳號顯示相應入口，連結採用展示配置中的校園。`#merchant-demo` 直接開店家視角，`#account-dining` 開學生視角。功能已關閉時，入口會提示需要開啟的權限；店家備餐仍要求 `food` 與 `administration` 同時開啟。

### 在既有助理對話內完成展示操作

首頁助理與 `/ai-assistant` 共用同一個對話元件，可直接輸入：

| 指令 | 可展示的結果 |
| --- | --- |
| 查看展示進度 | 讀取本人最新完成項目、訂餐、請假與圖書館狀態 |
| 展示點餐 | 核對固定餐點後建立本人展示訂單 |
| 展示標示可取餐 | 更新本人展示訂單的取餐狀態 |
| 展示預約座位／展示續借圖書 | 保存本人圖書館展示紀錄 |
| 展示送出請假／展示核准請假 | 展示申請與處理兩端的前置順序 |
| 展示簽到／展示宿舍報修 | 保存本人簽到或報修展示紀錄 |
| 展示繳交作業／展示發布成績 | 展示繳交與教師處理的前置順序 |
| 展示發布限時動態／展示傳送訊息／展示發布公告 | 保存本人合成社群、訊息與公告紀錄 |

展示指令由明確意圖辨識處理，不需呼叫雲端模型。操作先產生確認卡，確認前重新讀取完整快照，以 revision CAS 寫入，再核對完整回執與第二次讀回。換帳號、切換校園、過期、權限關閉或版本改變時停止；結果不明不自動重送，也不宣稱完成。取消確認卡不送出寫入。

只有明確包含「展示／示範／演示／demo」的指令使用這份合成資料。一般請求仍使用原本的助理能力與授權。展示對話不加入後續雲端模型的 history，模型回覆也不能自行產生這類展示確認卡。
