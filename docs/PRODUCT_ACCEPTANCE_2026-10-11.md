- Node 22 全套：Web 930 通過、1 個既有測試略過；Mobile 2,075 通過、1 個既有佔位測試略過；Functions 749 通過。Web 覆蓋率為 statements 70.81%、branches 68.01%；測試數與覆蓋率不代表正式服務驗收率。
- 完整 Firestore／Storage 規則與交易測試 114/114 通過，涵蓋 CI 指定的 6 個檔案。使用隔離的 demo project、連接埠與模擬器，已停止自有程序。
- iOS／Android 最新 Expo development export 均成功，各 2,101 modules、95 個資源，約 11.9 MB；屬 JavaScript／Hermes 打包，尚非原生簽章或真機驗收。
- 全工作區 typecheck、lint 通過；仍有既有 lint warnings，沒有宣稱零警告。Web production build 與 16 項 standalone server lifecycle 測試通過；實際 standalone `/health/live`、`/search` 都回傳 200。
- 修正快速恢復登入狀態在延後載入頁面造成的 SSR hydration mismatch：三個回歸測試在舊實作重現、新實作通過；正式建置的 28 個公開入口皆 200、手機寬度無橫向溢位、無 pageerror。為避免重複整頁載入觸發上游目錄限流，這組頁面巡檢使用瀏覽器端校園目錄 fixture；不構成正式帳號或校務 API 驗收。
- 瀏覽器課程流程使用本機測試回應驗證首頁測驗連結、正確分頁與焦點、送出後回執；fixture 未寫入正式系統。這是畫面與 API 合約的互動驗證，真實跨端提交仍待驗收。
- 修正淺色介面的輔助文字對比，避免首頁及提交回執低於 4.5:1。28 個公開入口在淺色／深色共 56 次 axe WCAG 2 A/AA、2.1 A/AA 自動檢查沒有違規；部分色彩對比仍被工具列為需人工判定，未宣稱通過完整讀屏或無障礙認證。

## 續作：真實 API 與重新繳交

接續整合 PR #29 的公開校園入口與學校登入開放條件，保留本分支的待辦、回執及登入初始化修正。Web 與 App 的測驗回答都遵守 2,000 字上限；開放中的測驗可更新原回答。編輯時帶入已儲存內容，若重新讀取後發現內容已變更，保留草稿並要求使用者選擇；不宣稱後端已具備跨端原子版本鎖。

作業與測驗重新繳交後，既有 Nuni API 會保留舊教師回饋。因此兩端明示早於最近一次提交的回饋，老師編輯中的回饋也會比對已讀取到的學生稿件變更。這是文字回饋流程，並未新增數字成績或取代學校成績紀錄。

`scripts/verify-nuni-course-api.mjs` 在隔離 PostgreSQL、固定 API 來源樹與真實 loopback HTTP 上驗證三個帳號身分。涵蓋課程建立、邀請加入、教師發布、同 key 並行提交只留一筆、回饋、更新與舊 key 重試、關閉後拒寫、登出後拒讀。使用本機 RS256 測試金鑰驗證 nonce／簽章／session handler，沒有使用 demo auth，也沒有連線正式資料庫；這不等於真人 Google 授權、Web/App 真機操作或正式校務驗收。

Firebase CI 現在保護進行中的 main 部署不被後續 push 中斷，並在失敗時保存綁定提交及 run 的部署結果與前置檢查。PR 驗證仍可取消舊執行。

## 發布阻塞與整合順序

2026-10-11 檢查的 main CI [run 38117411096](https://github.com/Miiduoa/graduation/actions/runs/38117411096) 在 Deploy Firebase Functions 因 production environment 缺少 `FIREBASE_TOKEN` 失敗。該次建置與檢查成功不能當作 Functions 部署成功；必須補正環境授權後，以新的部署記錄與服務驗證確認。本輪修正 CI 彙整不能代替部署憑證。

同日以本機已登入身分執行唯讀 preflight：可存取 `campus-one-tw`，但計費未開通，多個 Functions 依賴 API 未啟用，Authentication 與指定 Storage bucket 查詢回 404。因此補 CI token 仍不足以發布這條 Firebase 路徑。現行平台課程、帳號與店家使用既有 Nuni API；不能把 Firebase 阻塞當成更新 Nuni 網頁的必要前置條件。本輪沒有開通付費方案或更換平台後端。

先保留 main 的安全修正，再整合 #29 的平台帳號與學校資格，逐項移植仍適用的修復。#20 的 Node/Expo 修補與 #23 的部分原生修補已有重疊；#24 只取仍欠缺的正式 AI 設定限制。#25 的 `attendanceRecorded` 回傳假設、#26 的公開 `liveData.qrToken`、#27 的另一套 token/QR 格式與主線不相容，不能整支盲合或視為上架缺口已解決。

## 競品基準與本輪定位

2026-10-11 核對官方文件：

- [Canvas App](https://community.instructure.com/en/kb/articles/662784-what-is-the-canvas-app) 已提供手機繳交作業、課程行事曆、待辦、成績、教材、通知與訊息；[iOS 待辦說明](https://community.instructure.com/en/kb/articles/661646-how-do-i-view-the-to-do-list-in-the-canvas-app-on-my-ios-device) 有專門的行動待辦流程。因此 tasks、calendar、mobile submit 是競品既有基準，不能當成 Campus One 獨有突破。
- [Moodle Timeline](https://docs.moodle.org/501/en/Timeline_block) 已按時間或課程整理活動與期限；[Moodle App](https://moodle.com/us/products/moodle-app/) 的官方產品介紹也列出行動課程、離線存取與通知。功能表只能證明官方列出的能力，不能代替雙方實際使用比較。

本輪先修使用者可遇到的錯誤返回、任務遺漏、假成功及重試可靠性。公車只呈現可核實來源、宿舍不冒稱收件、簽到成功可安全重查，是本輪已補的可靠性細節；它們不構成「已全面超越競品」的證據。仍需用同一組真實學生、教師、管理員與店家任務，量測完成率、步驟、資料正確率及失敗後恢復，而非比較畫面數量。
