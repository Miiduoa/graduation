## 可重現問題與既有能力

基線 main 0d139f57d3b9c9d388de1a29c685c41515e31ede 已有簽章確認卡、撤銷、逐步行程前置核對，以及未知結果 journal/reconcile。一般追問可讓模型提出新卡，但後續 history 只含問答文字與執行結果。若回答僅說「已整理確認卡」，未執行卡片的精確標題、日期及時段沒有帶入後續請求；空回覆或提議產生前失敗也不一定使原提議失效。

重現：先取得兩筆行程，回答不重述卡片值，接著要求「第二筆改到 21:00，第一筆不變」。缺少明確的原安排快照與先撤銷、再預覽流程。

## 本切片

僅未嘗試執行的純行程提議出現「修改時間或條件」。展開後顯示原安排，輸入修改條件；沿用既有取消 API，以原 token/args 逐筆撤銷。每筆均回查為 revoked 才送出新的預覽要求。新要求只包含使用者看得到的允許欄位快照與修改條件，不包含其他歷史、token、mutation ID 或額外 metadata。

新預覽必須為同校園的純行程、全新且互異的操作 ID，才加入對話；仍需使用者另行確認。沒有改動後端簽章、權限或批次確認規則。此次不涵蓋已執行行程的修改，也不改寫一般聊天追問、草稿/IME/閱讀位置或手機流程。

失敗保留輸入。結果不明時只核對原操作；即使核對發現已成功寫入，也不重新建立同一行程。部分撤銷後只接續剩餘未撤銷卡。撤回模型同意、離開帳號/校園對話後，不再發送或顯示該次新預覽。

修改條件最多 300 UTF-16 code units；完整問題遵循既有 1000 上限。過長原安排會在撤銷前提示，不能靜默截斷。此限制仍是後續改善點。
