# 匯入結果的來源逐列核對

## 為什麼不能只看 complete:true

模型可能正常停止、輸出完整 JSON，卻漏掉一筆，或重複另一筆來湊出相同筆數。
這輪在既有 schema／引用驗證之後，以原始文字的 CSV／TSV 資料列核對結果。
來源掃描沿用 `aiDelimitedText` 的引號規則，不重新拼寫來源，不把模型提供的筆數當答案。

`aiTableAudit` 只接受可唯一判斷欄位的單一矩形表格：需要名稱欄及至少一個對應類型的資料欄。
後續手機分段可使用原有欄名參考，但參考不算來源證據。每筆引用必須落在單一資料列，包含該列名稱。
最大配對保留重複來源列的數量；重複課名不等於重複紀錄，也不能用重複回答抵銷漏列。
可明確解讀的學分、成績、星期、鐘點、日期與起訖節次會核對所屬欄位，而非只找整列有沒有該數字。
特殊節次沿用使用者選定學校的 profile。學校、學期、權限與連結課程都不從此核對程序推得。

缺值或 uncertainFields 保持留空和既有修正問題。來源列有對應草稿，不代表欄位已填完整或正確。
同一課表列可產生多個上課時段；本次不保證同一儲存格內的全部時段都已展開。

## 手機

模型正常停止但核對失敗時，只在已有可靠資料列邊界的範圍縮小重試，已成功段落不重跑。
與輸出截斷共用原本整次最多八次拆分、最多三十二次原生呼叫的上限，不另開第二套預算。
單筆仍有問題、無法安全切分或預算耗盡時整次失敗，不交付部分草稿；取消、逾時與換模型的檢查保留。
原有進度卡顯示「逐列核對發現漏列或欄位錯配」，全部完成後透過既有問題區顯示已比對的表格文字筆數。

## 網頁

貼上／檔案文字整理也使用相同核對；不符時拒絕交付草稿，提供來源文字行號及表格匯入退路。
網頁目前不在核對失敗後自動重載視覺模型，避免反覆配置 GPU。原有 worker 清理與鎖釋放仍執行。
圖片推論不做這項文字來源驗證：模型自己抄出的文字不能當獨立證據，圖片旁附帶的 OCR 文字也不算。

## 顯示與來源位置

通過可核對範圍後產生 `ai-table-coverage` 提示，表示來源列對應，不是信心分數或準確率。
有未能辨認結構的其他段落時明示只核對其中一部分。相同原文列的來源行號分別指回各自位置。
所有提示不包含姓名、課程名稱、成績或模型原始錯誤內容。

## 未涵蓋

無表頭、重複欄名、不規則表格、混有總計或多工作表標籤的單一文字塊回報 unavailable，
沿用原有人工核對，不聲稱逐列驗證成功。輸入解析失敗（包括空 rows 回覆）不在此新增重試路徑。
手機的 OCR 文字核對只能對照 OCR 產生的文字，不能證明它與原圖一致。
沒有新增圖片模型、校務帳密登入、來源上傳、模型下載、持久化資料或自動儲存。

涵蓋漏列、等筆數重複、欄位互換、同名不同時段、特殊節次、重複來源、跨行引號、
超過八十列的來源、無法驗證的輸入、取消與共用重試上限。
