# 截圖或檔案匯入（學校還沒串接時）

2026-10-12。這份只做評估與設計，**不改正式程式、不部署、不寫正式資料庫**。正式後端仍是 Fly 上的 `nuni-api`（`deploy/nuni-api/`）。後續實作若要存個人確認後的結果，放使用者自己的個人資料（裝置本機或既有 `users/{uid}/…`），不要寫進學校正式課表、成績、點名或班級名單，也不要對 `nuni-api` 跑 migration。

學校還沒讓我們串接時，學生要用最簡單的方式自己把資料帶進來，否則不想用。目標流程一律是：**選圖或檔案 → 自動辨識 → 預覽表格讓人一眼對、可點改 → 確認才寫入**。認不準的欄位標黃。錯資料不能默默進去。

學號驗證、一校一份 adapter 見 [school-login-adapters.md](./school-login-adapters.md)。那條路還沒 live 前，一般帳號靠這份匯入用課表；驗證成功是在**既有平台帳號上加上學校保證**，自行匯入的課表要接過去，不要另開一份空的。

---

## 1. 為什麼要做、現在做到哪

學校自動同步（e 校園／選課／成績正式版）要學生驗證，而且目前學號登入還未對一般使用者開放。沒有這條路時，產品不能只寫「請去學校系統看」。

現況對得上程式的部分：

| 項目 | 現況 | 缺口 |
| --- | --- | --- |
| 個人課表 | Web `/timetable`、App「我的課表」可手動新增、貼文字、選截圖。確認前不寫入。Web 有草稿清單（衝堂／重複／需確認）。可先記在這台裝置；有平台帳號後可存 `users/{uid}/personalTimetable/current`。 | App 截圖後用對話框一次確認，沒有可點改的表格。OCR 是瀏覽器／WebView 的 Tesseract.js（要連網下載字庫），不是 Apple Vision／ML Kit。沒有「資料來源：自行匯入」。空堂文案有「可以用下面的匯入」，但空狀態沒有把「匯入截圖」當主按鈕。 |
| 成績頁 | 走學校紀錄。學號未開通時標題是「這個功能還沒接通」，要人去 e 校園看。沒有截圖入口。 | 一般帳號完全沒有「自己先記一份參考成績」的路。 |
| 行事曆 | App 已可選 ICS 匯入，標題會加 `[匯入]`。 | 沒有考試週／行事曆截圖。ICS 匯入後沒有逐筆預覽確認。 |
| 選課結果 | App「從選課系統匯入」依賴學校課程清單。 | 學校沒接通時這條是空的。選課結果截圖還沒接上個人課表草稿。 |
| 學生證 | 沒有「拍學生證當個人資料」的正式流程。學生證出現在付款／門禁說明，那是學校核發用途。 | 未驗證帳號不該拿學生證照當通行或付款依據。 |
| 服務目錄 | `campusServices` 把「課表」標成學校帳號。 | 和「一般帳號也能排課表」不一致，之後文案要改，這次不動程式。 |

既有可重用的契約在 `packages/shared`：`parseTimetableText`、`analyzeImportDrafts`／`applyImport`（信心低於 65 標「需確認」、確認前不套用）、靜宜第 1–13 節時段表。AI 只能當建議層（見 `docs/adr/0003-ai-as-advisory-layer.md`），不能直接寫入課表或成績。

## 2. 一般帳號 vs 已驗證學生

**一般帳號**：Google／Apple／Email 登入，或這台裝置還沒登入。沒有經過學校核對學籍。  
**已驗證學生**：學校核發身分已通過（學號／SSO／校方核可信箱等）。只有這層能拉學校自動同步的正式資料。

原則：課表、自己記的考試、自己匯入的參考成績、自己填的身分備註，**不需要學生驗證**。需要驗證的只有「從學校自動同步、且會被當成正式校務」的資料。

| 功能 | 一般帳號 | 已驗證學生 |
| --- | --- | --- |
| 看／編輯個人課表 | 可以。手動輸入或截圖／檔案匯入。本機先用；登入後可雲端備份到自己的個人文件。 | 可以。另外可「從學校課表帶入」，仍要預覽確認。 |
| 截圖或檔案匯入（課表、考試、選課結果、參考成績、身分備註） | 可以。來源標「自行匯入」。 | 可以。同一套流程，不取代學校同步。 |
| 空堂、下一堂、本機讀書規劃 | 可以，只根據自己這份課表算。 | 可以。 |
| 成績正式版（學校成績單、排名、GPA 官方值） | 不行。頁面維持未接通／請到學校系統。可另提供「參考成績」（自行匯入，不算正式）。 | 可以自動同步。畫面上來源寫學校系統與讀取時間。 |
| 正式點名、出缺席正式紀錄 | 不行。 | 可以（課程成員＋學校／老師開啟的點名）。 |
| 班級名單 | 不行。 | 老師／校務身分才能看；學生端不因自行匯入而看到同學名單。 |
| 學生證當通行、付款、借閱、宿舍門禁 | 不行。拍學生證不能取得這些權限。 | 以學校核發與學校系統為準，不靠照片。 |
| 自行填寫姓名／學號／系所 | 可以當個人備註，**不因此取得學籍或校務權限**（現有帳號頁已是這個意思）。 | 學校回傳的身分為準；自行填寫當備註或被覆蓋（見第 8 節）。 |
| 找同學、空堂邀約、課程申訴 | 維持現況：要學校帳號。截圖匯入不打開這些權限。 | 可以。 |
| Nuni 課程空間（老師開課、作業） | 跟現在一樣走平台帳號，與學籍無關。 | 同上。 |

沒登入時：課表與匯入可先留在這台裝置。換裝置或清資料會不見，畫面上要講清楚。登入一般帳號後，把本機這份接到該帳號，不要開第二份空課表。

Apple／Email 登入目前不是完整產品入口（平台登入以 Google 為主）。設計上凡「不是已驗證學生」都算一般帳號，之後若開 Apple／Email，權限表不必另寫一套。

## 3. 每種資料可接受的來源

愈結構化愈準、愈便宜。截圖是「最懶也最願意用」的預設；能選檔案就並列，不要逼人只會截圖。

| 資料 | 手機截圖 | 網頁另存 PDF／HTML | 匯出 Excel／ICS | 拍照（紙本或螢幕） | 分享到 App |
| --- | --- | --- | --- | --- | --- |
| 課表 | **首選。** 選課結果或 e 校園週課表。直的、一週一張最好。多張可一張一張加。 | HTML 表格最穩。PDF 若是真表格可抽列；掃描影像 PDF 當圖處理。 | Excel／CSV 若有星期、節次、課名，優先走表格解析，不要走 OCR。ICS 在台灣課表少見（多半是第 N 節不是鐘點），當次要。 | 可以，準確度較差，必標黃。反光、歪斜要先提醒「再拍一張或改截圖」。 | 相簿、檔案 App、AirDrop／分享表單進匯入頁。 |
| 成績（參考） | 學期成績截圖。一次一學期較準。 | PDF／HTML 成績單列名、學分、分數。 | Excel／CSV 最好。 | 紙本成績單可以，學號與姓名當備註，不算驗證。 | 同課表。 |
| 行事曆／考試 | 考試週、校曆、課程公告截圖。 | 校曆 PDF。 | **ICS 首選**（現有解析可留）。Google 行事曆匯出、學校若有訂閱網址。 | 可以。 | 分享 `.ics` 或圖片。 |
| 選課結果 | 中選清單截圖，常比週課表更好對（有課號、學分、狀態）。 | 選課系統另存。 | 選課匯出 Excel。 | 少用。 | 同課表。寫入前轉成課表草稿，狀態「備取／未中選」預設不要勾選。 |
| 學生證身分 | 只當「自己填身分」的輔助，**預設不鼓勵**。若做：只抽姓名、學號、系所；大頭照與條碼不存。 | 不收學生證掃描檔當驗證件。 | 不適用。 | 同截圖，裝置端辨識後刪圖。 | 不做成「分享學生證照到伺服器」。 |

不接受：把學校帳密貼進 App、請使用者把 Cookie 匯出、遠端幫登入學校。那是串接，不是這條匯入路。

## 4. 讀取方式、成本、準確度

分三層，由上到下才用下一層。

### 4.1 結構化檔（先做、幾乎免費）

Excel／CSV、ICS、HTML 表格：對欄、對節次、對日期即可。準確度高（欄名對得上時約九成以上）。不經過 OCR，也不經過模型。選課 Excel、ICS 行事曆應走這層，不要當成圖片。

### 4.2 裝置端 OCR＋版面解析（截圖預設）

| 端 | 建議 | 說明 |
| --- | --- | --- |
| iOS | Apple Vision（`VNRecognizeTextRequest`） | 繁中螢幕字尚可，離線、不傳圖。 |
| Android | ML Kit Text Recognition v2（中文） | 裝置端。 |
| Web | 可暫留現有 Tesseract.js，標明要下載字庫；有 Safari／Chrome 內建 OCR 再換。 | 現況已從 jsDelivr 載 Tesseract，離線會失敗。 |

版面比單字 OCR 難。現有 `parseTimetableText` 吃的是「星期一 第3-4節 資料庫／王老師／主顧303」這種一行一句。週課表截圖 OCR 出來多半是格子、表頭「一 二 三…」、節次在左側。**一定要有各校版型設定檔**，至少：

- 節次表（靜宜已有 08:10–21:40 共 13 節；他校另檔，不可拿靜宜硬套）。
- 課表：列＝節次、欄＝週一到週五；或列＝一門課、欄＝課名／星期／節次／教室／教師。
- 成績：課名、學分、成績、學期。
- 選課：課號、課名、學分、星期節次、中選狀態。

設定檔放 `packages/shared`，按 `schoolId` 選。認不出版型時不要猜整張表，改把 OCR 原文給學生對照，或請改貼文字。

裝置端表格課表：欄位對得上時大約七到九成；缺星期或節次要標黃。紙本、手寫、歪斜會掉到五成以下，應提示改截圖。

### 4.3 雲端／模型結構化抽取（備援、要使用者同意）

適用：裝置端沒字、版型對不上、或多張雜亂截圖。輸出必須是固定 JSON 草稿（課名、星期、節次…），再進同一張預覽表。**模型結果是建議，不是成績或課表真相。**

成本（量級，實作前再核價）：雲端 OCR 大約每千張數美元；多模態模型一張大約幾分到幾角美元，截圖一多就貴。準確度對雜亂版面通常比純 Tesseract 好，但仍會改數字、改教室，所以低信心欄位必黃、必人工確認。

隱私預設：**圖不上傳**。只有學生按「用雲端再認一次」才傳，用完即刪，日誌不留原圖。一般帳號預設也走裝置端；未登入者不開雲端備援，避免圖進別人的帳。

現有 Tesseract WebView 不是裝置端優先，實作第一階段就應換成 Vision／ML Kit；Tesseract 只留做 Web 或備援。

## 5. 匯入流程（所有類型同一套）

1. **入口**  
   空狀態主按鈕「匯入截圖」。旁邊次要：「貼文字」「選檔案（Excel／PDF／ICS）」「手動新增」。未接通學校時不要只放「請先登入學號」。

2. **選圖／檔**  
   相簿、拍照、檔案。一次可多張，但預覽合併成一張表。圖只進暫存。

3. **自動辨識**  
   先看副檔名／內容是不是 ICS、試算表、HTML。否則 OCR＋該校版型。過程中明確寫「辨識完成前不會改你現在的資料」。

4. **預覽表格**  
   欄位依類型（課表：課名、星期、節次、教師、教室；成績：學期、課名、學分、成績…）。每一格可點改。列可勾選。信心低、衝堂、重複、缺節次的儲存格**黃底**，列上寫「需確認」。App 第一階段就要用這張表，不要再用只有「確認／取消」的對話框。

5. **確認寫入**  
   未按確認＝沒寫入（沿用「課表尚未被修改，按確認匯入後才會套用」）。黃列可寫入，但該列至少被看過或改過；也可讓人取消勾選。沒認出任何列：不寫入，請改貼文字或手動新增。

6. **寫入後**  
   只存學生確認後的列＋來源 `self_import`＋匯入時間。暫存圖刪掉。不存原圖、不存 OCR 全文。

合併或取代：已有資料時問「整份取代」或「只加入還沒有的」。預設課表空的用取代；已有課用合併，衝堂列黃底請學生挑。

## 6. 隱私

- 圖與 PDF 只為辨識存在暫存，確認或取消後刪。相簿原圖不刪（那是學生自己的）。App 快取與 Web object URL 都要清。
- 伺服器預設不收原圖。雲端備援僅選擇加入，處理完刪物件，保留時間以分鐘計。
- 只存確認後的結構化結果。不存人臉、學生證條碼、證件影像。
- 每筆標 `source: self_import`，中文「自行匯入」。學校同步是 `source: school_sync`。畫面要看得到，不能混成「學校資料」。
- 自行匯入的成績、學號、姓名**不是**已驗證學籍，也**不是**正式成績。助理、申訴、點名、排名不可把這些當官方來源。
- 不把匯入圖拿去訓練。不寫正式 `nuni-api` 資料庫。
- 未登入資料只在這台裝置；登出或換帳號要清畫面上的私人列，規則與現有成績頁切帳相同。

法務草稿曾寫裝置端 Vision／ML Kit、行事曆在本機。這條功能若上傳截圖，上架前要改隱私說明。本設計預設不上傳。

## 7. 怎麼接到現有頁面與未接通狀態

未接通、讀取失敗、清單真的是空的，三種畫面要分開。匯入入口放在「未接通」和「真的空」，不要放在「暫時讀不到」還假裝有資料。

**課表（先做）**  
- 一般帳號／未登入：空狀態主按鈕「匯入截圖」，次要貼文字、手動新增。現有匯入區留著，空狀態不要把按鈕藏在摺疊裡。  
- 已驗證且學校有課：保留「從學校課表帶入」，仍進同一張草稿表。  
- 服務目錄之後應改成一般帳號可進課表；此次只記，不改程式。  
- 未登入雲端備份維持「這個功能還沒接通，雲端備份先不用」，不擋本機匯入。

**成績**  
- 正式成績：未驗證維持「還沒接通／請到 e 校園」。  
- 另開「參考成績（自行匯入）」區塊或子頁，避免和學校成績單同一張表沒標來源。空的參考成績放「匯入截圖」。  
- 已驗證：上面學校正式版，下面可留自行匯入；正式列不可被截圖覆寫（見第 8 節）。

**行事曆／考試**  
- 空狀態：「匯入截圖」＋既有「匯入 ICS」。  
- ICS 也改走預覽表再確認，與截圖同一套，不要選完檔就直接進列表。

**選課結果**  
- 未接通時不要停在空白「學校課程」。改走匯入（截圖／Excel）→ 課表草稿。備取預設不勾選。

**學生證身分**  
- 帳號頁可「自行填寫」學號系所（已有精神）。拍照辨識若做，只填這些欄，並寫「這不是學生驗證」。  
- 不在付款、門禁、點名放「拍學生證匯入」。

## 8. 之後綁定學校時，資料怎麼合併

綁定＝一般帳號通過學生驗證，或學校串接上線後第一次同步。**不能默默覆蓋學生已確認的自行匯入。** 也不能讓自行匯入冒充正式資料。

共同規則：

1. 每筆有 `source`（`self_import` / `school_sync`）與 `updatedAt`。  
2. 同步進來的學校資料先當草稿，預覽「將新增／將取代／有出入」，確認才寫。  
3. 正式欄位（正式成績、正式點名、班級名單、學校身分）以學校為準；自行匯入不得覆蓋。  
4. 個人課表、自己加的考試、參考成績：預設合併，問清楚。

| 類型 | 建議 |
| --- | --- |
| 課表 | 學校課有對應鍵（課名＋星期＋節次，有課號更好）→ 預覽標「學校資料將取代這門自行匯入」，教室教師以學校為準，學生可勾「保留我改過的教室」。學校沒有、自己加的（社團、校外）→ 留下，來源仍是自行匯入。衝堂 → 黃列請人挑。提供「用學校課表整份取代」給想一次對齊的人。 |
| 參考成績 vs 正式成績 | 正式成績新開來源＝學校的列，不刪參考列。同一門課兩筆並陳時標「以學校為準」。學生可刪參考列。不把自行匯入的分數寫進學校成績集合。 |
| 行事曆／考試 | 學校校曆／課程截止日進來後，時間相同視為同一件，來源改學校或並陳。自己加的提醒留下。ICS 匯入維持 `[匯入]` 或改成「自行匯入」。 |
| 選課結果 | 綁定後改讀學校中選清單產生課表草稿，與第 7 節「從學校課表帶入」相同。 |
| 身分 | 學校回傳的姓名、學號、系所覆蓋自行填寫的對應欄，並標已驗證。自行填而學校沒給的欄（例如常用名）可留。學生證照片若曾暫存，綁定時確認已刪。 |
| 點名／名單 | 綁定後才出現。不存在「自行匯入點名」與學校合併。 |

換帳號、登出：本機未登入草稿只在使用者選擇「接到這個帳號」時合併；不要把 A 的自行匯入寫進 B。

`nuni-api`：綁定學籍、課程成員仍走現有 API。自行匯入的課表／參考成績不要當成 API 的學校課表或成績寫入。Fly 正式庫這次評估不寫。

## 9. 先做哪個、階段、工時、要你決定的事

**先做課表。** 每天都要看、現有草稿契約最完整、一般帳號已經能存個人課表，缺的是「截圖真的好用」：裝置端 OCR、格子版面、預覽表、空狀態主按鈕、來源標籤。沒有課表，成績與選課截圖也沒地方可去。

工時是程式與驗收的人時，不是上架日曆。正式後端與正式庫不包含在內。

| 階段 | 範圍 | 大約人時 | 依賴 |
| --- | --- | --- | --- |
| A. 課表匯入可用 | 空狀態「匯入截圖」；App 預覽表可點改、黃格；Vision／ML Kit，失敗才 Tesseract／貼文字；靜宜週課表版型＋既有一行文字；來源 `self_import`；圖用完刪；一般帳號／未登入本機可走完。Web 對齊黃格。測試用固定截圖與 Excel 樣本。 | 45–70 | 你同意第 10 節幾件事 |
| B. 檔案與選課結果 | Excel／CSV／HTML 課表；選課結果截圖進同一草稿（備取不預設勾選）。 | 16–28 | A |
| C. 行事曆／考試 | 截圖預覽；ICS 也改確認後才寫；來源標籤。 | 20–32 | A |
| D. 參考成績 | 成績頁未接通時給自行匯入參考區，與正式成績分開。 | 28–40 | A、你決定成績要不要給未驗證帳號看參考區 |
| E. 學生證備註 | 選做。只填姓名學號系所，圖不離裝置。不做可只留手動填。 | 12–20 | 隱私是否做拍照 |
| F. 綁定合併 | 學校同步預覽、課表合併／取代、成績並陳。學校串接未上線可先做假資料契約與測試，不碰正式庫。 | 24–36 | A，最好 D 也有 |

A 做完就可給學生在學校沒接通時開始用。B、C 可並列。D 在文案沒講清楚「非正式」前不要上。E 可整段不做。

## 10. 需要使用者決定的事

沒定案前不要做雲端傳圖、不要做參考成績、不要做學生證拍照。

1. **圖可不可以上雲？** 建議預設否；雲端備援要另按一次。若一律禁止，雜亂截圖就只能貼文字。  
2. **未驗證要不要「參考成績」？** 建議要，但獨立區塊。若不要，成績頁維持未接通，匯入只做課表／行事曆。  
3. **綁定後課表預設「合併（學校為準，自己加的留下）」還是「整份換成學校」？** 建議合併，並提供整份取代。  
4. **沒登入的課表，登入後要不要自動接到這個一般帳號？** 建議自動接，並提示「已接到這個帳號」。  
5. **第一版只做靜宜週課表，還是一開始就多校版型檔？** 建議第一版靜宜＋「認不出就請貼文字」；他校只先把節次表留接口。  
6. **學生證拍照要不要做？** 建議第一版不做，手動填就夠，避免證件影像。  
7. **黃列要不要強制逐格點過才能確認？** 建議不強制（怕嫌煩），但確認鈕旁寫「黃底是認不準的，請先看過」。

## 11. 刻意不做

- 不改正式程式、不部署、不對 Fly `nuni-api` 或正式資料庫寫入（本文件本身）。  
- 不拿學校帳密代登、不爬使用者沒同意的頁。  
- 不讓自行匯入變成正式成績、點名、名單、門禁。  
- 不把原圖當頭像或公開資料。  
- 不等待學校串接才讓一般帳號用課表。
