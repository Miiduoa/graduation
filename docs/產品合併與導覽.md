# Campus One 要做成什麼樣子

這份文件給人看，不是給工具看。對完三個產品之後，決定 Campus One 就是那一個 App，課表、找人、課務、生活都走同一套導覽。nunu.tw 繼續用，後端繼續走 Firebase，不另外掛 nolu 的 Supabase／Neon／Netlify。

核對來源：Campus One（本 repo）、nolu（`Miiduoa/web`，口號「有空就碰面」）、nuni-v2（私人 repo 這次環境讀不到，對照既有文件與 #62、#64–#70 的公開討論）。競品以台灣學生實際在用的為準：校務系統／e 校園、TronClass、CoolCourse／類似課表 App、Dcard 校園版。

## 一句話

Campus One 是靜宜的校園助手。課表要能自己管、截圖確認後才寫入；好友課表要先加好友才看得到；共同空堂可以約吃飯或讀書；課務與生活用真的狀態，沒開通就說沒開通。

## 為什麼課表不跟 nolu 後端走

nolu 的課表規則值得留：節次、衝堂、確認後才寫入、好友可見、空堂邀約。它的帳號、備援網和自建 session 不值得再養一套。Campus One 已經用 Firebase Auth、Firestore、既有好友文件。課表寫進本人文件，分享用有期限的 token，邀約寫進 meetups。學校選課紀錄仍走現有 `getMyAcademicRecords`，只當帶入來源。

nuni-v2 的記憶體預覽登入不當正式身分。線上站繼續是 nuni.tw／Fly `nuni-web`，這次不部署。

## 一個 App 的導覽

學生：

1. **今天** — 下一堂課、該簽到的課、今天的空堂。
2. **課務** — 我的課表、幫我安排、教材／作業／點名／討論／申訴。學校課表從這裡帶入。
3. **生活** — 地圖、公車、餐廳、校園牆、找人、共同空堂、報修。
4. **我** — 個人檔案、訊息、設定、匯出、刪帳、條款。

商家改看：待接單｜出餐｜菜單｜營業。教職員仍進課務裡的工作台，不另做一個 App。

畫面原則沿用現有紙白／墨綠。本機寫入成功只說「已記在本站」。沒有資料就空著，不要用預覽學生頂替。

## 這次先做、之後再做

先做：個人課表（三種看法、節次、編輯、截圖／文字匯入需確認、分享連結、好友課表、共同空堂邀約、安排幫手）、申訴頂卡、學生四入口、拿掉畫面上的助理浮球與 AI 用語、法律頁補齊。

之後：把還關著的課務（完整選課、正式測驗繳交）接到校方；店家金流；職涯資料源；nuni-v2 原始碼進到這個環境後再對一次畫面細節。
