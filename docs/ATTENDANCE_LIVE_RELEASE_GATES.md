# 課堂前景同步驗收

## 本輪範圍

Web 課堂的最新 50 場點名可接收伺服器更新。學生頁同步本人的出席收據，教師頁只同步場次與人數，不偷偷讀取或展開全班名單。全班詳細名冊與 CSV 仍是主動查核的快照，介面保留查核時間，不宣稱整份名冊自動即時更新。

教師開啟或結束點名後，學生不用再手動重新整理。更正本人的出席狀態也會更新；來源仍區分 QR 簽到與教師補登。沒有新增寫入端點、權限規則、付費辨識服務、依賴或部署設定。

## 同步與安全邊界

- 只接受非快取、沒有待提交本機寫入的 Firestore 快照。先核對場次版本、課程身分、時間與非負整數計數；個人收據沿用嚴格的名冊驗證。
- 最新場次與目前顯示的個人收據都確認後才啟用操作。快取不代表未簽到；查無收據不代表缺席。
- 離線、切換背景或同步錯誤時暫時移除簽到／教師更正入口與私有細節，卸載掃碼元件及停止相機。恢復連線不等於已確認，必須等待新的伺服器快照。
- 隱藏分頁、pagehide 與離開課程會移除監聽；回到頁面再建立，並再次確認當前登入帳號。錯誤可透過「更新紀錄」明確重試。
- 退選、權限變更、帳號或課程切換時，舊訂閱與較晚到達的手動讀取不得恢復舊資料。
- 教師使用一個場次查詢；學生使用一個場次查詢及每場一個本人收據監聽，上限 50 場。人數變動不會重新註冊所有收據或重跑整份歷史查詢。這不代表 Firestore 用量免費，仍需遵守專案讀取配額。
- 不保留跨背景／斷線的未送出簽到碼與更正草稿；回到課堂需重新核對再操作。
- 多個監聽提供各自最新的已確認快照，不宣稱跨文件顯示是同一時間的資料庫交易快照。寫入仍由既有伺服器交易決定。

## 驗證紀錄

本地已以 strict TypeScript 編譯無外部相依的協調器，並由 Node 實際執行 20 項檢查與 500 組確定性場次窗口切換。檢查包含快取、遲到回應、同步註冊失敗、錯誤釋放及重複訂閱。這是實際執行核心程式，不是 Firestore emulator、完整 React 或實體手機驗收。

新增 Vitest 測試檔：
- `attendanceLiveFeed.test.ts`：快照組合與監聽生命週期。
- `watchAttendanceLive.test.ts`：Firebase metadata、本人資料隔離、帳號切換與瀏覽器背景／網路事件。
- `CourseAttendanceLive.test.tsx`：真正課堂元件的開始／結束、自動更新、相機清理、離線、補登、重試與手動查詢競態。

既有兩份課堂／相機測試只加入隔離的同步替身，保留既有測試與斷言。新提交的 Vitest、Lint、完整相依型別及建置結果，仍須由 GitHub CI 確認，不能沿用 PR #305 的結果。

## 正式發布前

使用 HTTPS 測試站及兩個真實測試帳號驗證：老師開啟 → 學生頁自動出現 → 掃碼並明確確認 → 老師人數更新 → 老師結束 → 學生不能再送出 → 老師核定請假 → 學生畫面更新。另驗證 Safari 與 Chrome 在鎖屏、背景、網路中斷、重新登入與退選後的行為。

不得將通用 App smoke test、純函式測試或本地瀏覽器替身視為上述真實流程已通過。
