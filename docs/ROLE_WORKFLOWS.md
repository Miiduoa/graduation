# 角色、使用流程與管理範圍

更新：2026-10-09（Asia/Taipei）。本文區分現行行為與待補的產品能力，不代表所有角色流程均已上線。

## 權限的四個範圍

| 範圍     | 權威來源                                                  | 管理事項                                                 | 不會因此取得的權限                 |
| -------- | --------------------------------------------------------- | -------------------------------------------------------- | ---------------------------------- |
| 平台     | Nuni 目前 session 的 `isPlatformOperator` 與每次 API 授權 | 學校接入、服務狀態、公開看板、跨校檢舉、限時代操作與稽核 | 私人課程成員資格、無期限的校方代理 |
| 學校     | 校方核發的身分與所屬學校授權                              | 學校人員、校務服務、校內資料                             | 其他學校管理權、平台管理權         |
| 課程     | 每門課的 `memberRole` 與課程狀態                          | 教材、作業、作答、回饋與邀請                             | 正式教職員／學籍資格、跨課程存取   |
| 公開交流 | 登入帳號、公開看板與封鎖／檢舉規則                        | 瀏覽、發文、封鎖、檢舉                                   | 校務紀錄與私人課程內容             |

權限不能只用一個全域「學生／教師／管理員」數字比較大小。同一人在 A 課可以是共同授課者，在 B 課是學生；校方管理員也不應因職稱讀取所有私人作答。前端依已驗證狀態呈現入口，授權仍由後端執行。

## 現行工作流程

### 學生

今日頁讀取本人有效課程 → 列出仍開放、本人尚未繳交的作業 → 直接開啟對應作業 → 送出 → 收到伺服器確認 → 顯示繳交內容與時間。待辦、已繳交、老師回饋分開瀏覽，切換分類保留未送出的草稿。

參考期限不等同停止收件。超過參考期限但伺服器仍回覆 open 時，介面標示「仍可繳交」；只有 closed 或 archived 才停止對應操作。失敗或未知送出結果保留原本重試鍵，不畫出成功收據。

### 課程負責老師與共同授課者

授課課程 → 發布教材／作業／測驗 → 查看實際收件 → 留下回饋。課程負責老師可產生學生邀請碼；共同授課者不顯示該操作。收件份數不能標成「待批閱數」，因為現行列表沒有完整的未評閱人數契約。

建立課程只會取得該課程的負責角色，不認證為學校教職員。課程封存後保留可讀紀錄並停止新的課務操作。成員資格拒絕、帳號變更或 session 更新時，隱藏舊內容；暫時網路錯誤與權限撤銷分別處理。

### 平台管理

管理總覽 → 查看待審學校與最近待處理檢舉 → 進入對應操作 → 確認作用範圍／原因 → 等待伺服器確認 → 查看操作紀錄。檢舉總覽僅標示本次回傳、最多最近 50 件，不將截斷列表當作全平台總量。

學校開通與公開看板是不同事項。已開通學校的設定預設唯讀，平台協助修改需啟動既有的 15 分鐘代操作；到期或結束後回復限制。關閉學校與檢舉決定保留原因與伺服器檢查，不用瀏覽校園偏好代替操作對象。

### 校方管理與服務人員

現有完整管理台保留學校人員、店家與課班管理入口。新的 Campus One 管理介面尚未覆蓋所有校方操作，不能以平台選校直接代入校方身分。請假審核者、證件承辦、店家等角色應依服務與資源配置，不能一律歸為課程教師。

## 尚未完成的治理能力

下列是下一階段需求，沒有把未實作能力包裝成可用按鈕：

| 項目              | 需要的行為                                         | 最低驗收                                                 |
| ----------------- | -------------------------------------------------- | -------------------------------------------------------- |
| 課程成員管理      | 負責人查看成員、邀請共同授課者、撤銷成員           | 非負責人拒絕；撤銷後所有舊頁面與寫入立即失效；保留稽核   |
| 課程交接          | 原負責人提出、目標接受；交接期間保持唯一有效負責人 | 雙方確認、過期／撤銷、重試冪等、併發交接、最後負責人保護 |
| 校方委派          | 以學校與職務限定能力及有效期限                     | 跨校拒絕、委派到期、離職撤權、禁止自行升權               |
| 管理操作追蹤      | 每筆操作帶執行人、對象、原因、前後值與時間         | 不記錄密碼／session；搜尋與分頁；敏感存取受限            |
| 大量接入          | 批次匯入前預覽、逐列結果與可重試失敗               | 不因部分失敗重複建帳；禁止自動升權與覆蓋現有成員         |
| App／Web 一致帳號 | 原生 App 接通 Nuni session 與相同成員授權          | 實機雙帳號、登出／撤權、送出確認、重啟與跨裝置同步       |

## 競品基準與可量測目標

官方資料確認：[TronClass](https://www.tronclass.com/features) 已有課務與點名；[Zuvio](https://www.zuvio.com.tw/student) 已有課程碼與課堂互動；[USC Campus App](https://uscapp.usc.edu.tw/download/) 已有今日卡、截止日、下一堂課與離線課表。擁有這些功能本身不足以證明超越。

優先比較核心任務的完成率、點擊數、送出後是否有可信回執、失敗後能否恢復，以及角色切換是否誤導或暴露舊資料。本輪目標是首頁兩次以內開啟待辦、正確區分授課與修課、管理員找到負責事項；尚未進行競品實機對照測試，因此不宣稱已勝過競品。

此分支的驗證與交付範圍見 PR；正式部署仍以 [PLATFORM_RELEASE](PLATFORM_RELEASE.md) 的執行版本為準。
