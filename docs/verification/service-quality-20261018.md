# 服務操作與錯誤恢復驗證（2026-10-18）

本輪從 GitHub main `7be5f05a75d8df962a58b2b441a6e326927c87c1` 建立獨立分支，沒有變動其他工作目錄，也沒有合併既有候選 PR。範圍保留 Web、App、API、13 個產品領域及發布驗收；本輪交付的是下列可重現問題的修正，不代表所有功能、真機或商店驗收完成。

## 本輪改變

| 操作 | 原有問題 | 修正後行為 |
| --- | --- | --- |
| Web 關閉或更換找人代號 | 刪除公開代號失敗仍清掉私人指標，畫面宣稱關閉成功；跨校共用指標 | 公開代號與校別私人指標使用同一交易。失敗不宣稱成功，仍可重試；改名衝突不會清掉原代號 |
| Web 找人、好友邀請 | 帳號切換與延後回應可能留下前一人的資料；部分操作沒有錯誤回饋 | 依帳號與校園重新建立畫面；讀取可重試，操作防連點，查詢過期回應不覆蓋新結果 |
| App 搜尋同學 | 不存在或讀取失敗的 ID 被作者姓名備援轉成成員；錯誤被當成沒人符合 | 搜尋獨立查證實際資料與本人搜尋同意，失敗保留文字並提供重試；新增搜尋索引 |
| Web 繳交作業 | A 作業送出後重讀整頁，B 尚未送出的文字被卸載清除 | 同帳號、同課程背景更新保留其他草稿；拒絕存取、換校或換帳號則移除私有內容 |
| 學校服務入口 | 查詢登入方式失敗被誤報成服務尚未開放 | 區分載入、正式關閉、暫時失敗；登入、個資、校務入口與服務搜尋可重試 |
| 生活與所有服務 | 按鈕重複寫「打開」，圖書館等入口缺席，點進去才知道需要另一種帳號 | 使用「查館藏」「查公車」等操作；補入圖書館、公告、跨校交流，先標示帳號需求與學校登入狀態 |
| App 校園動態與看板 | 初次失敗可能一直載入；備援查詢遺失看板條件 | 顯示重試，網路失敗保留已讀資料，權限拒絕清空；備援查詢保留看板範圍 |

「移除 AI 痕跡」以可用的操作、自然繁中、正確狀態與必要說明為準。沒有刪除授權聲明、改寫歷史來源或移除仍有實際用途的助理功能。

- App 新增回歸：5 suites、35 tests passed，涵蓋找人、動態、看板、登入重新驗證與個別依賴失敗。
- Web production build、全工作區 typecheck 與 lint 通過；lint 仍有既有警告，沒有宣稱零警告。
- iOS 與 Android Expo export 成功，兩端各產生約 12.5 MB 的 Hermes bundle；這是 JavaScript 打包，並非原生簽章安裝包或真機驗收。

- 本機實際瀏覽器：生活入口、搜尋、503 後重試、查詢字串保留；320／390／1,440 px 無橫向溢出。登入方式失敗／恢復使用明確的瀏覽器測試回應，不是正式服務故障演練。
- 本輪獨立審查涵蓋差異及相關契約；不代表整個專案的安全認證。
- Web 獨立審查未發現確定缺陷；App 第一輪發現訂閱與限時動態吞錯問題，修正後第二輪無剩餘可重現問題。

## 發布仍需處理

- 新增的 `directory` 複合索引（`isDiscoverable`、`displayName`）需部署並完成建置，App 的新搜尋才能在正式 Firestore 使用；模擬器不證明線上索引已存在。
- 2026-10-18 本輪實查 `https://nuni.tw/api/nuni/sign-in-options` 為 `google: true, studentId: false`。修正學校帳號功能不等於正式學校登入已開放。
- 歷史上若已失去私人指標，孤立的公開代號不能由禁止列舉的客戶端自動清查。此次交易避免產生新孤立代號並遷移可確認擁有者的舊指標；正式歷史資料清查尚未執行。
- 未把分支修改當成 main、正式部署或原生安裝包。正式 OAuth、兩個帳號／兩台實機、iOS／Android 通知、掃碼與商店仍待驗證。
