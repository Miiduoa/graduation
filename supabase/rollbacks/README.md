# 繳交完整性回滾

本目錄不由 migration CLI 自動套用。請先確認目標環境與備份，使用具備物件擁有權及 migration ledger 寫入權限的管理角色，手動執行所選 SQL，並設定遇錯即停止（例如 `psql -X --set ON_ERROR_STOP=1 --file <檔案>`）。每份 SQL 自帶單一交易與 5 秒鎖定逾時；不得包在其他交易內執行。

- `20261106095010_restore_submission_grading_baseline.down.sql`：只撤回基線，限後續三份 migration 尚未套用時使用。若 ledger 已有 20261021055702，整份跳過。否則只移除帶有本基線建立標記的 trigger／函式，並僅在完整性函式仍為本基線寫入的版本時還原正式快照，保留其他既有物件；不刪 ledger，成功後須由部署流程另行撤銷 20261106095010 紀錄，才能重新套用。
- `2026-11-submission-integrity-batch.down.sql`：撤回基線與 20261106095011、20261106123311、20261106131129，並刪除這四筆 ledger 紀錄。只適用於未套 20261021055702、且符合本次正式 DDL 快照的環境；若 ledger 已有該版本則報錯，整筆交易不生效。可用於整批或部分套用後回復；不適用於已有其他相依變更的環境。

基線以物件註解記錄建立來源，不覆寫既有物件的註解。請保留標記；若標記遭移除，單檔回滾會保守保留該物件。既有同名物件無法僅靠 ledger 推斷來源。回滾不使用 CASCADE；若有額外相依物件，交易會失敗，須另行評估。

整批回滾內嵌正式原始函式與 policy 定義，不需讀取暫存 DDL 檔。它恢復原本較寬鬆的權限與存取語意，保留既有附件、繳交紀錄及其他使用者資料，不會撤銷期間已發生的資料變更。SQL 可重跑；請先停止相關部署與寫入，避免回滾與其他變更交錯。

相容性限制：正式 `protect_submission_integrity()` 只認教師或平台管理員，僅持有 `assignments.grade` 權限者仍可能被清除新增成績或擋下更新；基線只對符合正式快照雜湊的函式放行 `statement_timestamp()` 伺服器收據，讓 095011 的學生重繳可通過；未知版本會中止交易，已修正版本可重跑。兩份回滾只在目前函式內容符合本基線修正版雜湊時還原快照，不變更其 ACL。`group_id` 仍不可變更。
