# 語音草稿與服務入口確認

首頁與「所有服務」的語音轉寫只填入可編輯文字，不會自動呼叫雲端助理。關鍵字捷徑、分類與一般搜尋仍在瀏覽器處理。語音辨識本身可能由瀏覽器供應商處理；Campus One 不另行上傳錄音檔。

使用雲端建議前，畫面列出 Groq、指定模型、校園代碼與本次文字。使用者勾選並按確認後，才呼叫 `understandCampusRequest`。文字內的個資不會自動去識別化；使用者可先修改。

伺服器要求用途、版本、供應商、模型、校園與文字完全相符的確認契約。未確認的舊請求會被拒絕。固定出口沿用 `freeCloudModel`，沒有其他供應商、本機模型或付費 fallback；未設定、額度不足、逾時與無效回覆分別顯示失敗。

模型只能建議既有服務入口，不能呼叫任意工具或產生外部網址。這一步不自動讀取課表、作業、訊息、訂單等私人紀錄；由本人開啟服務頁後，依原有權限讀取。回執必須包含相符的 requestId、校園、文字、供應商、模型及本站處理時間，私人預覽必須為空。本站處理時間不是校務資料的更新時間。

## 取消與隔離

- 修改文字或分類、歷史導覽、換帳號與換校園會撤銷舊確認、結果及語音 session。真正換帳校會清除草稿；同校首次解析完成保留原搜尋網址的草稿，但仍須重新確認。
- 停止語音會中止辨識。每次語音只接受第一份非空 final，晚到回呼不會覆寫文字。
- 「停止等待」清除確認並忽略晚到回覆，不代表已送出的 Callable 或供應商請求立即中止。
- 明確失敗後可手動重試，保留同一 requestId；不自動重試。單一執行個體內最多保留 128 筆、每帳號最多 15 筆、完成後 60 秒，並保留每帳號 15 次／5 分鐘限流。這不是跨執行個體的去重承諾。
- 帳號與會員資格在模型前後重新確認。拒絕入場會釋放快取；沒有用舊快取繞過資格檢查。

## 整合與驗證界線

此修補依賴 #399 的 `freeCloudModel`，需待它合入 main 後再整合，不能單獨部署缺少該模組的後端。未配置帳戶、金鑰、部署環境或計費設定；只以合成轉寫、mock 辨識器與供應商 transport 驗證。

Mobile 的舊服務語意請求缺少確認契約，會被新版後端拒絕，保留基本捷徑；原生確認 UI 不在這次範圍。其他 Mobile AI 與 Python Agent 路徑也未完成此確認流程。

任務 helper 有 30 秒期限，外層帳號 preflight 另外耗時；平台可能先截斷請求，不能保證每次都取得帶原因的逾時回覆。免費方案聲明仍須由營運者核實，模型名稱不能證明帳戶不計費。
