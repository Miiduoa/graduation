## 使用者會看到的變化

- **截止日對得上日曆。** 首頁仍優先處理 24 小時內的待辦，但依台北日期分別標示「今天截止」與「明天截止」。較遠日期寫明月日，跨年帶年份。
- **短時間不再誇大成一小時。** 30 秒顯示「不到 1 分鐘」、20 分鐘顯示「還剩 20 分鐘」，小時與分鐘分開保留。過期天數按實際經過的完整 24 小時計算，不會因剛跨午夜就變成逾期一天。
- **回到首頁立即對時。** Web 恢復頁面、分頁可見或視窗重新聚焦，App 返回今天頁或回到前景，都立即更新日期與倒數。顯示更新對齊分鐘邊界；背景／離頁會清除對應計時器。
- **首頁推薦能實際處理的待辦。** Web 讀取時排除已關閉、逾期且未允許補交的 Firebase 作業與測驗，仍保留已發布的教師回饋。保持首頁開啟跨過截止時間時，也會移除明確不允補交的項目，不必重新下載資料。
- **保留來源政策。** Nuni 平台的建議完成時間與 Firebase 的禁止補交條件分開處理。`acceptsLate: true`、規則未知與未設定期限的已載入項目，不會被時間更新自行判成不可操作；提交仍由原有後端流程驗證。
- **切換範圍不會復活舊搜尋。** 帳號 A → B → A、登出再登入、校園 A → B → A 都建立新的搜尋狀態。舊摘要、預覽、錯誤與晚到回應不能重新出現。網址中的搜尋字及分類保留，切換本身不觸發模型請求。
- **長標題可在手機完整閱讀。** 首頁重點卡片的長英文標題會換行，320px 與放大文字時不再把頁面撐寬。

### 先重現，再修正

- 原期限函式確實把剩 30 秒／1 分鐘寫成「還剩 1 小時」，也把午夜後兩分鐘寫成「已逾期 1 天」。
- Web 舊首頁四個日期／前景案例失敗；App 舊時鐘的背景恢復及午夜案例也失敗。初次 App 測試的 React 渲染設定錯誤已修正，不計為產品缺陷。
- 資料載入的七個禁止提交案例、時間推移的兩個案例，先在原碼失敗，修正後通過。
- 搜尋原碼八個範圍切換案例失敗。新增 React commit 階段檢查，確認 passive effects 前也沒有一幀舊摘要或預覽可點選。
- 瀏覽器首輪有八個版面案例重現長標題溢出，修正 CSS 後通過。首輪另一個失敗是減少動畫的測試判準過嚴：既有 CSS 使用 0.01ms；判準調整為至多 1ms，沒有改動產品動畫設定。

## 比較基準與限制

[UniTable 官方介紹](https://unitableapp.com/) 已列出期限追蹤、課程儀表板、跨裝置同步與衝突保留；[TronClass 官方作業說明](https://support.tronclass.com/tw/question/homework/) 也區分繳交、評分與活動完成條件。本輪以日期正確、入口可完成、切帳號不殘留為可驗收基準，沒有將競品宣傳當成雙方實測，也不據此宣稱全面超越。

首頁以分鐘更新，不是逐秒時鐘。搜尋修正會忽略舊回應，不代表已取消伺服器請求。瀏覽器驗證編譯實際元件與 CSS，但使用合成 props 和 Next Link 的 anchor 替身，沒有登入真實帳號；200% 根字級不等同所有系統字體設定。Safari、原生真機、讀屏及正式服務端到端操作仍未驗收。

E 校園、學號登入與 WOW Class 停用設定維持原狀；這次沒有改 provider、API 契約、資料庫、權限、依賴、主線規則或正式部署設定。
