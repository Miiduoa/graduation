# 使用流程整理與維護準則（2026-11-14）

## 1. 範圍與五個主入口

本次整理既有功能的入口、任務分流、登入回程與首次使用流程。本文記錄的是這次工作樹的實作與定向驗證結果，**不代表本輪流程變更已合併或上線**。本輪起始基底 `3b5ef19` 已包含 PR #626 的宿舍雲端能力；後續整合 `db42bca` 的 PR #624 社團唯讀目錄與社團頁，再接入主線 `e444626`，保留 PR #623 的 GPA 修正、#625 的公開職涯頁及 #630 的隔離工讀模組。這些都是主線既有能力，不列為本輪新增功能；本輪僅修正它們與五入口、搜尋、登入及返回流程的整合。#630 的未註冊模組、API 與權限規則保持隔離，未因導覽調整啟用。PR #616（TronClass）等獨立項目的交付狀態仍以各自 PR 為準。

一般校園使用者的主入口固定為下列五項，名稱與對應關係由 [primaryDestinations.ts](../../packages/shared/src/primaryDestinations.ts) 共用：

| 入口 | 要處理的事 | Web | 原生既有 Tab key |
| --- | --- | --- | --- |
| 今天 | 先看今天的課、待辦與下一步 | `/` | `Today` |
| 課務 | 課表、課程與作業、成績、學分、行事曆 | `/timetable` | `學習` |
| 生活 | 交通、餐飲、住宿、職涯與校園資源 | `/life` | `校園` |
| 交流 | 話題、好友、對話、公告與通知 | `/connect` | `訊息` |
| 我的 | 個人資料、學生證、帳號連線與設定 | `/profile` | `我的` |

Web 的五個入口可供訪客瀏覽，主導覽的「我的」固定到個人中心，由使用者在頁內選擇登入。所有服務選單及搜尋用來找較少使用的功能；助理保留為輔助入口。

原生的五個 Tab 位於 `SchoolNavigation`。訪客與未建立學校工作區的使用者仍走既有 `PublicNavigation`／`PreAuthStack`，Google 平台功能沿用既有工作區。原生課務入口保留 `LearnStack` 的角色分流；學生畫面含課務摘要與課表入口，並非直接複製 Web 的 `/timetable`。店家角色第二格仍顯示「店家」。原生交流首頁直接呈現私訊與社群、好友、群組、通知捷徑，Web 則先呈現可搜尋的服務目錄。

這次同步的是名稱及任務歸屬，不變更既有認證與角色權限，也不重新命名原生 Tab key。實作入口見 [Web 主導覽](../../apps/web/src/lib/primaryNavigation.ts)、[原生 App](../../apps/mobile/App.tsx)、[原生 Tab 設定](../../apps/mobile/src/services/permissions.ts)、[交流首頁](../../apps/mobile/src/screens/MessagesLandingScreen.tsx)。

## 2. 任務分流與返回方式

課務次級入口沿用 [shared academicSections](../../packages/shared/src/academicSections.ts) 的「課表／課程與作業／成績／學分規劃／行事曆」。Web 課程詳情、群組及教材收藏會回到「課程與作業」脈絡；帳號與登入頁不套用課務次級導覽。學校成績與 Google 課堂回饋保留各自入口，不能因為同在 `/grades` 就把不同分頁當成父子頁。明確的社團路徑 `/groups/:groupId/club` 及其子頁屬於「生活 → 社團活動」，返回 `/clubs`，不套用課務次級導覽；一般 `/groups` 課程群組仍維持課務脈絡。

Web 生活與交流使用同一個 [ServiceDirectory](../../apps/web/src/components/ServiceDirectory.tsx)，分類定義在 [serviceJourneys.ts](../../apps/web/src/lib/serviceJourneys.ts)：

| 入口 | 任務分類 | `group` 值 |
| --- | --- | --- |
| 生活 | 出門與交通／吃飯與住宿／校園資源 | `travel`／`daily`／`resources` |
| 交流 | 看話題／找人與聊天／公告與通知 | `topics`／`people`／`updates` |

目錄預設呈現主要服務。同一任務的其他入口以可展開區收納，例如餐飲主入口下的相關功能；搜尋時仍能直接找到次級服務。名稱、說明、權限提示、父入口及功能旗標統一取自 [campusServices.ts](../../apps/web/src/lib/campusServices.ts)，分類頁不另存一份服務清單。

主線的公開職涯頁納入「生活 → 校園資源」，也可從所有服務及全站搜尋找到。「職涯／實習／校內工讀」直接導向 `/career`；「總機／地址／聯絡」仍導向學校資訊。職涯頁使用全站單一標題與麵包屑，返回生活時保留校園，避免另一條不帶校園的返回連結。加入職涯後生活預設有 10 個主要服務，飲食次級入口繼續收納；這不是新增主分頁。

`q` 與 `group` 寫入目前頁面的網址，從服務頁使用瀏覽器返回時可恢復篩選。跳到服務本身只攜帶經過整理的校園脈絡，不把搜尋、登入交易或其他頁面參數整包傳下去。Web [ServiceBreadcrumbs](../../apps/web/src/components/ServiceBreadcrumbs.tsx) 提供從深層連結回到所屬入口的路徑；它回到分類或父服務，與瀏覽器返回上一個搜尋結果的用途不同。

原生生活首頁保留地圖、餐廳、公車與圖書館等常用入口；較少使用的服務可展開或搜尋。社群、找人、行事曆仍可被生活搜尋找到，但日常主入口回歸交流或課務。既有原生 URI 保留，學校工作區中的社群與通知統一導向交流；舊 Home／Me 程式路由別名仍保留，訪客深層連結不變。分享貼文或通知的初始返回位置設為交流首頁。來源見 [CampusHubScreen](../../apps/mobile/src/screens/CampusHubScreen.tsx)、[rootNavigation](../../apps/mobile/src/app/rootNavigation.ts)、[MessagesStack](../../apps/mobile/src/screens/MessagesStack.tsx) 與 [schoolLinking](../../apps/mobile/src/app/schoolLinking.ts)。

職涯也接入原生生活分頁，`campus://career` 在訪客與學校工作區都能開啟同一個公開職涯實作；返回分別落在公開入口與生活首頁。冷開設定連結時保留「我的」首頁，第一次跨分頁開啟社群個人頁時保留交流首頁；已存在的分頁堆疊、頁面參數與草稿回程繼續沿用。職涯頁的校方公告按鈕使用既有安全導覽，在學校工作區開啟真正的公告列表，切回生活可接續職涯頁。

## 3. 訪客 → 登入 → 返回原任務

Web 使用流程以「先看能做什麼，遇到需要的資料再登入」為原則：

1. 訪客可瀏覽公開服務、整理裝置上的課表，或先進入「我的」了解帳號功能。
2. 需要帳號的操作使用既有登入工具產生返回位置，不手動拼接任意外部網址。
3. Google 帳號用於平台課程與公開交流；需要校方個人資料時，依所選學校實際開放的方式連線學校帳號。登入頁只在學號方式可用時顯示相應表單及可登入的說明；店家、教師與管理入口另以展開區呈現。
4. 登入完成後回到通過白名單的原任務；目的頁繼續依既有權限檢查資料，取得返回路徑不等於取得服務權限。

個人中心依目前可確認的帳號提供捷徑，避免登入後又走到另一種帳號才能用的頁面：

| 狀態 | 個人中心的主要安排 |
| --- | --- |
| 訪客 | 解釋登入用途，保留課表、成績匯入、圖書館、外觀與隱私入口 |
| 僅 Google 帳號 | 跨校公開交流、課堂成績與回饋、資料匯入、平台及助理權限 |
| 學校帳號 | 個人校務資料、校內社群頁、學期成績、學分規劃及學校帳號設定 |
| 確認中、錯誤或登出中 | 顯示狀態或重試入口，不提前顯示尚未確認可用的個人捷徑 |

「數位學生證」在個人中心前段有明確入口；可見入口與能讀取個人卡片是不同條件，個人證件仍依學校帳號規則處理。帳號與連線區保留 `NuniAccountPanel`，資格草稿與原有資料隔離方式不因分區而重設。

個人中心的校園服務、證件、設定及社群連結沿用目前已確認的瀏覽校園。登入連結同時保留外層選校參數與個人中心返回位置，因此從指定校園的網址進入，不會因瀏覽器另存了其他學校偏好而在登入頁換校。`all` 或未對應學校的 `personal` 範圍，在選校狀態確認後整理為 `campus=all`；不把舊學校、登入 token 或其他頁面參數一起轉送。

同樣的校園連貫性也套用到全站頁首與社團詳情的登入入口：[loginHref](../../apps/web/src/lib/navigation.ts) 將合法的校園選擇附在登入頁外層，原任務及 fragment 仍放在安全回程中；只有校園欄位可複製到外層，不轉送任意交易參數。明確 `all`／`personal` 排除殘留的學校欄位；網址指定學校不會覆寫裝置偏好。登入頁的公開服務、資料匯入及返回首頁也沿用目前校園。公開職涯以精確 `/career` 納入公開回程，沒有開放其他職涯子路徑或工讀申請權限。

本次補入精確 `/connect` 返回路徑，沒有放行任意 `/connect/*`。生活／交流回程只保留校園參數、最長 100 字的安全搜尋字串與該頁已知的 `group`；跨分類或未知群組、控制字元及無關參數不繼續帶回。新增分類時須同步核對 [legacyLogin.ts](../../apps/web/src/app/auth/account/legacyLogin.ts) 的處理及測試。相關實作見 [登入頁](../../apps/web/src/app/login/page.tsx)、[個人中心](../../apps/web/src/app/profile/page.tsx)、[公開路徑判定](../../apps/web/src/lib/publicCampusServices.ts)。

## 4. 首頁與偏好設定的漸進揭露

Web「今天」先呈現當下可做的事。訪客尚未選校園時引導選校園；已有校園但沒有課表時提供一組課表匯入／手動建立入口，不再同時堆疊多個相同目的的空狀態。訪客不顯示需要登入才能讀取的待辦與通知區塊，保留清楚的登入入口；已有課表時仍可直接查看課表內容。帳號管理集中到「我的」。來源見 [StudentToday](../../apps/web/src/components/today/StudentToday.tsx)、[TodayWelcome](../../apps/web/src/components/today/TodayWelcome.tsx) 與 [首頁](../../apps/web/src/app/page.tsx)。

首次首頁偏好以 `compactSetup` 呈現簡短介紹與「設定首頁安排」，使用者按下後才開表單。先設定目前階段與近期重點，通勤／住宿、其他目標及指定期間放在「更多安排（選填）」。可先略過，已設定後可再調整；建議最多顯示三項，不搶走今天主要任務的焦點。

展開時焦點進入第一個欄位，關閉或成功儲存後回到設定按鈕；驗證及儲存失敗保留可理解的提示。偏好由目前校園及帳號／訪客範圍區分，帳號確認中、切換或登出中不讀取另一個範圍的偏好。此為裝置保存的首頁安排，不宣稱跨裝置同步；首頁也沿用全站外觀設定。來源見 [CampusPersonalization](../../apps/web/src/components/today/CampusPersonalization.tsx)、[CampusPersonalizationSection](../../apps/web/src/components/today/CampusPersonalizationSection.tsx)。

## 5. 後續新增功能時的維護規則

- **先按任務放位置。** 修課與繳交內容放課務；交通、飲食、住宿與資源放生活；話題、找人與收訊息放交流；資料、證件、帳號及偏好放我的。「今天」呈現有時間性的摘要或下一步，不新增完整服務目錄。
- **保持五入口與角色例外的單一來源。** 主入口改動先更新 shared 定義，再核對 Web 路徑、原生顯示名稱及既有角色分流。原生路由 key、通知目標與深層連結不能只為改文案而改名。
- **先確認是否已有父任務。** 同一服務的紀錄、收藏或管理頁優先使用 `parentHref` 成為次級入口，讓搜尋仍找得到。Web 目錄必須經既有顯示函式處理功能旗標；原生則沿用自身服務開放與學校支援檢查，不直接複製 Web 可見性。
- **入口說明反映實際帳號。** 公開、裝置資料、Google、學校帳號及角色限定功能要標示正確。調整分類與推薦不授予權限，不以隱藏入口取代目的頁及後端的存取檢查。
- **每個任務都有可理解的回程。** 登入保留安全返回位置，深層頁能回所屬分類，搜尋返回保留條件；同頁分頁不是父子階層。只傳需要的校園脈絡，不沿用整包 query。跨帳號資料、編輯草稿及發文重入行為要保留原有邊界。
- **讓使用者逐步展開。** 次級功能、角色入口與選填設定收進可展開區；不可把基本操作改成必須先填完整偏好或先詢問 AI。新增可展開內容時一併檢查鍵盤焦點、讀屏名稱、空結果、失敗與重試狀態。

## 7. 續輪：職涯整合與登入、返回連貫性
