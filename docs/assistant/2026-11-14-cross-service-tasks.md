# 跨功能任務：來源查詢、相依執行與結果核對

## 這輪解決的問題

原本 Web 助理按問題選最多八項工具；讀書規劃的選擇分支會排除部分其他服務，複合需求容易只做其中一段。手機的單一已學技能也可能在分析完整問題前直接回傳。這輪把可明確辨識的複合需求拆成有限、有順序與來源依賴的任務，並保留每一步的結果。

程式從 `e4446262880c3d8188e0741f185d7aeebc3f944f` 的 main 開始；沒有將 #616 尚未合併的 TronClass writer 或 #590 的手機離線摘要修改混入本輪。

## 可實際接續的例子

| 使用者需求 | 這輪的處理 |
| --- | --- |
| 查今天課表，查未交作業，找相關教材，安排今天下午讀書30分鐘，查餐廳，查公車 | 查原課務 → 依已讀課程識別找教材 → 核對同步課表與個人行程 → 找空檔 → 產生原有簽章行程卡；餐廳、公車各自取得資料 |
| 查未交作業，安排今天15:00到16:00讀書 | 保留指定日期與一小時區間，從本次讀取的待辦選來源；確認前沒有新增行程 |
| 查今天作業，找今天30分鐘空堂 | 只查課務與空堂，不提升成建立行程，也不要求建立行程權限 |
| 查未交作業，安排今天下午讀書30分鐘，再點上次一樣的午餐 | 讀書與餐點各自準備確認內容；保留不同類型逐項確認，不能一個按鈕混成全部執行 |
| 查課表，開啟宿舍報修，查圖書館 | 課表回實際資料；尚未接到資料／執行器的服務明確標為需開啟接續，不當成報修或圖書館操作完成 |

安排後沿用既有確認、來源重查、權限、版本比較、冪等與讀回回執。正式點餐 adapter 目前仍要求付款，因此本輪不開放免付款下單；測試中免付款 fixture 的送出與重送只用來驗證原卡片契約。

## 執行架構

`crossServiceRequest.ts` 將全句拆成可完整辨識的子需求。未知子句、命名作業、互相矛盾的日期／時段、否定、引用、條件句或多段無法完整保留的安排，都回原有對話流程，不能只看到一個關鍵字就吞掉其餘要求。

`crossService.ts` 只呼叫原本的 `createTools`，不直接呼叫寫入 API。讀書安排先依序核對課務、課表、個人事件與空檔，再把本輪觀察到的精確作業 ID 交給原提議工具。教材使用課務結果中的課程 ID。單一已觀察到的公車站點可以接續到站查詢；多個站點保留選擇入口。

- 同一句的省略日期可以繼承唯一明確日期，分別指定的日期保持分開；有歧義時不猜。
- 作業／測驗篩選與每次查詢期間保留到後續安排，不從整個工具快取任意挑第一筆。
- 同一識別如果在不同課程或作業／測驗中重複，拒絕自動安排，避免工具快取選到另一個來源。
- 任一必要來源讀取失敗、不完整、缺少同步課表，依賴該來源的安排停止；餐廳等獨立查詢繼續。
- 最多十六個任務節點、十六次工具呼叫；維持原 adapter 的每題十二次 API 額度與五十五秒請求期限。額度不足保留部分結果，不默默聲稱全數查完。
- 首頁／聊天既有寫入流程與設定旗標不變；這條流程不新增排程、背景執行、永久任務記憶或跨裝置自動接續。

這些明確複合流程不需要模型決定工具順序，不把資料送往模型，回應標為 `dataRead` 以免下一輪外送私人結果。聊天入口仍使用原本的登入、同源、session、同意與配額控制。

## 能力目錄與畫面

`packages/shared/src/assistantTaskPlan.ts` 為現有服務目錄逐項標出目前 Web V2 的讀取、準備與入口能力。能力是描述，不是授權；服務本身仍檢查帳號、校園、角色及每筆來源。正式環境未接通的通知、訊息、宿舍、請假、學生證等不能因為有入口就當成可讀或可操作。

回應的任務清單採用共用解析器，限制版本、服務、節點數、欄位長度、相依順序及站內網址。畫面區分已完成、待確認、部分完成、尚未完成、開啟服務；無效資料退回一般回答。細節只在任務清單呈現一次，避免手機出現重複長段落。

卡片必須對應同一回覆中的操作識別。個人行程只有在精確回執再次核對通過後才顯示已完成；缺卡、錯誤回執、未知結果、保存未同步與取消仍保留各自狀態。備餐或導航入口不計為交易完成。來源標題以文字呈現，不能變成新的工具指令。

## 手機改善

`autonomousQuery` 先分析本輪全部意圖，再決定能否重用單一讀取技能。捷徑僅限工具與完整參數一致的單筆讀取；複合任務、寫入與需要重新查來源的操作走完整流程。

前置查詢按工具加完整參數快取，成功與失敗都只在本輪保留。必要來源失敗時不隱性重查或換用另一個篩選結果，也不接續相依寫入。回覆分別列出成功讀取與未完成項目；只有成功寫入且不是草稿，才可在摘要標為操作已完成。

## 驗證與已知範圍

使用 Node 22.23.4 與專案現有鎖定依賴，新增及回歸測試涵蓋完整 runner、真實簽章卡與確認、重送冪等、來源改變、帳校隔離、權限拒絕、取消、來源不完整、日期／時段矛盾、多課程同 ID、工具參數快取及 UI 回執顯示。測試使用合成帳號與資料，沒有提交正式作業、假單、訊息或訂單。

本輪確認的範圍是現有 nuni 私人課務／個人行程、餐廳／訂單／社團與公車的可辨識複合需求。公開課程搜尋仍有獨立入口，未將該入口完整納入通用跨功能執行器；任意自然語句、正式校方作業繳交、私人訊息代送及其他尚未接通的 writer 不能宣稱已完成。

已建立真元件的暫存視覺檢查頁；Browser 連線要求原始瀏覽器環境、cloud browser 無法連入工作目錄 localhost，因此未取得這輪手機／桌面真瀏覽器截圖。元件測試、型別與 lint 結果另於 PR 列出；正式發布仍須核對該次提交的遠端 CI、必要 App 審查與部署狀態。
