# 搜尋與導覽接續

本輪從 `main` 的 `b1f38039c731f869dae1452da8e14d37153d879f` 延續介面品質與角色流程。主要情境是「說出想做的事、找到服務、進入後返回」，以及手機上切換校園、開啟帳號選單。

## 使用者看到的改變

| 情境           | 改變後的行為                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 快速搜尋       | 有明確的「查看結果」按鈕，Enter 把鍵盤焦點帶到本地結果；AI 理解、公開查課與助理交接仍有各自清楚的動作。                              |
| 中文輸入       | 組字的 Enter 用於選字；完整服務搜尋在組字完成後才更新網址，晚到的路由同步不蓋掉正在輸入的內容。                                      |
| 清除與重新輸入 | 清除搜尋保留所選分類；快速入口的重新輸入清掉返回草稿並回到輸入框。助理面板的 Escape 保留關閉面板、留住草稿的行為。                   |
| 返回搜尋       | 進入服務後返回、前進與重新整理能延續原查詢與分類；回到空的歷史項目時，空目錄優先於舊草稿。                                           |
| 搜尋畫面       | 輸入、分類、AI 動作及結果具有固定層級；服務名稱、用途與存取提示使用一致排版，窄畫面讓動作另列。                                      |
| 語音失敗       | 錯誤文字位於搜尋列下方，輸入框仍可使用；資料使用說明可展開閱讀。完成的分析或本地搜尋以簡短狀態宣告，不逐張朗讀整份清單。             |
| 選校與帳號     | 浮層依實際頁首位置安排，避開手機底欄；選校使用單一捲動區，短視窗也能走到搜尋、選校與關閉。                                           |
| 字級與動效     | 搜尋入口、結果與選校跟隨站內字級偏好；結果只在出現時短暫進場，打字不反覆重播。系統與站內減少動態皆關閉位移，強制色彩保留邊界和焦點。 |

## 實作判斷

服務搜尋主要是在找入口。Enter 不應突然解讀成傳送給模型或開啟第一筆；因此先明確顯示並聚焦結果，其他動作沿用自己的按鈕。既有 `useCampusFinderAccount` 與 `useCampusFinderDraftScope` 持續決定學校帳號、Google 帳號、未登入與校園切換的草稿和助理邊界。

搜尋網址使用原生 History API 與 Next 同步，寫入 `null` 讓 Next 複製自己的路由狀態；不把 Next 私有 history state 當作外部輸入傳回。以目前瀏覽器網址是否仍是最後公布的搜尋區分延遲回應和真正導覽，不使用有限長度的待同步佇列。歷史返回也同步空搜尋紀錄，避免重新整理後恢復已離開的查詢。

浮層位置同時在頁首／父容器尺寸變化、視窗變化、捲動及原生 disclosure 開啟時更新。面板沿用非 modal 行為、互斥開啟及關閉後的焦點恢復。

## 驗證方式

- 元件行為：搜尋與中文組字、歷史同步、Quick 的明確提交與重新輸入、雙實例 label、帳號／校園切換、公開課程查詢、頁首與選校、語音錯誤。
- `scripts/qa/interface-design/`：實際產品元件和 CSS，資料與路由使用明示的合成邊界；新增 Quick 搜尋／語音錯誤、大字、手機短窗的選校與帳號鍵盤遍歷。畫面及來源 SHA-256 隨工作流保存。
- `scripts/campus-visual-smoke.py`：在 production Next 建置上走完整搜尋與返回，補足合成路由不能證明的真實歷史行為。
- Web TypeScript、變更 ESLint、UI design gate、production build 與差異格式檢查。精確結果以該提交的 PR 和 Actions 為準，舊提交的綠燈不取代新版本。

本機 Chromium 的啟動遭執行環境 socket 限制，雲端瀏覽器也無法連線至本機預覽；因此實際瀏覽器驗收交由儲存庫既有的 GitHub Actions 執行。合成資料、Chromium 手機視窗和 DOM 組字事件，不等於真實帳號、iPhone Safari 或作業系統輸入法驗收。main 既有的指定 GitHub App「審查通過」仍是合併條件。

## 設計參考

- [Apple — Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/)：清楚層級、一致操作、保留脈絡與不同輸入方式。
- [Apple — Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：短而有目的的回饋，動效可停用，操作不等待動畫。

實作使用 nuni 原有灰綠品牌、系統字體和深色主題；這些原則用來判斷操作品質。
