# 成績核對與個人學分規劃

手機入口：學分總覽 → 從成績核對已修學分。Web 入口：學分規劃 → 從成績核對並帶入已修學分（`/credit-planner/review`）。共用流程：選核對標準 → 選列與分類 → 預覽差異 → 明確確認 → 查看更新後的規劃。

## 來源與資料邊界

手機沿用 `loadCreditRecords` 的登入與學校範圍驗證。Web 沿用 `AcademicPage` 與 `loadAcademicRecords` 的正式校務讀取，目前官方 adapter 僅支援靜宜；其他校園不會顯示靜宜紀錄或提供錯誤入口。本次沒有增加新的跨校自動登入服務。

原始成績、手動選取及核對內容僅在畫面記憶體；只有確認後的合計寫入既有帳號＋校園隔離的本機規劃。Web／App 都使用 `creditTranscriptReview` 共用核心。原有 JSON 備份格式維持不變，沒有雲端自動同步。

使用者必須選擇 60 或 70 的參考及格分數，不是自動判定其學制。未知等第、未評分、零學分與矛盾的通過證據不自動計入。校共同必修等未明確配對的來源分類先放「其他」，由使用者核對。P／通過等來源明示標記可供核對，並不代表畢業正式採計。

一鍵選取只包含校務來源、明確通過、無同名／同課號疑義的列，不自動選取課程工作區評分。重複群組採保守處理，每組只能選一筆；同名不同課及可重複採計的特殊課程需另行以正式資料核對，不能宣稱已精確識別各校重修規則。Web 原成績契約沒有課號時不捏造課號，只能用名稱提示疑義。

## 套用流程

預覽列出總額與四類別更新前後。這是「取代」而不是將合計加到舊數字；資料不完整時應返回，不可把欠缺的抵免或其他學期資料當成零。與未來規劃同名的課程須逐筆選擇移除已修規劃或保留不同課程，沒有自動刪除。原畢業目標、類別目標與非學分條件保留。

手機寫入在同一個本機 scope 的既有佇列中重新讀取原規劃並比對預覽基準，規劃變更或 session 過期就拒絕；Web 以同步比較／寫入及 storage 事件拒絕已知的分頁變更。這是本機協調，不是雲端跨裝置交易或對所有不合作分頁的絕對鎖定。只有成功回執才顯示完成。
