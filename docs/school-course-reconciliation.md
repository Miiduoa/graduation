# 校方課表與 WOW Class 對照

## 操作與來源

WOW Class 課程頁上方的「核對校方課表」獨立讀取本人的 e 校園課表。即使 WOW Class 還在載入、更新或重試，也能先查看校方選課學期、學分小計、逐門學分、班別、修別、教師與原始上課時間、地點。

WOW Class 回應後，以目前快照重新計算對應課堂，不再重抓 e 校園。切換進行中／已結束／未開始，保留校方資料與校方搜尋；LMS 等待或失敗時移除配對連結，保留校方來源及原讀取時間。這不是兩個系統同時取得的交易，也不是背景同步。

只有按下核對才讀取 e 校園；搜尋、待核對篩選與展開在裝置完成。兩個來源都失敗時，不顯示零學分或假造空清單。沒有新增模型、付費 API、依賴、帳密儲存或學校寫入操作。

## 配對與帳號界線

同學期、完整課號且兩側唯一時才配對。不靠課名相似度、任意四碼截取或西元 Fall 推測；同門多時段合併展示，不同班別保留。學分矛盾顯示待核對，未知小計不由 LMS 推算。零學分與小數保留。選課學分不是已通過、抵免或畢業採計學分。

校務讀取工作區以 uid／schoolId 隔離；帳號切換、A→B→A、離頁仍撤銷舊請求採用資格。取消訊號不宣稱取消學校已收到的請求。LMS 快照不再控制校務工作區生命週期，配對結果改為從目前 LMS 與已驗證校務快照推導，不儲存舊配對。LMS owner／來源／格式錯誤時，明確告警並只顯示已驗證的校方資料。

結果只留畫面記憶體，不寫 localStorage 或個人匯入。課堂連結由正整數 ID 建立於固定校方網域。

## 課堂來源完整性

備援 `/api/users/{id}/courses` 的 fields 補上 semester，避免請求本身排除配對必要欄位。這只修正客戶端請求；真實校方版本是否提供該欄位仍須登入驗收，不以模擬資料宣稱實際支援。

主要及備援端點共用分頁驗證：一旦出現總頁數，後續缺欄位仍讀到原宣告終點；中途或宣告末頁為空、頁數改變、頂層與 paging 宣告矛盾、晚出現的頁數小於目前頁碼，整次失敗而不是回傳部分清單。保留第一頁合法空資料、無頁數滿頁續讀、重複 ID 拒絕、20 頁上限、每頁 50 筆、25 秒整體期限及單回應 2 MiB 限制。沒有擴大讀取到其他人的課程。

## 測試與發布

核心 31 項、元件 23 項、新增課堂頁雙來源整合 6 項，以及後端分頁／學期 18 項。原課堂頁 9 項及既有 scraper 測試保留不變。三項舊 LMS 切換測試改驗新需求：保留校務來源，但當前課堂 ID 必須正確、更新期間不得沿用舊配對。帳號切換和離頁防護沒有放寬。

本機以同一份新增後端測試注入 Node test runner，舊來源 6 通過／12 失敗，修正後 18 通過／0 失敗。此獨立執行不等於完整 Jest／Vitest／Lint／型別／建置。完整結果以本次提交的 GitHub Checks 和工作日誌為準，不沿用舊提交綠燈。
