## 期限來源與逐筆行為

`fly-migrate.mjs` 的 `spawnSync` 未設定 timeout；固定候選內的 `migrate.js` 也沒有整體 60 秒計時器。60 秒來自本手冊的 `fly machine wait --wait-timeout 60s` 與「逾時停止本次 machine」規則。`DATABASE_STATEMENT_TIMEOUT_MS=60000` 則是單條 SQL 上限，兩者不同。

已直接讀取固定候選的 `/app/apps/api/dist/migrate.js` 及其引用的 `chunk-4S45VAVE.js`。每筆既有 migration 先在記憶體算 SQL SHA256，再依序執行七次查詢往返：BEGIN、SET TRANSACTION ISOLATION LEVEL READ COMMITTED、交易內 search_path、`pg_advisory_xact_lock`、CREATE TABLE IF NOT EXISTS 控制表、依 ID 查 checksum、COMMIT。checksum 不符即拋錯並 ROLLBACK；符合時不重跑業務 SQL。缺少的 migration 才在該交易內執行 SQL 並登記。無追蹤上下文時沒有額外 traceparent 查詢；verifier 對同一 client 首次 BEGIN 另查一次 pg_settings。
