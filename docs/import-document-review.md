# 文件匯入：標題建議與來源對照

## 使用流程

Web 的 PDF／Excel 文件準備頁現在會以既有解析器的欄名對照表，尋找符合本次
匯入類型的唯一完整標題列。只有一個候選、且後面仍有內容時才預設採用。
重複標題、重複欄位或不完整欄名不猜選；復原草稿的手動標題與空選取也不覆蓋。
這是本機結構判斷，不是新的 AI 模型或辨識信心分數。

選取工作表／頁面後，可同時對照原始表格與實際解析結果。原始列號、未對應欄位、
標題前被排除的內容都能查看。預覽取前六筆整理結果；原始表格可繼續展開，
並不因此截斷真正交給下一步的資料。桌機並排，窄螢幕上下排列，寬表格僅在自身
容器橫向捲動；主頁不需左右滑動。

可全選可讀取內容或取消全選，輸出仍依文件原始順序，不依勾選先後。欄位錯誤
仍列為待修正草稿，下一步可以編輯；選到無法解析／沒有資料的範圍時，會阻止
只整理其餘部分。每次五百筆上限是所有選取範圍合計，沒有放寬。

普通整理不下載模型、不呼叫 AI，也不自動確認儲存。原有 AI 操作保持明確點選，
可在普通解析無法處理時使用；來源與已選內容仍由現有匯入中心管理。

## 實作邊界

- `documentReview.ts` 共用既有欄名對照、文件驗證與正式解析器，未另寫欄位解析規則。
- 提示標題僅限可明確判斷的欄名；不是 OCR 錯字修復或任意表格的語意理解。
- 預覽不證明來源檔內容正確，也不增加學校登入或連線權限。
- 手機 App 的原生文件準備頁未在本輪改版；此畫面是可在手機瀏覽器使用的 Web 頁面。
- 未改模型、依賴、資料儲存、後端、安全規則或部署流程。

## 驗證

純函式測試使用實際 shared 解析器，涵蓋候選標題、歧義、原始行號與順序、缺值、
校園不符、重複資料、無法解析的範圍及合計筆數上限。
元件測試涵蓋手動設定保留、來源／結果預覽、明確確認、取消、全選、不可讀頁面、
AI 退路與文字安全顯示。完整互動與專案檢查以這次提交的 Vitest／CI 結果為準。

本機版面檢查使用實際元件的 React server-rendered HTML 與合成資料，透過 Chromium
檢查桌機、手機寬度、深色樣式與原生 details 展開；它不是已部署網站、hydrated React
互動或真實模型驗收。沒有用這些檢查宣稱辨識準確率、真機效能或勝過競品。
