# 成績核對與個人學分規劃

入口：原生 App 學分總覽 → 從成績核對已修學分 → 選取核對標準 → 核對來源、重修與分類 → 預覽差異 → 確認套用 → 查看更新後的規劃。

## 本次接通

沿用 `loadCreditRecords` 已有的登入與學校範圍驗證，不增加另一組校務登入或拿使用者輸入的學校 ID 充當資料來源。原始成績、手動選取及核對內容僅在畫面記憶體，只有確認後的合計寫入既有帳號＋校園隔離的本機規劃。Web 備份格式維持原樣。

使用者必須選擇 60 或 70 的參考及格分數；這不是自動判定其學制。未知等第、未評分、零學分與矛盾的通過證據不自動計入。校共同必修等未明確配對的來源分類先放「其他」，由使用者核對。P／通過等來源明示標記可供核對，並不代表畢業正式採計。

一鍵選取只包含校務來源、明確通過、無同名／同課號疑義的列，不自動選取課程工作區評分。重複群組採保守處理，每組只能選一筆；同名不同課及可重複採計的特殊課程需另行以正式資料核對，不能宣稱已精確識別各校重修規則。

套用預覽列出總額與四類別更新前後。這是「取代」而不是將合計加到舊數字；資料不完整時應返回，不可把欠缺的抵免或其他學期資料當成零。與未來規劃同名的課程須逐筆選擇移除已修規劃或保留不同課程，沒有自動刪除。原畢業目標、類別目標與非學分條件保留。

寫入在同一個本機 scope 的既有佇列中重新讀取原規劃並比對預覽基準，規劃變更或 session 過期就拒絕。處理期間互斥、重複確認不連續覆寫，寫入失敗保留核對內容。這是單一 App JavaScript 執行環境中的協調，不是雲端資料庫跨裝置交易。回傳成功後仍須點「查看更新後的學分規劃」，用新的路由實例讀取保存結果。

## 驗證邊界

本機已執行純核心 Node 檢查 14 組，涵蓋門檻、零分、未知成績、分類、重複群組、小數、來源不變性及未來重複課程處理；此結果不等於完整 Jest 或型別檢查。新增核心、repository 與 React Native 畫面測試均須以此 PR 的最新 SHA 在 CI 的實際報告為準。

待驗收：真實授權學校帳號的成績來源完整度、iOS／Android 觸控、鍵盤、大字體與讀屏、離線舊副本提示。本流程沒有新增四校自動登入、官方畢業規則、雲端自動同步、課程先修安排或 Web 核對畫面。
