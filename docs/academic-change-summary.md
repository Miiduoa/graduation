# 校務更新差異摘要

## 範圍

以已合併 PR #287 的 main `52ed309c8b2c815fc1803d6032e8483d81d79646` 為基礎，接入 Web 共用 AcademicPage。成績頁與學分規劃的校務資料區使用既有已驗證 snapshot 比較前後成功讀取，不額外發送請求、不修改登入或自動更新同意設定。

比較核心另支援課表時間、教室、教師與學分；本次未接入 PersonalTimetable 或原生 App。仍只使用既有靜宜校務來源，不代表新增其他學校直連、背景同步或推播。

## 配對與資料完整性

- 原有資料 ID 可能包含分數或教室等可變欄位，因此不用 ID 判定課程身分。
- 成績用學期、課名、班別；課表用學期、課號、班別，缺課號才改用課名。
- 同名重複科目或同課多時段無法唯一配對時只標示需核對，不猜測修改前後值。
- 零分、文字成績保留；90 與 090.00 不當作變更。
- 未回傳只表示本次來源沒有該筆資料，不代表退選或刪除；整批空回應不製造大量刪除通知。
- 帳號、校園或課表學期改變會建立新基準；超過 5,000 筆、時間未前進或無效時間不產生變更通知。
- UI 的「兩次讀取時間」是 snapshot.fetchedAt，不是學校的修改或公告時間。

## 隱私與生命週期

基準只在頁面記憶體，不寫入瀏覽器持久儲存、不傳送至其他服務、不覆蓋個人匯入。離頁、登出、帳號／校園切換即丟棄；更新中或失敗時隱藏舊摘要。暫時失敗可保留上次成功基準，授權失效、權限不足或服務未設定則清除。晚到的舊請求不得在新頁面顯示。

初始最多顯示 8 組差異，再按每次 20 組展開；沒有靜默截斷。沿用既有主題與深色模式，長字可換行，操作按鈕至少 44px。

## 驗證

新增 44 個案例：核心 25、元件 12、頁面整合 7。頁面測試使用實際 hook 與排程控制器，只 mock 校務資料讀取與外部頁面相依項。

本機已執行核心 25 個案例並通過（只將 Vitest runner 換為 node:test，斷言與業務邏輯不變），以及使用來源介面的獨立 strict 型別檢查。全專案 Vitest、ESLint、型別檢查與 build 必須以本 PR 對應 commit 的 CI 為準，不沿用上一個 PR 的結果。真實校務帳密登入、手機瀏覽器視覺及無障礙實測尚未完成。
