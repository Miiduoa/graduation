# 手機校園導航確認流程

手機「校園助理」預設開啟校園導航。輸入起點與終點後，先預覽本次文字、校園代碼、公開地點的候選編號、名稱、分類與別名，以及查詢時間和來源更新時間。勾選同意並按下「確認規劃」，才會把這些內容交給 Groq。

這個入口沿用 [校園導航任務](free-cloud-navigation.md) 的伺服器契約與啟用條件。未設定合法雲端服務時只能預覽，不會轉用其他供應商或本機模型。程式沒有配置金鑰、啟用計費或驗證真實帳戶的免費額度。

## 同意與結果

- 每次預覽都要重新同意；修改輸入、取消、離開頁面、換帳號、切校園或登入失效，會清除同意與結果並忽略晚到回覆。取消只能停止本頁等待，已送出的 Callable 不一定能立即中止。
- 同一份計畫重試沿用請求 ID；重複點擊不會在本頁同時送出兩次。配額失敗顯示重試時間，不自動重試或切換供應商。
- 手機 client 核對供應商、模型、校園、時間格式與回執，拒絕任意工具、動作、跨校地點、無效座標或非預期網址。取得有效導航建議後，仍須按「開啟校園地圖」才會進入既有 `MapV2`，不直接外開網址。
- 不會附加帳號識別碼、課表、作業、私人摘要、歷史對話或座標給模型。使用者自行填入的文字仍需在送出前核對，這不是自動去識別化保證。

導航同意只限這次公開地點判讀，不授權作業提交、付款、訊息、資料寫入或 Python 執行。這個入口不顯示寫入提案，也不呼叫寫入確認服務。

## 已存資料

「已存資料」保留既有課表查詢、資料摘要、作業提醒與服務入口。此頁使用 `tools-only`：以既有規則查詢資料，無法處理時明確說明，不啟動模型、下載或本機推論。其他尚未改造的模型入口不在本次範圍內。

舊 `askCampusAssistant({ mode: 'campus', messages, context })` 請求會在處理私人內容及呼叫 Callable 前拒絕，避免繞過預覽同意。新版公開導航使用獨立 client。

## 整合與驗收

此變更依賴 PR #399 的 `public-campus-navigation` Callable 契約。合併後須在當時的 main 重新套用並驗證，不能將本機結果當成新提交的遠端 CI 成功。

測試僅使用合成公開地點、模擬 Callable、帳號及導覽狀態。瀏覽器以 React Native Web 執行實際元件與 client，不能取代 Android／iOS 真機、原生鍵盤、讀屏或正式雲端驗收。既有 Python 路徑、其他語意入口與背景作業不在本次確認流程的涵蓋範圍。
