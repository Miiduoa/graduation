# 校方課表與 WOW Class 對照

## 操作流程

開啟 Web 的 WOW Class 課程頁，按「核對校方課表」。使用目前登入的本人來源讀取 e 校園課表，顯示學期、校方選課學分小計、逐門學分、修別、班別、教師與原始上課地點。能唯一核對的課程可直接開啟 WOW Class 課堂。

WOW Class 讀取失敗時仍保留校方課表入口；以缺少 LMS 來源的狀態展示，不將失敗轉成成功的空清單。e 校園讀取失敗也不隱藏已取得的 WOW Class 課堂。

這是兩個既有授權來源的前端整合，不是新的學校登入連接器。核對由使用者主動觸發；搜尋、待核對篩選與分批展開不額外讀取學校，也不再次提交密碼。沒有新增外部模型、付費 API 或套件。

## 資料界線

- 學分、班別、修別與時間來源為 e 校園；課堂識別來源為 WOW Class。保留兩份讀取時間，不聲稱兩個系統是在同一交易內取得。
- 同學期、完整課號，且兩側均有唯一候選時才建立對應。只正規化全半形、課號字母大小寫與明確民國學期格式。不切出任意四碼，不靠課名相似度，也不將西元 Fall 學期猜成民國學期。
- 同一課程不同時段合併展示；不同班別、課名或修別保留成不同課程。學分矛盾時顯示待核對，不選第一筆或加總。
- 校方選課學分小計未提供就保持未知；零學分和小數學分保留。這不是已通過學分、抵免學分或畢業審核。
- 未對上的課程不判成未選課；目前 WOW Class 狀態可能不包含它。兩份清單的其他課堂仍可查看，不能偷偷納入選課學分。
- 只有合法正整數課堂識別才能建立固定校方網域的連結，不採用來源提供的任意網址。

## 帳號與畫面

核對前沿用 loadAcademicRecords 的 token、校籍與來源驗證，核心再次檢查 owner、校園與來源。結果只保留在這次畫面記憶體，不寫 localStorage、校方資料或個人匯入。帳號切換重新建立工作區，更新來源、切換狀態與離頁會淘汰舊回應。重複點擊不重複讀取。重新核對失敗不繼續呈現舊成功狀態。

介面沿用現有主題變數、單欄手機布局、鍵盤焦點與至少 44px 控制項；使用文字標示狀態，不只靠顏色。課程和未配對課堂分批展示，仍能展開完整清單。

## 驗證

新增核心測試 31 項、React 畫面測試 15 項。核心已以 strict TypeScript 編譯，再將同一測試檔的測試執行器匯入從 Vitest 換成 Node test，在本機執行 31/31 通過。這個數字不是完整 Vitest、React 或專案 CI 的結果。修改的 TypeScript/TSX 語法轉譯未產生診斷。

完整 Web Vitest、lint/typecheck、建置、安全掃描與原生相鄰流程以本次提交的 GitHub Checks 為準。沒有降低既有檢查門檻。校方真實帳號、兩份實際課號格式、Safari/Chrome 實際操作與正式環境網路可達性仍需驗收。

本次僅修改 Web 介面及新增純讀取核對邏輯；沒有改動 Mobile、後端權限、資料庫、部署設定或啟用登入開關。未部署正式服務。
