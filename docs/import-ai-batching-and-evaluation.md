# 匯入：手機長表格與可重現的辨識評測

## 手機長表格

本機文字 AI 的一次操作最多接受 8,000 字元。每次原生推論仍只接收最多
1,000 個來源與欄位參考字元，另外加上既有固定提示；沒有放寬模型 context 或
輸出 token 上限，也沒有改成雲端 API。

僅在完整矩形 TSV 資料列，或以空白行分開的完整段落之間切分。每段最多八個
資料單位，單次操作最多十六段、八十筆輸出。超長、跨行引號儲存格或無法確定
邊界的段落會要求改用原始表格或手動分段，不直接把一筆紀錄切成兩半。
短於單次字元上限的原文維持原有單段路徑。

工作表名稱與辨認出的欄名可以作為後續段落的解讀參考；它們不是新增的來源
證據。每段 `SOURCE_DATA` 都是連續原文，輸出的來源行號還原為整份輸入的位置。
在 PDF／Excel 路徑中，行號是「所選內容整理出的文字」行號，不冒稱原 PDF
印刷行號。每筆仍必須通過既有來源與欄位驗證，並由使用者核對。

`runMobilePersonalImportAi` 依序呼叫已啟用的 Qwen2.5 模型，透過既有 availability
訂閱顯示第幾段。直到全部段落完成才回傳一份草稿；中途失敗不把前幾段當作
整份成功。取消與逾時會要求停止原生工作，原生 Promise 真正結束前仍保留互斥鎖，
不啟動後續段落或接受晚到的結果。切換模型會使整次結果失效。

這是長文字整理，不是手機原生圖片視覺推論。沒有新增學校登入、權限、下載模型、
上傳來源或自動儲存。完整分段送入模型也不能保證模型沒有漏列紀錄。

## 辨識評測工具

使用分開的人工標註與辨識輸出檔案，不從模型輸出反過來產生答案。

```sh
node --test scripts/import-ai/evaluate.test.mjs
node scripts/import-ai/evaluate.mjs gold.json predictions.json
```

最小人工標註格式（以下為合成範例，不是真實準確率資料）：

```json
{
  "schemaVersion": 1,
  "datasetType": "synthetic",
  "cases": [{
    "id": "week-a",
    "kind": "timetable",
    "rows": [{ "title": "資料庫", "dayOfWeek": 1, "startPeriod": 3, "endPeriod": 4 }]
  }]
}
```

辨識輸出必須明示成功或失敗：

```json
{
  "schemaVersion": 1,
  "cases": [{
    "id": "week-a",
    "status": "ok",
    "rows": [{ "title": "資料庫", "dayOfWeek": 1, "startPeriod": 3, "endPeriod": 5 }]
  }]
}
```

成功時可使用來源驗證後、人工修改前的匯入 rows；不要混用原始模型 JSON 與已修正
的資料。失敗使用 `status: "failed", rows: []`，未提供的案例算 missing，不能從
分母消失。`datasetType: "real"` 是標註者聲明，不是工具自動證明其代表性。

### 判讀

- 完整紀錄精確率／召回率使用多重集合比對：順序不同不扣分，重複輸出不會增加
  召回率，同名不同星期的課程不合併。成績零分與零學分不會被當作缺值。
- 先取出完全相同的紀錄；剩餘同名紀錄只有一對一時，才列出星期、節次等差異欄位。
  多個同名時段無法唯一配對時會列為 ambiguous，不挑最有利的配對來灌高成績。
- 空分母回傳 null，不回傳 100%。`complete` 只表示案例都交付了 ok 結果，不表示
  辨識正確。整份失敗仍計入 failedCases 與召回率分母。

標準欄位因類型而不同：課表比對課名、課號、學年學期、教師、教室、星期與原始
節次／時間；成績比對課名、課號、學年學期、學分與成績；活動比對名稱、地點、
完整起訖日期、時間與全天旗標。僅正規化全半形、頭尾及連續空白；數字與數字字串
不同，缺值不推算。欄位轉換必須在評測前採用固定且一致的規則。

### 真實驗收

同一份未參與調整的資料，同時測現有匯入、AI 匯入與競品。人工標註需涵蓋至少
橫式週格、跨節課程、同名多時段、無課號、零學分、跨日活動及模糊／裁切來源。
每個案例固定學校節次設定與輸出規格，另記錄冷啟動下載、暖啟動耗時、峰值記憶體、
手動修正次數及取消後資料是否保留。不得只挑成功案例；不能以程式測試數量替代
真實辨識正確率。

工具不連網、不自動修改或上傳檔案；結果寫到標準輸出。個人成績單、帳密、姓名
與真實截圖不要提交到公開 repository。沒有真實裝置與同樣本競品結果前，不據此
宣稱全面勝出。合成測試只驗證工具如何計分。
