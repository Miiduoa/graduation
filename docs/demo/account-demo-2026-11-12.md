# 帳號展示資料與學生證

## 這次處理的問題

Google 平台帳號已有登入身分，但數位學生證只讀 Firebase 校園身分；既有口試工作區又只存在裝置上，沒有連到指定帳號。結果是登入後課程資料不足、學生證無法展示，展示進度也不能跟著帳號保存。

本次新增帳號專屬的展示配置，並把合成課程資料放進既有的平台課班與個人匯入資料層。runtime 以已驗證的 platform account ID 查資料，程式沒有信箱白名單或前端管理員捷徑。

## 介面與操作

- `/demo/account`：登入本人帳號後讀取展示資料，管理 12 個展示功能及保存情境進度。
- 設定頁：只有取得本人有效展示配置時，才顯示展示工作區入口。
- `/student-card?campus=pu`：Google 平台帳號可查看本人展示卡、暫時出示 DEMO 學號及 60 秒展示 QR。
- 課程資料使用原本 `/classroom` 的讀寫與成員權限。
- 課表、行程、成績使用原本的 personal-imports 同步引擎。首次使用裝置需在展示頁按「同步我的課表與行程」，既有資料有衝突時先核對，不自動覆寫。

工作區的訂餐、請假、報修、社群與訊息動作只更新本人合成展示紀錄，不產生正式交易或對外通知。正式校籍 QR、校方服務與真正的 AI 代辦權限仍使用其原有授權；本次沒有變更 Firebase 規則或開啟萬用開發帳號。

## 帳號與資料保護

`/api/nuni/account-demo` 每次重新核對上游 session principal，只讀寫該 account ID。Web 使用 cookie/context，App 使用 Platform bearer。關閉、過期或停權的配置不可執行。更新使用 revision CAS，核對資料庫回傳與再次讀取的相同結果才回報成功；遇到競態或不明結果需重新讀取。

`nuni_account_demos` 開啟 RLS。既有 Web runtime 只能讀取可用展示列、更新 permissions/state/revision/updated_at；不能建立或刪除配置，也不能更改帳號、profile、啟用狀態或到期日。用來序列化帳號停權的 row lock 只追加 `platform_accounts.updated_at` 的欄位權限。帳號真正刪除時，展示配置以外鍵 cascade 清除。

學生證會在切換帳號、session、學校、離頁或到期後清除出示內容。展示 QR 使用獨立前綴，不會成為校方驗證 token，也不會呼叫 NFC 門禁。

SQL 測試使用真正的 PostgreSQL engine（PGlite），並以非 superuser、無 BYPASSRLS 的 runtime 角色核對欄位 ACL、RLS、CAS、停權與到期。它不是正式環境 UI 驗收；正式資料寫入另由上述讀回紀錄確認。

獨立審閱指出的兩個前端問題已修正並補測試：資格到期時取消同步 checkpoint；成功回執必須包含本次預期權限／狀態及相符版本，不能只因版本增加而宣稱完成。

畫面另完成淺色／深色樣式靜態檢查，修正深色品牌底上的文字對比。隔離 Chromium 因執行環境禁止建立 socket 而未能啟動，未取得瀏覽器截圖；不能將元件測試視為正式帳號或實機畫面驗收。
