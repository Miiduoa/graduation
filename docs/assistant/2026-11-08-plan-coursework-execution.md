# 從讀書計畫接續作業準備行程

## 要完成的學生任務

手機助理的「整理今日重點」與「規劃未來七天」已能整理 nuni 課業。本輪讓即時計畫中的作業可以直接接續找準備時間，不必先離開計畫、找下一堂課，再重新查一次作業。

使用者在即時計畫或逐日安排中，按「安排『作業名稱』的準備時間」。助理先重新核對精確作業來源，再以原有流程尋找三十分鐘候選。選定時段後顯示完整來源與行程預覽，最後由使用者按「確認建立準備行程」，保存並讀回同一筆個人行程。

「查看這份作業」仍保留。測驗只有原本的精確查看入口；本輪的準備行程橋接限作業。

## 來源與執行邊界

- 計畫的 `nuniSource` 只定位帳號、學校、學期、課程及作業，不能授予讀取或寫入權限。
- 重新檢查這台手機目前保存的課程連結、真實課堂時段與伺服器授權；使用既有的精確目標讀取與課堂作業讀取器產生新的 `CourseworkRead`。
- 沒有近期可核對的課堂時段時，保留查看原作業入口，不捏造課堂 anchor。
- 不解析 `step.detail` 的時間文字，不採用計畫顯示的空堂作為可寫入時段；仍重新核對個人行程與緩衝時間。
- 同名作業按原課程／作業 ID 核對；來源不足、重複 ID、來源上限或課程連結變動，不能改選另一份作業。
- 新的作業來源查詢沿用有限等待與停止機制；換帳號、換學校、離開畫面或撤銷計畫資料後，晚到結果不得繼續接成可操作草稿。
- 已保存計畫是歷史副本，仍移除即時 `nuniSource`。必須重新整理取得目前來源，才能進入這條流程。
- 實際寫入沿用既有作業來源確認、最新空堂重查、操作紀錄、衝突檢查、讀回回執與原 ID 恢復，不新增另一套行程寫入器。

## 模型歷史隔離

來源式計畫及其前一個使用者問題保留在畫面，但從之後一般模型的歷史輸入中排除。這個過濾涵蓋本機工具選擇、一般本機回答及雲端 callable，正常對話與目前的新問題仍保留。

這是共用模型輸入邊界的修補，不代表平台帳號的每一個既有畫面路徑都會呼叫模型。作業準備與計畫來源查詢本身仍走確定性的資料流程。
