# 依工作情境設計的 Agent 與跨功能任務

## 產品定位

一個人可能同時是修課學生、某門課的教師、社團幹部或門市工作人員。Agent 共用任務解析、來源讀取、簽章確認、冪等寫入、讀回與失敗續接；工作情境決定建議問題和資訊呈現，實際操作資格仍逐一由原課程、門市或管理服務核對。

| 工作情境 | 本輪提供的定位 | 實際執行範圍 |
| --- | --- | --- |
| 學生與個人 | 課業與校園生活安排 | 沿用本人課表、待辦、教材、個人行程與校園來源。 |
| 教師 | 授課與備課助理 | 新增本人已核對校園的負責授課概況，可搭配公開活動、聯絡資訊及明確個人行程。 |
| 店家 | 門市營運助理 | 新增授權門市、目前訂單狀態與當班摘要，可搭配校園來源。 |
| 社團幹部 | 社團與活動工作 | 沿用社團與公開活動讀取；成員管理、發布仍由原工作區辦理。 |
| 校務與課務 | 校園資訊與承辦入口 | 查公告和聯絡資訊；假單與申訴核閱仍由原服務確認指派資格。 |
| 平台管理 | 服務資訊與管理入口 | 查公開服務資訊；管理操作沿用原工作區。 |

選擇工作情境不會新增角色、改變帳號、擴張學校範圍或送出 API 請求。所有情境共用原 Conversation，保留草稿、歷史、尚未確認與結果未知的卡片。範例按鈕只填入問題，原草稿可復原。首頁沿用既有 `teacherOnly` 判定提供教師預設，不增加身分查詢；手動選擇不會被後續 preference 更新覆蓋。

本版包含相依分支的職涯服務後，能力目錄為 **46 項：19 項具資料讀取，其中 5 項可準備待確認操作；27 項維持入口**。prepare 已包含於 read，這不是 46 項皆能自動執行。共用角色定義可供其他客戶端使用，本輪新增的角色助理互動主要在 Web／手機瀏覽器；不宣稱原生 App 已接上相同新 reader。

## 教師授課來源

`get_teaching_overview` 使用已驗證的 Platform 帳號及原 `class-workspaces`、`course-access` 來源。先列出本人工作區，僅對 active／owner-teacher 候選取得既有的校園核對回執，再讀作業與測驗，最後重新核對同一課程版本與角色。

- 不變更學生 `mySubmission`／`myResponse` 的原判定，也不把教師當學生讀待繳資料。
- 顯示課程、作業／測驗標題、開放狀態、截止時間與收到的份數；**收到份數不等於待批改份數**。
- 不讀學生答案、個別學生名單、評分或批改內容；co-teacher 尚未納入這條已核對的 owner-teacher 能力，會保留資格未核對狀態。
- 每門課需四次來源請求，另有清單與 principal；沿用每題 12 次 API 上限並保留兩次後續額度。預設請求上限為三門，但在一般完整預算下最多可完成兩門完整來源核對，剩餘明確標為 partial。
- `unreadCourseCount` 是帳號清單內尚未完成校園核對／讀取的候選數量，不能解讀成目前學校尚有多少門課。

校園核對沿用既有 `course-access` POST 查詢介面，沒有新增教師資格、授權或課務業務寫入。跨校、撤權、校驗失敗、帳號改變與取消都不降級成成功空資料。

## 店家營運來源

`get_merchant_overview` 依序使用原授權端點：`merchant-workspaces`、`realms`、指定門市的 `orders` 與 `shift`，最多四個 GET，連同 principal 共五次。校別必須由來源明示或原受信任 realm 對照核對，不能從店名、校名或同名 tenant 推測。

- 唯一且已核對校園的門市可直接讀摘要；多門市或仍有未核對範圍時要求先到原工作區選擇，不任選第一間。
- 訂單僅投影目前取得頁面的各狀態筆數、總筆數及有無下一頁，並非營收或全日成交量。
- 當班分開呈現 open、明確未開班及來源不可用；只有原端點的 `FOOD_SHIFT_NOT_FOUND` 才算未開班。
- 不輸出顧客姓名、聯絡資料、備註、訂單品項、金額；不混用買家訂單來源。
- 接單、取消、退款與交班仍由既有門市介面處理，本工具只讀概況。

店家失敗續接使用版本 3 的簽章 proof，記錄原 tenant/location。重試先重讀當前授權與校園範圍，仍只讀原門市；新增其他門市不會改變目標，原店撤權則拒絕。帳號、登入、校園、對話、原始問句、任務圖、有效期限及原店必須吻合。版本 1／2 的既有續接維持相容，但不能用降版略過門市綁定。無法確定門市的初次結果不簽出可猜測目標的重試。

## 跨功能執行

以下明確語句由既有任務圖直接處理，不需要模型決定來源數字或工具順序：

| 問句 | 行為 |
| --- | --- |
| 查我的授課概況，查近期活動 | 分別顯示授課與公開活動來源，保留各自的部分資料或失敗狀態。 |
| 查我的授課概況，幫我新增行程明天15:00到16:00備課 | 讀授課資料並準備原簽章個人行程卡；使用者確認後才寫入並讀回。 |
| 查我的授課概況，幫我新增行程明天15:00到16:00寫教案 | 保留明確標題「寫教案」，不改成學生作業標題。 |
| 查我的門市營運概況，查學校電話 | 讀原門市摘要與目前校園官方聯絡資料，不改用買家訂單。 |
| 部分來源失敗後重試 | 只續接簽章中的失敗讀取，不重送已完成行程，也不產生替代原卡的新提議。 |

新增的 explicit event 節點只接受原 calendar parser 已能完整解析的日期、未來起訖與標題。它使用自己的子句準備卡片，摘要也取實際簽章卡片的值。已經有明確行程卡時不再顯示可能取代該卡的課務安排捷徑。公開貼文與活動的原來源選擇限制仍然生效。

角色資料只以已驗證投影呈現；模型取得來源／狀態／範圍提示，教師標題與店家自由文字不進模型摘要或後續模型歷史。混合未知要求的 fallback 不會因教師問句含「課」而預讀學生待辦。任一來源回報登入失效或 `SESSION_CHANGED`，包括非 401 狀態碼，整題中止，不回傳先前的私人部分結果。

## 驗證與相依關係

測試涵蓋純來源 parser、角色 reader、真正 `createAdapter` 的 Platform HTTP 路徑、跨功能 runner／確認／取消／冪等／讀回、簽章續接以及 UI 草稿和卡片保留。principal 再驗證開始時先清除舊快取，刷新失敗後不能沿用上一次帳號啟動新角色來源。

既有 Assistant Chromium harness 新增 `role-pending-390` 與 `role-unknown-390`：390px 真實選單與範例操作、零額外 API、原草稿可復原、卡片 DOM 不重建，未知結果仍能使用原 token 核對。沿用原幾何／溢出／焦點驗收，沒有放寬標準。這些測試使用合成資料，不是正式校園或門市的真人驗收。精確通過數及最新遠端結果記錄在本輪 PR。

本輪最初基於 #631 開發；工作期間發現擁有者已關閉該 PR 並刪除分支，因此不更新或重開它。獨立開發分支與仍開放的 #684（`852d1ecd72ac37f0ad8d430a4b77e86b41812531`）核對整合，保留其 task-first 入口、職涯能力相容與行程恢復。#684 的歷史本身包含 #631、#672、#682、#683；新 PR 的增量與相依部分分開說明，維持 Draft 待審，不把已關閉的 PR 視為獲准合併。

沒有新增套件、資料遷移、角色權限、部署開關或模型服務。正式合併及部署仍需最新版本的必要檢查與指定 App 審查證據。跨裝置長期任務、背景自動執行、教師批改、店家交易寫入及私人校務來源不在這輪已完成範圍。
