# 角色、工作流程與完成條件

更新：2026-11-18（Asia/Taipei）。本文件說明目前程式的入口與工作分工；部署版本及驗收結果以對應 PR、CI 與正式站 revision 為準。

## 共用入口，依工作內容分流

Web 採五個主要入口，App 的學校登入介面使用同一份[主要目的地](../packages/shared/src/primaryDestinations.ts)：**今天、課務、生活、交流、我的**。App 的訪客與 Google 公開登入另採任務入口，依資格進入公開資訊、Google 課班或店家工作，不宣稱共用學校登入的五分頁介面。角色改變內容與優先順序；同一人可同時修課、授課、協助社團與經營門市。

| 入口 | 使用者要完成的事 | 後續接續 |
| --- | --- | --- |
| 今天 | 看今天的課表與待辦，進入已授權的教學、門市或平台工作 | 直接開啟對應課程或工作台；Agent 的預覽、確認與未知結果留在原頁 |
| 課務 | 課表、課程與作業、成績、學分、個人行事曆 | 依原課程來源開啟教材、作業、測驗與回饋，不把不同帳號的課程互換 |
| 生活 | 交通、餐飲與住宿、圖書館、社團與職涯 | 查找後前往服務；返回保留搜尋與分類。免登入篩選仍可找到公開餐廳菜單 |
| 交流 | 公開與校內話題、好友與聊天、公告與通知 | Google 公開交流與學校帳號私訊分別確認資格；通知與私訊維持不同目的地 |
| 我的 | 本人資料、學生證、帳號連線、學校資格與設定 | 需要登入時回到原任務；填寫學號或個人資料不等於取得學籍或工作權限 |

「所有服務」是全站查找工具。預設先呈現每類常用項目，其他項目與子服務按需展開；搜尋仍涵蓋收合內容。名稱、分類、存取需求與開關以[服務目錄](../apps/web/src/lib/campusServices.ts)為準。

## 各角色的主要流程

入口是工作建議。是否能讀取或執行，仍由每個服務核對目前帳號、學校、課程、棟別或門市資格。

| 角色／工作情境 | 起點與主要任務 | 完成後的結果與接續 | 實際邊界 |
| --- | --- | --- | --- |
| 訪客 | 選擇瀏覽校園 → 公開公告、地圖、公車、活動、圖書館與職涯 | 正確校園的資訊與服務入口 | 私人課務、私訊及管理操作另行登入；不以選校取得權限 |
| 學生／Google 使用者 | 今天的課程待辦 → 對應作業 → 保留草稿 → 確認送出 → 查看回執 | 本人提交內容、時間與伺服器狀態；需要安排時交由 Agent 準備預覽 | Google 課班與學校／TronClass 來源分流；參考截止日不等同停止收件 |
| 教師／教授 | 授權課程 → 教材、作業、測驗、收件與回饋；App 教學工作台另接點名與成績簿 | 原課程的內容、操作回饋與下一件工作 | 依課程成員角色；負責老師與共同授課者能力不同，收件數不能冒稱未批改數 |
| 助教／教學協作者 | App「助教工作」→ 教學待辦 → 已加入課程；再回自己的課表與群組 | 該課程可處理的教學事項，以及本人課務入口 | 助教名稱不自動取得教師、成績公布或跨課程權限 |
| 社團幹部 | 社團與課務 → 已加入群組／社團 → 活動、介紹與既有成員工作 | 原社團的實際結果，再接續本人課務 | 公開社團目錄、群組與管理分開；未開通的入社或指派能力不由介面補造 |
| 店家申請人 | 同一 Google 帳號 → 進駐申請 → 查看原申請的待審、補件或結果 | 審核說明與下一步；未送出草稿保留 | 補件與待審不引導重複申請；核准但尚無門市指派時明示等待權限 |
| 店家負責人／店員 | 授權門市 → 開店準備；營運後先選值班門市 → 訂單、收款與取餐 | 目前門市與訂單的可信狀態；保留申請、菜單與收款草稿 | 平台門市與舊 App 餐廳來源分流；新申請需明確選擇，不取代日常營運 |
| 一般教職員／承辦 | 校務服務 → 已指派工作；其他需求由公告、校方窗口與生活服務接續 | 工作清單或可重試的讀取錯誤；沒有資格時提供服務出口 | `staff` 名稱不等於全部校務權限，個別服務按指派範圍核驗 |
| 宿舍輔導員 | 輔導員工作台 → 確認學校與負責棟別 → 報修、外宿、包裹 | 授權棟別的清單與處理進度；重新載入可查回 | 居民服務與職員工作分流；沒有輔導員資格可回宿舍服務，不新增角色指派入口 |
| 系所主管／校級主管 | 授權課程與教學協作 → 校方公告、聯絡窗口；案件依服務指派開啟 | 本範圍的工作與結果 | 職稱不授予全校私人作答或平台管理；現有 App 入口不是完整系所分析儀表板 |
| 校方管理員／公告編輯 | 確認本校資格 → 公告或活動管理 → 編輯確認 → 查回清單 | 同帳號、同校園的內容與更新結果 | 確認中、讀取失敗與無權限分開；切帳換校不沿用舊清單、草稿與晚到回應 |
| 平台管理員 | 平台工作台 → 待審學校、店家、資格或檢舉 → 核對對象與原因 → 處理紀錄 | API 確認的結果與管理紀錄 | 依平台 session 與每次 API 授權；不自動取得私人課程資格 |
| 校友 | 校園活動 → 公告與已開放交流 → 生活／帳號設定 | 公開資訊與本人仍可用服務 | 不保證畢業後的學校帳號仍可使用校內私訊與私人課務 |
| 家長 | 目前可使用訪客及本人帳號的公開功能 | 公開資訊與登入狀態 | **尚無可交付的家長綁定與子女資料流程。** 角色列舉／示範資料的 `parent` 不代表已有驗證關係、同意撤銷、授權讀取及家長工作台；不展示孩子成績或出席入口 |

Web「我的工作」依實際課程、門市及平台資格產生；沒有兼任工作的學生不增加空工作選單。純教師今日頁已顯示的授課課程不重複列出；兼修課與授課者保留兩種工作。App 的[角色工作流](../apps/mobile/src/services/roleWorkspaceFlow.ts)提供主要工作、接著處理與日常帳號入口。

教學與申訴是不同任務：`/classroom` 是 Google 課程，學校課程保留原 `/course/*` 來源，`/teacher` 是課務申訴。舊教學管理入口被封鎖時仍保留封鎖及資料隔離，提供授課工作與申訴的可用出口；不為了恢復畫面放開舊資料讀取。

## 角色與權限的證據

| 範圍 | 採用的證據 | 不能取代它的資料 |
| --- | --- | --- |
| 本人帳號 | 目前驗證成功的 session 與 owner | 前次登入畫面、自己填寫的學號與名稱 |
| 學校 | 目前帳號／學校的 active、伺服器確認 membership | 瀏覽校園、離線快取、尚未提交的本地變更 |
| 課程 | 該課程有效成員及 `memberRole` | 全域教師／助教名稱、另一門課的角色 |
| 門市 | 目前帳號的 workspace、場域與門市指派 | 申請已核准、商家名稱、公開店家資訊 |
| 宿舍 | 既有服務能力與實際授權棟別 | 一般職員角色、空棟別清單 |
| 平台 | session 的平台管理資格與每次管理 API 授權 | 校方管理員、教師、選校偏好 |

前端決定入口，後端維持授權。錯誤不能當成「沒有工作」；重新確認時停用舊入口。切回先前學校也須取得本次伺服器確認，不能讓已撤權內容從快取復活。

## 任務接續與 AI

1. 先呈現真實待辦，再呈現協助安排與查找的助理；一般載入／重試不拆掉同作用域的對話與草稿。
2. 可準備操作時，保留預覽、使用者確認、執行與結果讀回。結果未知時先查核，不因重新整理或返回而重送。
3. 開啟服務只代表完成導覽。開啟職涯、店家或校務頁，不表示完成申請、接單、核准或結案。
4. 返回保留查詢、分類與展開狀態；需要帳號綁定的搜尋快照維持帳號、session 與校園範圍。服務網址只帶合法校園參數。
5. Agent 定位以正在處理的任務與資料來源為準。本次流程整合不新增教師批改、店家收款或管理核准工具，不把入口建議視為已具備代辦能力。

## 驗收方式

每個角色核對主要工作是否可找到、目的地是否屬於正確來源、返回能否接續、失敗能否重試、結果是否有依據，以及換帳／換校／撤權時是否隔離舊資料。驗收與部署分開記錄。

- [主導覽](../apps/web/src/lib/primaryNavigation.test.ts)、[服務目錄](../apps/web/src/lib/campusServices.test.ts)、[搜尋復原](../apps/web/src/lib/campusDirectorySearch.test.ts)驗證分類、唯一目的地及安全返回。
- [帳號工作區](../apps/web/src/components/AccountIdentity.test.tsx)、[校方資格](../apps/web/src/lib/useSchoolRole.test.tsx)、[店家工作區](../apps/web/src/features/merchant/MerchantWorkspace.test.tsx)驗證工作來源、錯誤及下一步。
- [App 導覽](../apps/mobile/src/__tests__/releaseNavigation.test.tsx)及服務測試驗證原生目的地與角色分流。
- [角色瀏覽器驗收](../scripts/qa/role-workflows/check.py)使用實際帳號／店家元件與合成 API，涵蓋窄版、深色、草稿及返回；不涵蓋全部角色或真人登入。
- [正式 build 流程驗收](../scripts/campus-visual-smoke.py)檢查主入口、查找與跨頁接續；實機、正式 OAuth 及校方資料接入另驗。

本次整合的本機驗證：Web 與 shared 完整型別檢查通過；初次整合的主要導覽、目錄、搜尋、身分與課務等 9 組契約共 218 項，以及 shared 助理服務 64 項通過。修正學校課程與 Google 課班來源混用後，另完成課務次導覽、實際導覽元件、麵包屑與主要入口 4 組共 168 項測試；兩次數字有重疊，不合併計算。正式 build 的編譯階段成功，但後續 Next.js 型別檢查程序仍失敗且未提供診斷；完整 build 尚未通過。角色瀏覽器測試頁建置成功，Chromium 因環境禁止建立 socket 而無法啟動，未執行情境或產生截圖。完整 build 與瀏覽器結果須由對應提交的 CI 確認，不能以以上單元測試代替。
