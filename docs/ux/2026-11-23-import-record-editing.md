# 已匯入個人紀錄的編輯流程

延續 PR #755 的課表與課業接續工作，基於 `3268364c093bf4afec7dd6cb69eea79195cf940a`。

## 實際問題

原本的編輯器位於整份個人紀錄清單下方，長清單按下「編輯」時，欄位可能遠在畫面外。編輯 A 後直接點 B，會以 B 的內容取代尚未儲存的 A；取消也直接丟棄內容。儲存錯誤只顯示在頁面上方，與正在修改的欄位分離。

## 修改後的行為

| 情境 | 行為 |
| --- | --- |
| 開啟編輯 | 使用共用原生對話視窗，名稱欄位取得可見焦點；背景不接受鍵盤與滑鼠操作。 |
| 未修改就取消 | 直接回到原紀錄的編輯入口。 |
| 修改後取消、關閉或 Escape | 先詢問是否放棄；繼續編輯保留欄位與操作位置。 |
| 儲存中 | 欄位與退出動作暫停，阻止重複寫入；有未儲存修改或進行中的寫入時註冊離頁警告。 |
| 儲存失敗 | 原內容保留，錯誤直接呈現在編輯視窗內；可修正後重試。 |
| 欄位無效 | 送出後先展開包含錯誤欄位的收合區塊，再定位到該欄位。 |
| 改名後不符合搜尋、或移除紀錄 | 原入口消失時，焦點改回搜尋欄位並讓它出現在畫面內。 |
| 移除紀錄 | 顯示具名確認，保留紀錄為安全返回動作；失敗不關閉確認視窗。 |
| 身分重新確認 | 主視窗與確認視窗一起隱藏，同帳號／校園恢復後保留草稿；實際範圍切換使用原有 workspace key 隔離。 |
| 另一分頁先修改 | 保留開啟時的原始版本，交由既有 Web Lock 內的版本比較拒絕過期寫入；不改寫另一分頁的結果。 |

表單沿用既有欄位與驗證規則，沒有更動正式儲存協定。portal 表單自行套用站內文字大小、44px 操作區與可換行配置。超長名稱只在初始欄位位於視窗外時立即定位；搜尋焦點的定位依當下減少動態偏好處理。

本輪未加入編輯草稿的跨頁自動還原。離頁警告、同範圍身分重新確認時保留內容，以及正式保存是不同的行為。

## 驗證

- 新增 17 項元件回歸，先在原碼重現缺少編輯對話視窗，再驗證修改、取消、儲存失敗、延遲寫入、帳號／校園切換、版本衝突與可見焦點。
- `PersonalImportCenter`、`personalImports` 與 `personalImportDrafts` 共 132 項測試通過。
- 前後兩輪的課表、課業、匯入、捲動與附件復原相關測試一併執行：13 個檔案、384 項全數通過。
- 真實 Chromium 驗收 8 種尺寸／偏好，包含 320px、大字、200% 文字、360px 高視窗、淺深色及系統／站內減少動態。
- 瀏覽器使用真實產品元件、hooks、Web Locks 與儲存函式，經正式匯入流程建立 40 筆明示合成紀錄；故障注入僅限該測試範圍的 `localStorage` key。
- 每個情境預期 6 次儲存嘗試、5 次成功寫入，其中包含另一分頁的合成更新；過期版本拒絕不產生寫入。每次重載前保存紀錄，失敗則在解除測試鎖前保留截圖、HTML 與當下狀態。
- 測試針對 Chromium 與本機合成資料，未執行正式資料寫入，亦未宣稱 iPhone Safari 或原生 App 真機驗收。

## PostgreSQL 驗收初始化

前一個 head 的 [Web Tests](https://github.com/Miiduoa/graduation/actions/runs/45177004137/job/137705306697) 在跨服務重啟的附件復原案例遇到 5 秒 timeout；該案例及主工作流與 main 相同，同一案例在 [main 的工作流](https://github.com/Miiduoa/graduation/actions/runs/45163199683/job/137653502381) 曾於 73ms 完成。現有紀錄支持初始化或 runner 延遲的解釋，但無法精確斷定卡在哪個資料庫準備步驟。

修正將 driver 載入、連線及測試 schema 建立移至各儲存模式獨立的 `beforeAll`：PostgreSQL 準備上限 20 秒，memory／模擬 SQL 準備上限 5 秒。真正的業務復原案例仍保留 5 秒上限與全部原始斷言；正式程式和全域 timeout 不變。本機該檔 30 項 memory／模擬 SQL 測試通過；真實 PostgreSQL 與全專案結果以最終提交的 GitHub Actions 為準。
