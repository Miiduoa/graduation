# 從作業尋找空堂並完成準備行程

## 使用者可以完成的事

手機助理查到 nuni 作業後，使用者可按「安排準備時間」，再按「幫我找 30 分鐘空堂」。也可以接著說「幫這份作業找 30 分鐘準備時間」，選定來源後直接開始唯讀尋找；同名或多份作業先選確切來源，再啟動一次查詢。

助理讀取目前帳號、學校在這台手機的課表與個人行程，最多提供三個可核對時段。使用者選一個時段後看到原作業、期限、完整行程與資料核對時間，再另外按「確認建立準備行程」。只有重新核對原作業與選定時段都成功，才保存並讀回同一筆個人行程。

尋找與選擇時段沒有寫入，也沒有保留時段。行程成功後可以直接查看已建立的行程及原作業；重新開啟 App 後，仍沿用既有操作紀錄核對。

## 排程規則

- 每次處理一份已選定的 nuni 作業，固定建議完整的 30 分鐘。
- 搜尋今天起七個台灣日期，且必須在作業原期限前結束。
- 只使用適用學期、具有可核對日期與鐘點的已存課程，尋找兩段已知上課時間之間的空堂。空白日或只有一堂課，不足以推斷其他時間可用。
- 時段限制為 08:00–22:00，與上課及個人行程前後保留各 10 分鐘，開始時間向上對齊五分鐘格並且必須晚於現在。
- 個人行程包含同日、跨日與全天事件；全天結束日沿用既有不包含結束當日的定義。
- 停課、調課與跨夜例外使用既有 dated occurrence 解析。無法確認適用學期、缺少星期／鐘點或損壞例外時，不產生假空堂。非適用學期若有移入目標日期的補課，也先要求核對來源。
- 每個可用區段提供一個建議，最多三個；不自動選第一個，不偷偷替換使用者已預覽的時段。

這些是依本機已存副本推算的候選時間，不是校方即時排程、外部行事曆同步或使用者所有生活安排的完整證明。無可用建議時仍保留手動輸入；手動修改後不沿用舊建議的可用性證據。

## 可重用接點

| 層次 | 責任 |
| --- | --- |
| `campusClockAvailability` | 重用 PR #523 的純區間演算法與五分鐘格／三十分鐘選取，沒有帳號、網路或寫入 |
| `nextSavedClasses.scheduledSavedClasses` | 將指定日期與適用學期的已存課程解析成真正鐘點，保留例外與不完整資料的區別 |
| `courseworkStudyAvailability` | 同帳號學校的課表與個人行程讀取、緩衝、七天範圍、型別化候選與確認前核對 |
| `nuniCourseworkStudy.findCourseworkStudyDrafts` | 綁定原作業來源，保存完整來源與不可由 JSON 還原的時段證據 |
| `NuniCourseworkStudyAction` | 尋找、停止、選擇、預覽與明確確認；共享原對話的忙碌與取消保護 |
| `assistantCalendarExecution` | 既有操作紀錄、寫入鎖、單次執行、個人行程衝突、讀回與原 ID 恢復 |

這輪只取用 #523 可重用的純計算，不從計畫文字解析時間，也不讓已保存的讀書計畫取得寫入授權。後續整合 #523 時應保留此處的資料完整性檢查與個人行程避讓。

## 確認前與最後寫入檢查

尋找時段先等待同帳號／學校的個人行程寫入佇列，再讀取課表。每次讀取有二十秒等待上限，來源通知、停止或登入狀態改變會使晚到結果失效。

確認時先重查原作業與課程身分，接著重新讀取最新課表和個人行程，檢查使用者選定的同一段時間。若期限、作業狀態或空堂變更，顯示原因並要求重新核對，不換成另一個時段執行。

最終的額外 `AssistantCalendarWriteCheck` 只能限制新的事件寫入，不能取代原執行器的檢查：

1. 在既有行程寫入鎖中比對剛讀取的 ledger，避免預覽後的匯入或行程更新漏進來。
2. 在寫入操作紀錄前與其原生保存返回後，核對課表／行程版本及開始時間。
3. 在個人行程真正保存前，寫入 guard 仍必須有效；不在已持有的 ledger 鎖裡再次等待該鎖。
4. 行程本身保存造成的變更通知，不會使正常讀回降成結果不明。讀回與保存核對紀錄使用原帳號／學校 guard。

未送出事件而遭最後檢查擋下時，來源卡提供重新查詢入口。已送出但結果不明時，沿用原 operation ID 的唯讀核對，不重新找時段、不重做寫入。

## 驗證與交付範圍

新增測試包含區間運算、學期與補課例外、個人行程緩衝、空白／損壞資料、等待寫入、精確作業選擇、停止及晚到結果、最後寫入 guard、自身變更通知、結果不明恢復與 JSON 還原限制。

真正的對話畫面測試從課堂作業查詢出發，不填任何日期或鐘點，經尋找、選擇、確認後使用真 resolver、executor、journal 與 ledger 讀回保存成果；另驗證選完時段後新增衝突事件會擋住保存。傳輸、模型與原生儲存邊界使用可控測試資料。
