# 跨功能 Agent：公告、活動與未完成查詢接續

這輪接續 [2026-11-14 跨功能任務](./2026-11-14-cross-service-tasks.md)，並整合當前 main。目標是讓 Agent 直接取得更多功能的真實資料，以及讓複合任務在部分來源失敗後可以繼續查詢。沿用既有提議、確認與執行紀錄，不另建一套寫入機制。

## 使用者可直接使用的流程

| 要求 | 實際行為 |
| --- | --- |
| 查校園公告 | 從目前校園的公開公告來源讀取內容，保留來源、原公告時間與本次查詢時間。 |
| 查近期活動 | 查目前校園的公開活動，回傳已讀取資料中的未來或進行中活動；未讀完的來源明確標為部分完成。 |
| 查校園公告，查近期活動，查未交作業，查公車 | 依序執行各個來源查詢，每一步獨立呈現完成、部分完成或尚未完成。私人課務與公車維持原帳號及原校園。 |
| 只重查未完成的項目 | 從最近仍有效的任務選出未完成的讀取節點，只重讀它們和必要來源，不重送整句原始要求。 |
| 點選某一步的「重新查詢」 | 只選取這一步；例如教材依賴課務時，先重新核對課務，再查對應教材。 |
| 查未交作業，安排明天讀書30分鐘，再點上次一樣的午餐，查公車 | 沿用原有讀書與點餐提議。若公車失敗，重查公車不會重建、撤銷或改寫原確認卡。 |

這些可完整辨識的簡單／複合查詢使用確定的任務圖，不需要模型決定工具順序。未完整辨識的自然語句仍走既有對話流程。公告及活動僅新增讀取；發布、報名、取消報名或加入行程沒有因此取得執行能力。

## 公告與活動的來源邊界

新增 `get_campus_announcements` 與 `get_campus_events`。兩者重用學生公告牆及活動頁的 reader，透過專用具名 Firebase Client app 讀取公開資料。這個 app 不初始化 Auth、不使用 Admin，也不沿用其他 Firebase app 的登入狀態；校園固定為已驗證請求的校園。

每次實際 Firestore 查詢都納入既有的每題十二次 API 額度，並檢查 principal、請求取消及工具期限。單次工具仍有四秒期限。不能把來源錯誤換成成功的空陣列，也不能因來源拒絕存取就改讀另一個集合。

- 公告沿用學生頁既有的公開可見性規則，最多回傳五筆。
- 活動最多讀三頁、回傳五筆，保留分頁未讀完、跳過異常紀錄、來源故障及資料截斷資訊；不宣稱已查完校園所有活動。
- 結果含來源集合、站內連結、校別、查詢時間，以及原公告／活動時間。摘要先顯示來源與限制，再顯示內容，避免摘要長度上限把限制截掉。
- 外部文字僅作資料呈現，不當作 Agent 的新指令。原文連結僅接受無帳密的 HTTPS 網址。
- 來源部署需要原本的 `NEXT_PUBLIC_FIREBASE_PROJECT_ID` 等公開設定；測試 emulator 僅允許 `demo-` 專案。未接通、隱藏校園或無法核對的來源保留為未完成。

## 重查憑證與任務範圍

後端只替 `blocked` 或 `partial`、沒有操作卡、且所有來源依賴都是讀取的節點發出重查憑證。有效期從原始要求解析時起算十五分鐘；後續重查不延長原期限。

憑證以獨立用途的 HMAC 簽章綁定帳號、session、conversation、校園、原問題、原解析時間、任務圖雜湊及允許的節點。瀏覽器只能從允許集合挑選節點，不能提交新工具、修改參數或擴張任務。後端重新核對簽章與當前身分，使用原時間重建任務圖，確認沒有因程式更新而改變原意，再取出必要的讀取依賴。

`POST /api/nuni/assistant/retry` 沿用同源、登入與 principal 檢查，只接受 `schoolId`、`conversationId`、`token`、`stepIds`。讀取不依賴原 Fly machine，也不重置原提議版本。重查有獨立的記憶體配額：每個伺服器實例、每帳號每分鐘三次、每小時十次，同時最多一項。這是單實例限制，並非跨實例的全域帳號配額。

重查執行器使用全新工具與空的提議問題、停用寫入，允許的範圍包含課表、行程、課務、匯入課務、餐廳、訂單、教材、空堂、社團、公車、已支援的公開課程及新增的公告／活動讀取。讀書提議、重新點餐、導頁與任何 writer 都不能進入重查依賴圖；回傳含操作卡時會拒絕交付。

## 接續時保留原意

相對日期在原始要求解析時就固定。午夜後重查「今天作業」，仍查原本那一天；沒有明寫期間的「查功課」也保留原查詢範圍。另一方面，「下一堂課」及可接續安排的空檔不能把已過去時段重新當成未來選項。因此，重查空堂會排除已過期的空檔，一般查詢仍保留查看歷史空堂的能力。

必要來源每次都重新核對。例如第一次課務完成但教材失敗，重查教材時若課務變成不可用，就停止教材查詢，不拿上一次成功的課務快取代替。回應會保留兩個未完成節點的新憑證，仍沿用原到期時間；來源恢復後可以再接續。

畫面保留原回覆及其確認卡，把重查結果附在後面。已接續的節點從舊回覆的重查按鈕退役；未選取的其他失敗節點仍可各自接續。只有精確的重查語句會選取舊憑證，否定、假設或混有新命令的句子不會被當成純重查。到期後關閉接續按鈕，要求重新描述查詢。

查詢回覆標為 `dataRead`，不加入後續外送給模型的歷史。停止請求、登出、換帳號或換校園後，晚到的重查結果不會加入新對話。重查不取代原卡片物件或確認狀態；原有付款導頁、確認冪等及回執核對契約保持有效。

## 驗證重點

使用 Node 22.23.5、pnpm 10.28.2 及現有 frozen lockfile，測試包括：

- 真實 `run` → `retryTaskReads` → 原卡確認的接續流程；讀書與點餐卡不重發，確認重播不重複寫入，需付款／未開放下單時仍只導頁。
- 部分來源失敗、必要依賴改變、重查子集合、新失敗憑證、原期限不延長。
- 跨帳號、session、conversation、校園，簽章竄改、越界節點、過期及未來時間拒絕。
- 午夜跨日、隱含課務期間、下一堂課與空堂的時間語意，以及一般歷史查詢回歸。
- 新匿名 Firebase app 的隔離、公開 reader 分頁與來源故障、工具額度、取消及來源內容驗證。
- UI 按鈕、有效期限、原卡保留、停止／換帳校的晚到結果、回覆驗證及模型歷史隔離。

具體測試計數與 production build 結果記錄於 PR。測試使用合成帳號、資料與來源，不提交正式作業、報名、假單、訊息或訂單。

## 手機 smoke 修正與仍有的範圍

既有 Maestro CI 在輸入 `NTHU` 時，紀錄顯示欄位只收到 `N`，導致清大選項找不到。本輪僅讓選校 helper 等待畫面穩定、完整重填並核對 `NTHU`，最多重試兩次；選校項目與選中學校的原斷言仍保留。實機／模擬器結果以新提交的遠端 Maestro 執行為準。

整合目前 main 後，遠端行程修訂畫面測試另發現 320px 窄版的焦點捲動回歸：「重新預覽」原本已完整可見，原生 Tab 與既有焦點補捲動卻讓頁面淨移動 11px。修正保留原生焦點順序，只在同一次 Tab、視窗與版面未變、目標原本可見時還原多餘的 document 捲動，再重新核對是否被輸入區遮住。快照單次使用，取消按鍵、離開表單、pointer 或卸載會使舊還原失效；原有畫面測試的 1px 門檻不變。

這輪沒有新增通用背景 Agent、排程、永久任務記憶，或手機端的 Web 重查 API 介面。未接通的宿舍、請假、私人訊息及校方 writer 仍是原有功能入口。重查只恢復讀取，不自動接續之前被阻擋的讀書／點餐寫入；需要新的安排要求或原確認卡。

本地瀏覽器預覽受環境連線與協定安全政策阻擋，未取得真瀏覽器的畫面驗收。本輪不以元件測試替代該項驗收。合併與發布仍須核對相同 commit 的遠端 CI、GitHub 必要 App 審查及部署狀態。
