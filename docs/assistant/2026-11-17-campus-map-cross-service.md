# 課表、活動與校園位置的跨功能任務

## 學生現在能完成的事

| 說法 | 執行流程 | 結果 |
| --- | --- | --- |
| 下一堂課教室在哪裡 | 讀本人已同步課表 → 找唯一下一堂課 → 用原始教室查所選校園地圖 | 課名、時間、教室與來源位置；不只提供地圖首頁 |
| 下一堂課在哪，幾點 | 同上，沿用首頁既有建議問句 | 時間由課表回答，位置由地圖來源回答 |
| 任垣樓在哪裡 | 直接讀所選校園的公開地圖資料 | 名稱、來源座標、已提供的樓層／設施與地圖連結 |
| 查近期活動，查第二個活動位置 | 讀完整活動清單 → 核對原始排序及明確序號 → 用所選活動原始地點查地圖 | 活動名稱、原始地點與可核對位置 |
| 查下一堂課，查教室在哪裡，查餐廳 | 課表與地圖有依賴；餐廳是獨立讀取 | 地圖暫時失敗時仍保留餐廳結果，失敗步驟可重查 |

「查圖書館」仍是圖書館服務需求；「圖書館在哪裡」才是地點查詢。學生活動中心、辦公室、系辦與教室名稱可作為具體地點。尚未提供資料的地點會明示，沒有推算未知房號、樓層、導航路線或到達時間。

## 本輪改變

- 服務目錄的 `map` 從入口改為真實資料讀取，工具為 `get_campus_map`。
- 目錄共 45 個服務，16 個具資料 reader，其中 5 個也能準備待確認操作；其餘 29 個仍是服務入口。這是程式能力契約，實際可用性仍取決於帳號權限、來源與既有部署開關。
- 跨功能圖增加唯讀 `map-location` 依賴步驟，支援課表與活動兩種來源。
- 新增不使用模型的 `map-read` 入口。直接地點與下一堂課地點查詢，在模型尚未可用或未勾模型同意時仍可使用；一般複合服務語句保留原聊天路徑。
- 地圖查詢與原聊天分開保存讀取識別。既有待確認／結果未知的行程或點餐卡不會被重設、撤銷或誤送出。
- 來源失敗的重試重新讀取必要的課表或活動，從新結果取得教室／場地；不沿用失敗之前的舊地點。

## 真實來源與結果界線

地點資料沿既有 `/map` 使用的公開來源：先讀 `schools/{schoolId}/pois`，只有該集合確實為空，才讀帶精確校別條件的 root `pois`。使用獨立匿名 Firebase client，不使用 Admin SDK 或學校登入，也不把私人教室文字傳到匿名資料庫查詢。

靜宜沿現有 `withProvidenceCampusPlaces` 組裝正式隨附的 OpenStreetMap 建築、設施與公車站牌快照。其他學校不會混入靜宜資料。無公開設定或來源讀取失敗時，靜宜可保留隨附資料並標示部分來源及快照日期；其他學校回報來源不可用。

每個來源查詢計入原本的 API 額度、取消與期限，最多掃描 200 筆、最多回傳 5 個候選。多出的資料、被丟棄或截短的紀錄、重複識別、讀取失敗都會保留不完整狀態。

| 地點結果 | 任務狀態 | 意義 |
| --- | --- | --- |
| 完整且唯一的精確地點或已核對建築對應 | completed | 已完成這次來源定位；建築對應仍不等於房號或樓層已確認 |
| 模糊文字的一筆候選，或單一來源尚待核對 | partial | 顯示候選，供學生核對 |
| 多個同名／相符地點 | partial | 不擅自挑第一筆 |
| 來源、掃描或結果清單不完整 | partial | 不宣稱唯一或完整 |
| 無相符地點或來源不可用 | blocked | 不假裝已找到位置 |

活動位置只接受本次已讀取且完整、順序可核對的活動清單，明確序號限 1–5。部分或無序清單、缺場地、越界序號不會改選另一筆。課表位置只接受同校、完整、時間可定位且唯一的下一堂課；並行課程、缺教室及已開始的課程不會被當成唯一下一堂課。

活動地圖重試另外綁定首次選中的 `schoolId/source/id`，再重讀清單取得同一活動的最新場地。新活動插入或清單排序變動不會把「第二個」重新解讀成另一場活動；原活動消失、超出本次可核對清單或來源不完整時維持 blocked。只有實際完成首次來源選取，才會發出該地圖步驟的簽章續接。一般唯讀 token 維持原格式；帶活動身分的內部簽章升為 v2，外層 UI 契約不變，舊的無身分活動地圖 token 不接受重選。

## 請求與權限

`map-read` 只接受以下兩種 task，外層保留既有 `schoolId` 與 `conversationId`：

```json
{ "kind": "place", "query": "任垣樓" }
```

```json
{ "kind": "next-class" }
```

同來源、登入、session 與固定校別驗證沿既有 BFF。入口不接受模型歷史、任意工具圖、caller 指定的資料庫路徑、寫入欄位或 chat route token。內部圖限最多兩個唯讀節點，`writes=false`，不呼叫模型、不產生卡片；回覆不進模型歷史。讀取額度與併發上限沿既有唯讀 followup。

一般模型若真的呼叫地圖工具，最後的位置回答也由已驗證的來源格式化，避免把候選、建築或缺漏改寫成確定教室、樓層或路線時間。帳號或校別切換、登出與停止查詢後，晚到回覆不再顯示。

沒有新增套件、登入方式、資料集合、Firestore 規則、migration 或部署旗標。這輪沒有接通通知／請假／宿舍等仍待平台與學校身分橋接的私人服務，也沒有啟用校方作業 writer。
