# 2026-11-23：接續門市工作

## 產品決定

本輪從 main `f7f5acba2177562ed42ea73067d094b6e7946edb` 開始，先修正商家每天進出門市與訂單的路徑。

設計標準是：點選哪間門市，就進入哪間；重新整理、登入與返回後，仍能辨識目前工作；設定與日常接單有各自的位置。這符合 Apple [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/) 的一致性、清楚回饋及保留情境，也依 [Motion](https://developer.apple.com/design/human-interface-guidelines/motion/) 讓動態服務操作。這些是本次採用的設計原則，不代表產品由 Apple 設計或已達到全產品同等品質。

既有 #735 已處理一般導覽接續與可及性；#739 正在處理教師首頁、附件核對和社群表單，本輪不重做那些改動。

## 實際問題與改變

| 原本的問題                                           | 本輪行為                                                                                    |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 個人身分頁每間門市都連到同一個 `/merchant/workspace` | 品牌、門市名稱、校區與實際狀態一起顯示，每店有正確 tenant/location 連結；同品牌同校也能區分 |
| 首頁只提供一個通用門市入口                           | 前兩間已授權門市可直接開啟，其餘放在可展開清單，申請進度仍有自己的入口                      |
| 選店只放在元件 state，重新整理及返回無法接續         | 用明確網址保存門市、工作區與訂單篩選，支援正常返回、前進及另開分頁                          |
| 門市設定與訂單桌一起展開，工作位置不明               | 分成「門市概況」及「訂單與收銀」，目前位置用可及的選中狀態標示                              |
| 訂單清單沒有工作類型篩選                             | 提供全部、待收款與確認、備餐與取餐；計數明確只代表目前這一頁                                |
| 讀取門市後，訂單頁次容易重設                         | 頁次保留在同帳號、同門市的記憶體快取，失效游標可回到第一頁                                  |
| 暫停營業被身分頁當成不能開店                         | 沿用伺服器資料的狀態標籤，區分暫停接單、尚未啟用與停權                                      |

## 導覽與資料規則

路徑固定為 `/merchant/workspace`，只接受 `tenant`、`location`、`section`、`queue` 作為工作位置。

```text
/merchant/workspace?tenant=campus-one&location=store-a
/merchant/workspace?tenant=campus-one&location=store-a&section=orders&queue=active
```

以上為合成識別值。網址只表示想開啟的位置；實際門市與訂單仍由目前帳號的 API 授權。tenant/location 共用既有 validator；缺一、重複或不合法的識別值顯示可恢復錯誤，不自動換成其他門市。登入回程只重建已允許的欄位，取餐憑證、角色、確認狀態與任意參數不會跟著傳遞。

指定真實門市時直接查核該目標，避免本人示範資料替換成不同門市。無權限、不存在或失效時提供重讀及返回入口；已啟用但被停權的門市，提示由管理者確認，不誤導為重新填寫開店設定。

同路徑使用原生 history 保留帳號所屬的工作快取。依目前安裝的 Next Router 行為，呼叫前移除內部 `__NA`、`_N` 與 tree 標記，再讓 Next 的 patched History API 複製必要資訊及同步網址；保留其他自訂 history state。外層 Suspense 包住讀取路由的 client component，外部 Next 導覽也會同步工作位置。

返回門市時將焦點放回原門市連結；讀取期間若使用者已選擇其他控制，則不搶走焦點。切換工作區後，原控制若已卸載，焦點回到該門市標題。

## 寫入與草稿

- 切換訂單篩選不寫入，也不重新讀取 API。
- 尚未送出的訂單確認會取消，避免舊確認套在新的選取；已送出或結果未確認的操作保留原面板和原重試資訊。
- 門市設定與菜單草稿沿用同帳號／同門市快取。換帳號會清除；不宣稱重新整理後可以恢復所有草稿。
- 訂單頁次保存在同一頁面工作期間的快取，不放入網址；書籤或重新整理從第一頁核對目前訂單。
- 進駐申請的草稿及未確認收件結果仍屬於原頁面。若點門市入口會離開該頁，先保留原申請，提供新分頁入口；重試仍使用同一份申請及同一 key。
- 沒有新增付款、接單、交班或取餐的自動執行，也沒有變更後端權限。

## 驗證方式

使用 repository 指定的 Node.js 22.23.5、pnpm 10.28.2 及 frozen lockfile。

必要回歸涵蓋 URL 驗證、真正父層導覽、示範資料邊界、同名門市、帳號切換、舊回應隔離、草稿／未確認申請、訂單收款取餐與失效游標。本機 8 份相關測試共 146 個案例全部通過；完整 Web TypeScript、定向 ESLint 及 UI design gate 已通過，提交前再核對 Prettier 與 diff 格式。

`scripts/qa/merchant-workspace/` 打包真正產品元件及 CSS，僅以合成帳號、API 與 Next routing 邊界替換外部資料。瀏覽器驗收由 `Merchant Workspace Browser` workflow 執行，保存桌機、390px 深色、320px 放大文字／減少動態的截圖、流程結果及來源 SHA-256。合成驗收不代表正式帳號、真實金流、Safari 或原生 App 已通過。

## 後續產品優先順序

1. **以真實案件建立教師工作佇列。** 授課會員資格和課程連結不是待批改、待核閱的案件數；應取得已授權案件，接到可完成及可返回的位置。
2. **讓課表與課程工作區接成完整課務路徑。** 沿用已確認的 `linkedCourseId`，銜接今天的課、教材、作業與回條；無確定對應時明確讓人選課，不猜測連結。
3. **統一 Agent 任務的結果追蹤。** 延伸已存在的行程執行核對，讓各角色與服務都能分辨待確認、執行中、完成、結果不明及重新核對；入口或提案不能算作已執行。
4. **交流從功能目錄走向內容與對話。** 保留校內／跨校權限邊界，但讓人先看到可讀內容與正在進行的對話，再揭露次要服務入口。
5. **將文字、間距與操作回饋規則落到所有主要工作頁。** 優先清理仍使用固定小字的課程頁，依同一套文字偏好、鍵盤焦點及減少動態規則驗收。
6. **以完成第一件事驗收首次體驗。** 延續按需登入；訪客、學生、教師及店家各自能從入口完成一個真實任務，成功後留在結果與下一步。

這份順序是依本輪檢查的主要入口及相關程式提出的產品判斷，不是全系統功能或部署完成清單。
