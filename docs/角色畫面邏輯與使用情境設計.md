# 角色畫面邏輯與使用情境設計

## 一、角色定義與權限架構

本 APP 定義五大角色群組（RoleGroup），每個角色群組擁有不同的頁籤組合、功能權限與操作邏輯。

| RoleGroup       | 對應 UserRole      | 主要職責                     |
| --------------- | ------------------ | ---------------------------- |
| student         | student, alumni    | 選課、查成績、使用校園服務   |
| teacher         | teacher, professor | 教學管理、給分、考勤         |
| admin           | admin              | 系統管理、數據分析、全域設定 |
| staff           | staff              | 場館/宿舍/印刷等校務服務管理 |
| department_head | principal          | 審核簽核、部門報表           |

額外隱含角色：

- **vendor（店家老闆）**：餐廳系統中的店家管理者，透過 cafeteria 模組的角色欄位識別
- **visitor（訪客/未登入）**：可瀏覽公開資訊，無法使用個人化功能

## 三、各角色畫面邏輯與真實使用情境

### 3.1 學生角色

#### 每日使用流程

1. **早上 8:00** — 開啟 APP，Today 頁面顯示今日課表、待交作業、校園公告
2. **前往教室** — 從「校園」頁籤進入校園地圖，搜尋教室位置，啟動 AR 導航
3. **中午 12:00** — 進入「餐廳」查看各餐廳人潮預測，選擇人少的餐廳；使用閃購優惠；查看月預算剩餘
4. **下午上課** — 進入「課程」查看教材、繳交作業
5. **下課後** — 查看圖書館座位、使用列印服務、搭公車回家（交通資訊）

#### 畫面邏輯

| 畫面                   | 入口               | 顯示條件              | 可執行操作                       |
| ---------------------- | ------------------ | --------------------- | -------------------------------- |
| TodayScreen            | 底部頁籤           | 永遠可見              | 查看公告、今日課表、待辦事項     |
| AcademicStack          | 底部頁籤「課程」   | student 角色          | 查看課程列表、教材、作業、成績   |

| ARNavigationScreen     | 地圖 → AR 導航     | 所有角色              | 相機 AR 即時導航                 |
| CafeteriaScreen        | 校園 → 餐廳        | 所有角色              | 查看餐廳、菜單、預算、閃購、揪團 |

### 3.2 教師角色

#### 每日使用流程

1. **早上 8:30** — Today 顯示今日授課時間、待批改作業數量、學生出席提醒
2. **上課前** — 進入「教學」開啟點名功能，學生用 APP 簽到
3. **課堂中** — 透過教學管理發布即時測驗、查看學生互動
4. **課後** — 批改作業、輸入成績、發布教材
5. **中午** — 使用校園餐廳（同學生流程）

#### 畫面邏輯

| 畫面                 | 入口             | 顯示條件     | 可執行操作           |
| -------------------- | ---------------- | ------------ | -------------------- |
| TeachingStack        | 底部頁籤「教學」 | teacher 角色 | 課程管理、給分、考勤 |
| AttendanceScreen     | 教學 → 考勤      | teacher      | 開啟點名、查看出席率 |
| GradebookScreen      | 教學 → 成績      | teacher      | 輸入/修改成績        |
| CourseMaterialScreen | 教學 → 教材      | teacher      | 上傳/管理教材        |

教師共享學生的所有「校園」功能（地圖、餐廳、交通等），但在某些畫面有額外權限：

- 餐廳：可點餐但無月預算追蹤
- 列印：有教師專用額度

---

### 3.3 店家老闆（Vendor）角色

#### 每日使用流程

1. **早上 6:30** — 開啟 APP，進入「店家管理」查看今日預訂單
2. **準備營業** — 更新今日菜單（標記售罄、新增特餐）
3. **營業中** — 即時接單、更新訂單狀態（製作中→完成→取餐）
4. **促銷時段** — 建立限時閃購（快過期食材打折）
5. **營業結束** — 查看今日營業報表、評價回覆

#### 畫面邏輯

| 畫面                      | 入口                   | 顯示條件    | 可執行操作             |
| ------------------------- | ---------------------- | ----------- | ---------------------- |
| VendorManagementScreen    | 校園 → 餐廳 → 我的店家 | vendor 角色 | 管理菜單、訂單、閃購   |
| MenuTab（內嵌）           | 店家管理 → 菜單        | vendor      | 新增/編輯/刪除菜單項目 |
| OrderTab（內嵌）          | 店家管理 → 訂單        | vendor      | 接單、更新狀態         |
| FlashDealCreator（Modal） | 店家管理 → 閃購        | vendor      | 建立限時優惠           |
| StatsTab（內嵌）          | 店家管理 → 統計        | vendor      | 營業額、熱門品項分析   |

**與學生的關聯**：

- 學生在 CafeteriaScreen 看到的菜單 = 店家在 VendorManagementScreen 編輯的菜單
- 學生下的訂單 → 即時出現在店家的訂單列表
- 店家建立的閃購 → 即時出現在學生的閃購輪播

---

### 3.4 管理員（Admin）角色

#### 每日使用流程

1. **早上 9:00** — 進入「管理」儀表板，查看全校系統概覽（在線人數、公告數、待處理事項）
2. **處理事務** — 審核新公告、管理使用者帳號、查看系統錯誤回報
3. **餐廳管理** — 進入 AdminCafeteriaScreen 審核店家申請、查看營運數據
4. **失物管理** — 審核失物招領貼文、標記已歸還
5. **報表** — 查看各項統計分析

#### 畫面邏輯

| 畫面                     | 入口             | 顯示條件   | 可執行操作                 |
| ------------------------ | ---------------- | ---------- | -------------------------- |
| AdminStack               | 底部頁籤「管理」 | admin 角色 | 系統管理儀表板             |
| AdminCafeteriaScreen     | 管理 → 餐廳管理  | admin      | 審核店家、查看全校餐廳數據 |
| UserManagement（規劃中） | 管理 → 使用者    | admin      | 帳號管理、角色分配         |
| SystemSettings（規劃中） | 管理 → 設定      | admin      | 系統設定、通知管理         |

**與其他角色的關聯**：

- 管理員可看到所有角色的數據彙總
- 管理員可修改店家的營業狀態
- 管理員可發布全校公告（所有角色都會收到）

### 3.5 職員（Staff）角色

#### 每日使用流程

1. **早上 8:00** — 進入「服務」查看今日待處理：宿舍報修單、印刷排程、場地借用
2. **處理報修** — 查看學生提交的宿舍報修單，安排維修人員
3. **場地管理** — 審核場地借用申請
4. **失物管理** — 登記拾獲物品、通知失主

#### 畫面邏輯

| 畫面               | 入口             | 顯示條件   | 可執行操作     |
| ------------------ | ---------------- | ---------- | -------------- |
| StaffStack         | 底部頁籤「服務」 | staff 角色 | 服務管理儀表板 |
| FacilityManagement | 服務 → 場地      | staff      | 審核場地借用   |
| RepairManagement   | 服務 → 報修      | staff      | 處理報修單     |
| PrintManagement    | 服務 → 印刷      | staff      | 管理列印排程   |

---

### 3.6 訪客（Visitor / Guest）

#### 使用情境

新生參觀校園、家長陪同、外校訪客

#### 可用功能（無需登入）

- 校園地圖（所有 POI 瀏覽 + AR 導航）
- 交通資訊（公車時刻、路線規劃）
- 餐廳資訊（瀏覽菜單，不可點餐）
- 公開公告

#### 不可用功能

- 課程相關（課表、教材、成績）
- 個人化服務（宿舍、支付、列印）
- 訂餐、揪團、閃購
- 收件匣

## 五、共用模組與角色差異

### 校園地圖模組（所有角色共用）

- 50+ POI 點位（精準 GPS 座標）
- A\* 路徑規劃（22 節點校園路網）
- AR 實景導航（感測器融合 + 路線偏移偵測）
- 分類篩選（13 類：教學/行政/圖書/餐廳/宿舍/運動/停車/便利/醫療/宗教/出入口/研究/其他）

### 餐廳模組（角色差異）

| 功能       | 學生 | 教師 | 店家     | 管理員   |
| ---------- | ---- | ---- | -------- | -------- |

| 線上點餐   | ✅   | ✅   | ❌       | ❌       |
| 月預算追蹤 | ✅   | ❌   | ❌       | ❌       |
| 閃購搶購   | ✅   | ✅   | ❌       | ❌       |
| 建立閃購   | ❌   | ❌   | ✅       | ❌       |
| 菜單 CRUD  | ❌   | ❌   | ✅       | ❌       |
| 訂單管理   | ❌   | ❌   | ✅       | ❌       |
| 揪團點餐   | ✅   | ✅   | ❌       | ❌       |

## 六、權限控制實作

權限透過三層機制控管：

1. **Tab 層**：`getTabsForRole()` 根據角色群組回傳不同頁籤組合
2. **Screen 層**：`RouteGuard` 包裹需要權限的畫面，無權限時顯示存取拒絕
3. **UI 層**：`RoleGatedSection` 條件渲染，隱藏無權限的 UI 元素

```typescript
// 權限定義範例
const PERMISSIONS = {
  student: [
    'announcements.view',
    'courses.view',
    'campus.view',
    'groups.view',
    'messages.view',
    'profile.view',
    'credits.view',
    'calendar.view',
    'transport.view',
    'library.view',
    'cafeteria.view',
    'health.view',
    'dormitory.view',
    'print.use',
  ],
  teacher: [
    ...student_permissions,
    'courses.create',
    'courses.grade',
    'courses.attendance',
    'courses.material',
    'announcements.create',
  ],
  admin: ['*'], // 全部權限
};
```
