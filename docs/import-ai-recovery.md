# 手機表格整理：完整資料列與有界重試

這次修改延續本機文字 AI 匯入，沒有新增雲端辨識、下載模型、登入或自動寫入。
既有模型、1,536 輸出 token、每段 120 秒與整份 80 筆結果上限均保留。

## 改善的輸入

- 有可辨識欄名的 CSV，以及矩形 TSV，可以按完整資料列分段。
- 依 CSV 的引號規則處理儲存格內逗號、換行、空白行與雙引號跳脫；也用於 TSV。
- 支援 LF、CRLF、檔頭 BOM 與末尾空欄位。原文不重新序列化，字元、順序、來源行號保留。
- 一段最多八個完整資料單位。即使整份少於 1,000 字元，也不會一次將數十列交給模型。
- CSV 必須有至少兩個可辨識欄名。沒有欄名的逗號散文不會被猜成表格。
- 模糊邊界、不完整引號及不規則表格不提供資料列切點；完整短段落仍沿用既有文字整理。
  超過安全預算的單筆資料不強拆，必須縮小來源。

來源語法參考：RFC 4180 §2，第 5–7 點（https://www.rfc-editor.org/rfc/rfc4180.html）。
本程式是提供 AI 整理邊界的保守掃描器，不取代既有正式 CSV 匯入解析器。

## 模型輸出被截斷

只有原生引擎明確回報 `finishReason: 'length'` 時才自動重試。
若原文有經分段器確認的完整資料列／段落切點，就把該段分為兩半，維持來源順序重新整理。
不解析、不拼接截斷的 JSON，也不重新跑先前成功的段落。
欄位參考會傳給子段，但不變成子段的來源證據。

一次操作最多八次拆分；初始最多十六段，所以最多三十二次原生呼叫。
單筆仍無法完成、拆分預算耗盡、格式／引用錯誤、取消、逾時或模型變更時，整次失敗，不交付部分草稿。
取消／逾時仍須等原生 Promise 結束才解除互斥，晚到結果不會寫進預覽。

## 畫面回饋

沿用手機匯入頁的 availability 訂閱：顯示第幾段、目前原始文字行號範圍及縮小範圍重試原因。
重試時總段數可能增加，這不是估算百分比。PDF／Excel 的行號是所選內容整理出的文字行號，
不是 PDF 印刷頁碼，也不是原始工作表儲存格座標。

## 驗證與限制

Web 測試驗證純分段器，Mobile Jest 測試使用替身模型與實際 shared schema parser 驗證整合。
包含短密集 CSV、帶引號跨行欄位、來源順序、重試後行號、部分 JSON 丟棄、總重試預算、取消、逾時與模型切換。
Web 迴圈涵蓋 120 組確定性的合成格式變化；它們不是 120 份真實學校樣本。

這些測試不衡量真實模型準確率、手機速度、耗電或記憶體；送入完整來源仍不保證模型不漏列。
手機仍是文字模型，沒有新增原生視覺模型，也沒有改變 Web 圖片辨識 Worker。
