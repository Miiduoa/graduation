- 網頁：https://nuni.tw/demo/oral-exam

## 1. 今天正式站怎麼進各角色（盤點）

正式站是 https://nuni.tw（Fly `nuni-web`）。後端 Firebase 專案 `campus-one-tw`，課業／平台資料另有 Supabase `hrrmkrayvrgnwcroyttp`。

**結論：在本次改動之前，正式站無法在不使用真實校園憑證的情況下，把學生、教師、校方、店家、平台營運從頭到尾跑完。** 舊的 client-side demo 在正式環境是關掉的。

### 1.1 不需真實學號、今天就能用的入口

| 角色／場景 | 今天怎麼進 | 實際能示範什麼 |
| --- | --- | --- |
| 訪客／公開校園 | 直接開 nuni.tw，選學校後看地圖、公車、館藏、公開公告、餐廳資訊 | 公開資訊。`tw-demo-uni` 在正式環境目錄是隱藏的。 |
| 平台學生／教師課班 | Google 登入 → `/classroom` 或手機「課程與作業」 | 平台自己的課班、作業、繳交。**不是**校方課表／TronClass。 |
| 失物招領 | Google 登入 → `/lost-found` 或手機「開啟失物招領」 | 平台失物招領，與校籍無關。 |
| 店家申請 | `/merchant` 或 `/login?returnUrl=/merchant`，用 Google | 申請與門市工作區。需要已核准的店家身分，不是一鍵示範帳號。 |
| 校方人員 | `/auth/account?method=school` 或 `/admin` 的校方入口 | 學校核發帳號。正式站**未開啟**學號直登（`SCHOOL_STUDENT_ID_LOGIN_ENABLED` 維持關）。 |
| 平台營運 | `/admin/login` → `/admin/ops` | 需要真正的平台營運帳號。一般 Google 或校方身分進不去。 |

| 機制 | 位置 | 正式站狀態 |

### 1.3 程式裡已經有、但不能當正式站口試入口的資料

這些資料**仍然存在**，本次沒有關掉或刪掉。它們主要服務本機／開發，或當 Firebase 空資料時的後備。

**網頁 client-side demo**

- `apps/web/src/lib/demoRole.ts`：8 種角色（學生、教師、TA、社團幹部、系主任、管理員、校友、訪客），存在 `localStorage.demoRole`。**沒有店家、沒有平台營運。** 設定頁已拿掉「示範工具」（`settings/page.test.tsx` 仍檢查正式設定頁不出現 seed／重置）。
- `apps/web/src/lib/demoData.ts`：王小明、王大明老師、課 `c1`–`c8`、社團、公告、作業 workspace。顯示名稱沒有「示範」前綴；學號像 `M11302001` 是虛構的靜宜格式，不是口試標籤。
- `apps/web/src/lib/demoStore.ts`：跨角色 localStorage（請假、繳交、點名、訂餐、私訊）。`seedDemoQueues()` 一鍵種佇列。教師／成績冊等**正式頁**已改走學校帳號 + Firestore／nuni API，不再用這份 store 當主路徑。

**手機 demo**

- `apps/mobile/src/data/demoPersona.ts`、`demoUserStories.ts`、`demoCoursesMock.ts`：顧晉瑋／張怡君等 9 個 persona。
- `apps/mobile/src/state/demoRole.tsx`、`demoStore.tsx`、`demo.tsx`
- `apps/mobile/src/services/demo*.ts`（訂餐、請假審核、商家訂單、AI context、inbox seeder、session）
- `apps/mobile/src/services/testSeedData.ts` + `studentIdAuth.ts` 的 `test_student` / `test1234`：本機測試帳號，**正式學號登入關閉時不能用**。
- 舊口試稿：`docs/ORAL_DEFENSE_DEMO_CHECKLIST.md`、`docs/DEMO_DATA_FLOW_MAP.md`、`docs/口試最終檢核清單.md` 假設「左上頭像切 demo 角色」。那條路在正式 App 進不去。

**後端種子（會碰資料庫，不是口試當天的預設路徑）**

## 2. 缺口與這次補上的路

| 缺口 | 處理 |
| --- | --- |
| 正式站沒有免憑證的角色切換 | 新增 `/demo/oral-exam`（網頁）與手機「口試示範工作區」。資料只在該裝置的 localStorage / AsyncStorage。 |
| 網頁 demo 沒有店家／平台營運 | 口試工作區五個角色：學生、教師、校方、店家、平台營運。 |
| 姓名不像示範帳號 | 一律「示範學生王小明」這類標籤；學號 `DEMO1140001`，不是真實學號。 |
| 線上點餐必須保持關閉 | 只展示菜單與**預先備好**的示範訂單，可把「備餐中」標成「可取餐」。沒有建單、付款。 |
| 校方／營運不能看到真實租戶 | 工作區寫死 `nuni-oral-exam`。沒有放寬 `/admin/ops` 或 Firestore 規則。 |
| 若之後要寫正式庫 | `scripts/demo/seed-oral-exam.mjs` 預設 `--dry-run`。`--apply` / `--remove` 只動 `demo:true` 且 `oralExamTag=2026-11-12` 的文件。 |

**沒有改的旗標與權限：** 未開啟 `SCHOOL_STUDENT_ID_LOGIN_ENABLED`、`ONLINE_ORDERING_ENABLED`、TronClass／E-campus；未放寬 auth；未部署、未合併。舊功能都還在。

**口試當天不必寫正式庫。** 工作區本身就能把下列流程跑完：課表、LMS 作業／繳交／成績冊、點名、請假、行事曆／公告、社團動態＋限時動態＋私訊、餐飲菜單與備餐單、失物招領、校園助理脈絡、校方名冊、營運租戶健康。

## 3. 可選種子腳本（不要對正式庫執行，除非你自己確認）

```bash
pnpm demo:oral-exam
# 或
node scripts/demo/seed-oral-exam.mjs --dry-run
```

`--dry-run` 會印出將 `SET` 的路徑，例如：

- `schools/nuni-oral-exam`（`directoryVisible: false`、`demo: true`）
- 公告 2、行事曆 3、課程 3、作業 2、點名、請假
- `cafeterias/oral-exam-cafe-1`（`orderingEnabled: false`、`merchantMode: info_only`）
- 菜單 3、示範訂單 2、失物 2、社團 1
- 示範名冊 5 人（無密碼、不建立 Auth）

**不會寫 Supabase。** 課業示範走 client-side。

若要真的寫入（僅限標記列、且需你自己的憑證）：

```bash
ORAL_EXAM_SEED_CONFIRM=nuni-oral-exam node scripts/demo/seed-oral-exam.mjs --apply
ORAL_EXAM_SEED_CONFIRM=nuni-oral-exam node scripts/demo/seed-oral-exam.mjs --remove
```

未設 `ORAL_EXAM_SEED_CONFIRM=nuni-oral-exam` 時，`--apply` / `--remove` 會直接拒絕。本次 PR **沒有**對 `campus-one-tw` 或正式 Supabase 執行過這兩種模式。

## 5. 建議 8 分鐘串場

1. 打開 https://nuni.tw/demo/oral-exam，說明這是隔離租戶，不是真實靜宜帳號。
2. 學生：課表 → 繳交 → 簽到。
3. 教師：成績冊發布 82 分 → 核准病假。
4. 店家：菜單 → 備餐單標可取餐。
5. 校方：公告／行事曆／名冊。
6. 營運：只看得到 `nuni-oral-exam`。
7. 手機重複學生＋店家各 30 秒，證明 App 同一套資料。
8. 問助理卡讀出當前角色脈絡（截止日、點名、訂單）。

還原：網頁或 App 按「還原示範狀態」。
