# Demo 故事腳本 — AI 為主軸的一週校園生活

> **2026-05-17** — 設計給口委 demo 的 8~10 分鐘完整故事，串通 8 角色與 15 條動作鏈。

## 主故事：AI 主動洞察 → 推送任務 → 多角色協作

**核心張力**：AI 不是被動回答，而是「看見、想出、推給對的人」。每一個 AI 洞察都對應到一個角色的真實動作，每一個動作都會在另一個角色的視角看到「正在發生」的痕跡。

---

## 一週時間軸（demo 走場順序）

### 🌅 週一早晨 — 王小明（student）視角

**00:00 / 開場**
- 進入 `/`，AI 主動洞察卡片：「⚠️ 你借的《Clean Code》3 天後到期、線性代數小考 5 天後、3 個必修還沒選下學期」
- 點「續借書」→ AI 直接執行 `renewBook()` → 到期日 +14 天
- 點「規劃下學期」→ 跳 `/credit-planner`，AI 推薦組合（避開衝堂、補學分缺口）

**01:00**
- 看 `/timetable`：第一堂資料結構 9:10 開始。AI 橫幅：「教室 5 分鐘步行，建議搭 9:00 校車」
- 點橫幅 → 跳 `/bus`，公車 ETA 顯示

**02:00 / 進入課程頁**
- `/course/c1`：紅色橫幅「老師正在點名」（demoStore.attendanceSessions.active = true）
- 點「📍 GPS 簽到」→ 觸發 `emitAttendanceCheckedIn`（mobile）/ `markAttendance`（web）→ teacher cockpit 即時看到出席+1

### 👨‍🏫 切換角色 → 王大明老師（teacher）

**03:00**
- 進入 `/teacher/course/c1`，看到「3 份待批改作業」（demoStore.submissions filter !graded）
- 點 `/teacher/course/c1/gradebook` → 看成績冊
- 點「AI 起草評語」按鈕 → AI 為每個學生生成個人化回饋 → `draftFeedback()` 寫入 demoStore → 學生收到「老師起草了你的評語」訊息

**04:00**
- 點 `/teacher/course/c1/attendance` → 已開啟的點名 session
- 結束點名 → `endAttendanceSession()`：自動把缺席學生（多人，不再只 stu-001）通通通知

**05:00**
- 開 AI 助理 → AI 主動報告：「3 位學生連續缺席，建議發送關懷訊息」
- 點「一鍵發送」→ `bulkRemind()` → 3 個學生 inbox 同時收到

### 🧑‍💻 切換角色 → 林助教（ta）

**06:00**
- 進入 `/teacher/course/c1` TA 紫色橫幅
- AI 助理：「目前有 5 個學生在 AI 求助佇列，主題集中在『鏈結串列遞迴實作』」
- 點「批量回覆」→ AI 起草模板回覆 → `replyHelpRequest()` → 學生收到 ta 的回答

### 🎯 切換角色 → 陳社長（club_officer）

**07:00**
- 進入 `/clubs`：3 個待審入社申請
- 點「✓ 核准」→ `approveClubMember()` 用真實 club name + officer name → 申請者收到歡迎訊息
- 開 AI 助理 → AI：「下週黑客松報名只有 12 人，建議在 IG/PO 發招募文」
- 點「AI 起草招募文案」→ AI 生成 → 點「送出待審公告」→ dept_head 收待審

### 🏛️ 切換角色 → 黃主任（dept_head）

**08:00**
- 進入 `/admin`：「📥 待審公告 2 件」（陳社長剛送的 + 王老師早上送的）
- 點「✓ 核准」→ `approvePendingAnn()` + `notifyStudentsAnnApproved()` + `notifySubmitterAnnApproved()` → 學生 + 原提交者都收到
- 開 AI 助理 → AI：「本週系所掛科風險：5 個學生在資料結構 < 60 分」
- 點「發送輔導通知」→ `sendDeptBroadcast()` → 全系師生 inbox

### 🛡️ 切換角色 → 系統管理員（admin）

**09:00**
- 進入 `/admin`：使用者管理 + 安全日誌
- AI 安全分析：「過去 24h 5 次境外登入失敗 + API 突發流量 → 建議封 IP 並寄信」
- 點「執行 AI 建議」→ `disableUser()` / `lockIp()` → demoStore 寫入 + log

### 🎓 切換角色 → 張學長（alumni）

**10:00**
- 進入 `/`：簡潔校友儀表板
- 看 `/announcements`：過濾出校友活動 + 系所公告
- AI 助理：「下個月有同學會、可以申請在校成績單」
- 點「申請成績單」→ 開模板 → 寄信給管理員 inbox（demo 模擬）

### 👀 切換角色 → 訪客（guest）

**11:00**
- 進入 `/`：只看公開公告、地圖、校車、餐廳
- 點任何受限功能 → 跳「請登入」提示
- AI 助理：「我可以告訴你這個 App 的功能，或幫你引導到登入頁」

## AI 主軸貫穿全程的設計

每個 AI 開場白統一結構：
```
{角色稱呼}，{我看到的}
👁️ 洞察區（從 demoStore 即時拉）
🎯 我建議你：{動作 1} / {動作 2}（按鈕可點，按下去真的會執行）
```

範例（學生）：
```
王小明，早安！我幫你巡了一下今天的狀態：
👁️ 借閱《Clean Code》3 天後到期 ／ 資料結構小考 5 天後 ／ 學分還差 12 分

🎯 建議優先處理：
[一鍵續借書] [規劃下學期選課] [整理今日待辦]
```

範例（教師）：
```
王老師，早安！這是今早的課堂熱度：
👁️ 3 份新繳交待批改 ／ 5 位學生在 AI 求助卡關 ／ 8 號學生連續缺席

🎯 建議優先處理：
[AI 起草評語給全班] [批量發送關懷訊息] [開啟今日點名]
```

範例（系主任）：
```
黃主任，午安！系所本週掃描：
👁️ 待審公告 2 件 ／ 掛科風險學生 5 人 ／ 教師平均回覆速度 3.2 小時

🎯 建議優先處理：
[核准待審公告] [發布輔導廣播] [約談低分學生導師]
```

## demo 走場節奏建議（8 分鐘版）

| 時間 | 角色 | 動作 | 觀察重點 |
|------|------|------|---------|
| 0:00–0:45 | student | 開首頁、續借、看課表、AI 對話 | AI 洞察區、一鍵執行 |
| 0:45–1:30 | student | 進課程頁、即時點名橫幅、繳交作業 | 跨角色資料流上行（→ 老師） |
| 1:30–2:30 | teacher | 看待批改、AI 起草評語、結束點名、發批量提醒 | 跨角色資料流下行（→ 學生）+ AI 動作 |
| 2:30–3:15 | ta | TA 視角紫色橫幅、求助佇列、批量回覆 | AI 為 ta 摘要學生集體問題 |
| 3:15–4:00 | club_officer | 審核入社、AI 起草招募文案、送待審 | 第三條動作鏈 |
| 4:00–4:45 | dept_head | 待審公告 2 件、核准、發系所廣播 | 公告流閉環 + 雙向通知 |
| 4:45–5:30 | admin | 安全日誌、AI 安全建議、執行處置 | 系統視角 + AI 主動防禦 |
| 5:30–6:15 | alumni | 校友儀表板、申請成績單 | 邊緣角色也有功能 |
| 6:15–6:45 | guest | 公開資訊、嘗試受限頁面 | 權限軟擋 |
| 6:45–8:00 | 切回 student | 看訊息收件匣堆滿剛才其他角色的動作 | **故事閉環** — 一個學生看到 5 個角色在過去 6 分鐘為他做了什麼 |

最後的 1 分鐘把所有動作鏈在 student inbox 一次性呈現，是整個 demo 的高潮。
