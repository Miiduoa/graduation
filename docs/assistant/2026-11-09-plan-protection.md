# 重新規劃時保留指定提議項目

## 可用流程與保護範圍

在未執行的純行程提議開啟「修改時間或條件」，逐項勾選「保留原樣」，再輸入修改條件、重新預覽。保留的是提議內容，並非已寫入行事曆的紀錄。舊提議仍須全部安全撤銷；新提議使用新授權並逐筆手動確認。結果未知時只能先核對，不能重新送出寫入。

保護完整六個原交易欄位：title、date、endDate、allDay、startTime、endTime。比較包含選填欄位存在性與原始值，不正規化或修補簽章內容。保護相同內容的精確筆數，順序可以改變。完全相同的重複項必須整組選取；部分選取會在撤銷前阻擋，不會替使用者擴大選擇。

伺服器及前端使用同一純驗證函式各自檢查。任何指定內容遺漏、變更、增加相同內容副本、未知欄位或無法可靠對應，都拒絕整份新預覽。先扣除所有原提議的精確匹配，再檢查剩餘新項目是否與保留項目同名或有完全相同的非名稱欄位；有歧義即拒絕，不用相似度猜測。

伺服器拒絕時使用既有 proposal sequence 機制使該次新提議全部失效，再回固定 422；不釋出新 answer、cards 或 token。前端也拒絕不合格的回覆，不加入可確認卡，並記住被拒候選的 mutation ID，重試不得重用。沒有變更簽章、權限、confirm/reconcile 契約或實際行程紀錄。

## 全部保留、取消與範圍切換

全部保留不需要重新規劃：介面停用重新預覽，提供「回到原提議」，不呼叫模型、不撤銷原提議。若先前失敗嘗試已撤銷舊卡，則明示不能恢復舊確認卡，不重用失效授權。伺服器亦在模型與 bootstrap 前拒絕全選重規劃請求。

選擇與修改條件在收起、錯誤、取消核對及重試期間保留；送出期間停用欄位。新提議或帳號／學校範圍切換不繼承舊選擇，晚回覆沿既有 active/scope guard 丟棄。原生 checkbox 具唯一序號、名稱、日期及時間標籤；窄版與鍵盤由固定資料瀏覽器驗收。

## 限制及驗證邊界

- 原安排最多 16 項；修改條件最多 300 字；送往模型的完整問題仍限 1000 字。超長時在撤銷前明確拒絕，絕不截斷保護內容。
- 沒有跨次模型提議的可靠項目 ID。同名未保留項目若改動後與保留項目造成歧義，會保守拒絕；可另外規劃或調整保留選擇。
- 保證原交易內容及其精確數量，不宣稱能辨識所有「改名又改時段」的語意副本。
- 選擇是目前對話的暫存狀態；本切片沒有新增跨重新整理的草稿持久化。
- 前端瀏覽器驗收載入實際 Assistant 與樣式，使用固定假 API、帳號、學校和記憶體行程。故意不合格的 200 回覆用來驗證前端防線，不代表正式伺服器會釋出這些卡。
- 後端測試使用真實簽卡／撤銷／確認邏輯與記憶體 adapter，驗證被拒候選授權不可執行、正確新卡僅在逐筆手動確認後寫入。沒有呼叫真實帳戶、模型服務或校務抓取。
- 瀏覽器 workflow 在分支執行；完整 PR CI、CodeQL 與指定 App 5504170 審查需另行取得，不能用此測試替代。
