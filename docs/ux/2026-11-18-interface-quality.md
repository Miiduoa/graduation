# nuni 介面、動效與操作品質

## 這次解決什麼

首頁與服務頁已有真實資料及角色流程，但共用控制在不同頁面的呈現不一致：首頁弱化目前位置、手機管理者的標頭過度擁擠、按鈕背景被行內樣式固定、通知在小螢幕超出可用寬度，課務分頁也可能把目前頁藏在捲動區外。

本輪以 `main` 的 `6b0dbe30ac788742658f7a134d0be5f61bdbb230` 為基礎，完成 Web 與手機瀏覽器的共用介面調整。角色工作流 #627／#672 另有進行中的變更；本輪保留 main 的入口、授權與資料來源，不將那些分支的完成度算入本輪。

## 設計決定

| 範圍 | 改變後的體驗 |
| --- | --- |
| 首頁 | 課表、待辦與通知有一致的實色分組；既有排序決定的下一堂課／優先作業有清楚底色，仍保留文字狀態。響應式標題同時套用站內字級偏好。 |
| 全站基礎 | 保留灰綠品牌、系統字體與 OLED 深色；統一間距、字級層級、圓角及動效時間變數，瀏覽器工具列與離線頁同步採用新版亮色背景。 |
| 主導覽 | 首頁與服務頁沿用同一個目前位置標示；手機導覽保留文字及可觸控範圍。 |
| 帳號入口 | 登入後以「帳號」收納原本的個人頁、平台管理及登出；管理入口仍依伺服器 session 資格呈現。 |
| 浮層 | 語音、帳號、選校與服務選單互斥；點外部、離開焦點或切換頁面時關閉。語音面板依頁首實際高度配置可用空間，保留頁首入口與手機底欄。明確關閉與 Escape 回復觸發鈕焦點；輸入法組字中的 Escape 保留。 |
| 課務導覽 | 目前分頁及鍵盤聚焦的項目自動保持在該列可視範圍，只調整橫向捲動；320px 下匯入動作另列。 |
| 共用按鈕 | 使用樣式表處理外觀，hover／按壓不再被內建行內樣式覆蓋；保留原 props、ref、className 與外部 style 相容性。 |
| 通知 | 長內容可換行，手機底部避開固定導覽；關閉鍵至少44px，通知有輔助技術語意，滑鼠或焦點進入時暫停倒數，離開後使用剩餘時間。 |
| 行程修改 | 保留原生 Tab 順序；焦點移到原本已可讀的控制項時保持閱讀位置，真正被輸入區遮擋的控制項才補償捲動。 |

動效參數是本專案的選擇：短回饋140ms、一般切換200ms，僅對操作結果或層級變化使用。系統 `prefers-reduced-motion` 和站內減少動態偏好均保留；高對比模式使用可見邊框與系統色。沒有新增動畫套件、持續裝飾動畫或逐張卡片延遲進場。

## 驗證範圍

- 使用專案指定 Node 22.23.5、pnpm 10.28.2 與原鎖檔套件。
- `AppHeader`／既有服務選單驗證登入返回、帳號入口、登出與重試、浮層協調、路由及帳校切換。
- `AcademicNavigation` 驗證原有 href／校園／學期參數，以及局部捲動、字級變化、焦點及 observer 清理。
- `Toast` 驗證狀態語意、通知獨立期限、hover／focus 暫停、常駐通知、數量上限及清理。
- 原有首頁課程與待辦測試持續驗證資料順序及連結，不以版面改動替換原業務契約。
- 既有實際瀏覽器檢查持續驗證站內大字偏好，以及行程修改時的鍵盤焦點與輸入區遮擋；修正產品，不降低字級或捲動驗收門檻。
- `scripts/qa/interface-design/` 使用實際產品元件與 CSS，將帳號、校園、HTTP 與 Next 路由邊界替換為合成測試來源；輸出截圖、檢查結果及來源 SHA-256。所有合成畫面均不代表正式帳號驗收。
- 全站 Web 型別檢查、production build、變更檔 ESLint、UI design gate 與差異格式檢查。各結果以對應提交的 PR 紀錄及 Actions 為準。

本輪未修改原生 App，沒有進行真人帳號或正式寫入測試；瀏覽器截圖不能取代 iPhone／Android 實機與 Safari 驗收。合併與正式發布仍遵循儲存庫既有的 main 合併閘門，包含指定 App 的「審查通過」。

## 參考

Apple 的設計指引用來協助判斷層級、導覽連續性與有目的的動效；nuni 保持自身品牌及跨平台操作方式。

- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：透明效果集中在導覽／控制層，內容維持清楚可讀。
- [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：短促、有目的、可中斷的動效與減少動態支援。
- [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)：穩定的主要目的地、明確標籤與目前位置。
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：文字、對比、觸控與不同輸入方式的可用性。
