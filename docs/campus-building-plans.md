# 建築平面圖與樓層預覽

校園空間導覽以真實地點座標顯示建築的相對位置。建築圖面預覽則使用獨立的平面幾何資料，讓使用者檢視房間、樓板與牆面，並切換單層、整棟與分層視角。

靈感來源：[平面圖轉建築圖示範](https://www.instagram.com/reel/DfbqRrZBnFJ/)。原作者明示範例平面圖為虛構，本功能也不將示意模型當作正式校園圖資。

## 操作

1. 在地圖開啟「空間導覽」，選擇一個地點。
2. 開啟「平面圖建模預覽」。這會替換目前對話框，關閉原來的校園 3D 場景。
3. 選擇「從圖片建立圖面」，或載入清楚標示為虛構的範例；也可下載目前學校／建築對應的 JSON 範本。
4. 從圖片描點或匯入 JSON 後，資料只在瀏覽器記憶體內使用，不上傳、不建立校園地點。按「下載目前圖面」可保存預覽模型；在描圖畫面按「下載編輯檔」則連底圖與未完成描點一起保存，下次用「開啟編輯檔」繼續。
5. 用平面圖或房間清單選取房間，也可搜尋房名或樓層；切換立體畫面可查看樓板、牆面與樓層分離。

目前支援圖片手動描圖及結構化 JSON，**尚未提供照片／PDF 自動辨識或雲端保存**。所有圖面均為待核對資料；提供來源網址、設定比例或自行加入 `verified` 欄位都不會變成已驗證資料。

## 從圖片建立圖面

這個入口適用各校，建立單張圖片中的單一樓層。圖片以 PNG／JPEG／WebP 為限，最多 10 MiB、解碼前原圖最多 2,400 萬像素；瀏覽器解碼並重新輸出成最長邊 2,048px 的 PNG，原檔不會上傳。SVG、PDF 與無法解碼的檔案不會當作底圖。

1. 選擇平整、清楚的平面圖圖片，填寫圖面與樓層名稱。透視拍攝的照片可能失真，尚無透視校正。
2. 沿樓層外框依序點按至少 3 點，再按「完成外框」。最後一條邊自動閉合，不需重複第一點。每個外框或房間最多 64 點。
3. 按「新增房間」，填入名稱並描出房間範圍。可改名、移除房間、返回上一步或重畫；也允許只描外框、不建立房間。房間可重名，識別碼仍各自獨立。
4. 不方便點按時，可在圖片使用方向鍵移動準星（Shift 加速）及 Enter／空白鍵加點，或輸入水平／垂直百分比後按「加入描點」。觸控保留原生垂直捲動及 pinch zoom；垂直捲動不應新增描點。
5. 若無可信尺寸，直接建立預覽；圖面以 `units: "relative"` 表示未校正比例。完整圖片的長邊為 20 示意單位、預覽樓高為 3 示意單位，保留圖像長寬比，不表示實際公尺或方位。
6. 若有可靠的已知距離，可選兩點校正，輸入公尺距離及 1–10 公尺的樓高，再套用比例。校正點以圖片像素距離計算，至少相距圖片長邊 0.5% 且至少 2px；可選在外框外的圖片尺寸標線。樓高不從平面圖推測。
7. 按「建立立體預覽」。資料經相同幾何驗證後進入 3D；外框產生示意牆面，房間表示命名區域，尚未建模門窗或通行連接。

完成後可「返回圖面編輯」，保留本次底圖與描點，再次建立預覽。取消編輯會丟棄描圖草稿並保留上一份已完成圖面；換圖或重畫外框會清空舊描點與比例。改匯入 JSON、載入範例、清除、切換學校／建築或關閉時，會中止晚到讀檔並回收底圖 URL。

「下載目前圖面」保存範圍、房間、單位與來源標示，**不包含底圖圖片或已驗證宣告**。匯出後重新匯入仍保留 `relative`／`m`，不會把未校正圖面改成公尺。若要關閉後繼續編輯原圖，請另外保存編輯檔。

## 保存與重新開啟編輯檔

在描圖畫面選擇「下載編輯檔」，即可取得 `building-plan-project.json`。即使外框、房間或比例校正尚未完成，也能保存目前步驟；檔案包含已處理的 PNG 底圖、圖片比例座標、已描房間、尚未完成的描點、名稱、來源與校正欄位。正在修改而暫時空白的文字或數字會保留，重新開啟後仍需完成原有驗證才能建模。

重新開啟時，先選擇相同學校與建築，再按「開啟編輯檔」。驗證成功後進入描圖畫面，不會自動建立模型或產生導航目的地。讀取期間保留原草稿；可「取消開啟」返回原內容，壞檔與跨校／建築檔不會取代現有圖面。讀取期間原描圖區暫停操作，避免未完成的開檔結果蓋掉新的描點。

| 下載項目 | 重新使用方式 | 包含內容 |
| --- | --- | --- |
| 目前圖面 `building-plan.json` | 「匯入 JSON 圖面」 | 預覽模型、房間、單位與來源；不含底圖或編輯步驟 |
| 編輯檔 `building-plan-project.json` | 「開啟編輯檔」 | 底圖與可續編草稿，包含未完成描點及原始校正輸入 |

編輯檔上限為 16 MiB，其中 PNG 底圖最多 10 MiB、長邊最多 2048px，文字與描點 metadata 最多 256 KB。格式為 `nuni.building-plan-project`、版本 1；scope 必須與當前學校及建築完全一致。檔案不保存 object URL、已驗證宣告、導航資料或執行內容，也不會自動存到瀏覽器資料庫或雲端。

匯入會先檢查檔案大小、版本、scope、描圖狀態與 PNG 標頭尺寸，再重新解碼並輸出 PNG；尺寸不符或不能解碼時拒絕。已完成的外框／房間沿用相同幾何驗證，未完成的描點保留供修正。資料會重建為已知欄位，額外欄位不會還原。另存失敗時仍保留目前草稿，只有使用者選取的新編輯檔驗證成功後才替換目前內容。

## 在圖面內找房間

「搜尋圖面房間」依目前圖面的房名與樓層搜尋，支援全形字元、大小寫與以空白分開的多個條件。查詢期間會搜尋所有樓層；即使兩層有同名房間，也會各自列出樓層，直到使用者選擇才切換樓層並同步平面／3D 選取狀態。

清除搜尋後回到目前樓層的清單，保留選取並把鍵盤焦點交回搜尋欄。換圖面或切換學校／建築會清除舊查詢。這個搜尋只讀取本次圖面的命名區域，不修改校方 POI、課表教室解析或 Google 步行導航目的地；待核對圖面的命中不代表正式教室定位。

## 圖面格式

```json
{
  "version": 1,
  "schoolId": "example-school",
  "buildingId": "example-building",
  "name": "單層格式範例",
  "units": "m",
  "source": { "label": "虛構格式範例" },
  "floors": [{
    "id": "floor-1",
    "label": "1F",
    "elevation": 0,
    "height": 3.4,
    "outline": [[0, 0], [12, 0], [12, 8], [0, 8]],
    "rooms": [{
      "id": "room-101",
      "name": "範例教室 101",
      "polygon": [[1, 1], [5, 1], [5, 6], [1, 6]]
    }],
    "walls": [{ "start": [0, 0], "end": [12, 0], "thickness": 0.2 }]
  }]
}
```

- `schoolId`、`buildingId` 必須與當下地點精確相同；下載的範本會帶入這兩個值。
- `units` 接受 `m` 或 `relative`。平面座標 `[x, y]`、標高 `elevation`、樓高 `height`、牆厚 `thickness` 都使用同一圖面單位。`m` 是圖面宣告的公尺單位，並不代表已測量或核實；`relative` 明確表示未校正的示意單位。
- `[x, y]` 是圖面自身的平面座標，**沒有地理北向資訊**；不可據此推算日照或校園導航方向。
- 多邊形依輪廓順序列點，不重複最後一點。房間代碼須在整份圖面唯一；樓層依標高排列，不可互相重疊。
- `rooms` 只表示圖面上的命名區域，不會自動判定用途、可通行範圍、無障礙動線或真實教室代碼。
- `walls` 可省略。每段牆使用起點、終點與厚度；需要開口時在資料中分成不相接的線段。現階段不建模窗戶、斜屋頂、樓梯踏階或樓板孔洞。
- 立體畫面以剖視方式將牆高截短至最多 1.2 個圖面單位，方便查看房間；這個顯示高度不代表真實牆高。組合樓層時只標示最上層的房間，其他房間仍可由樓層選單與清單選取。
- `source.url` 可省略；提供時只接受無帳密的 HTTPS 網址，標示為匯入者提供的來源。

資料校驗會拒絕格式錯誤、跨學校／建築、不支援的單位、自交或退化多邊形、超出外框的房間與牆線、無效高度及過大的圖面。檔案上限為 256,000 bytes，最多 12 層、200 個房間、512 段牆；每個多邊形最多 64 點，平面範圍最多 300 × 300 個圖面單位。這些上限用來限制本機解析與繪圖成本，不是實測性能保證，也不驗證房間間的重疊或建築通行語意。

## 顯示與資料邊界

平面 SVG 與房間清單不依賴 WebGL。Three.js 場景只在使用者開啟立體視圖後載入；畫面變動時才繪製，閒置沒有持續動畫。關閉或切換資料會清理 GPU 資源；背景／離開可視區暫停繪圖，WebGL 失敗時可回到平面操作。

本功能不讀取原有 `apps/mobile/src/data/indoorMaps.ts` 的示意房間，也不改動課表教室解析、官方地點、步行導航或手機樓層摘要。房間選取只影響預覽，尚未連到 AI 工具或實際室內定位。

## 下一階段的可驗證接點

1. 圖片自動候選／PDF 單頁底圖：在現有手動描圖與核對流程加入辨識候選，保留來源、取消與人工修正；不將既有課表文字辨識端點當作通用幾何模型。
2. 經核對的教室對應：使用明確 `schoolId + buildingId + floorId + roomId`，讓課表與 AI 選取既有房間；未知或多義時保留原文或候選。
3. 通行圖：另行蒐集出入口、走廊、樓梯、電梯與連通資訊，並獨立驗證可通行／無障礙路線。建築可視化不等於導航資料。
4. 日照：另需地理位置、真實北向、日期時間、建築及周邊遮蔽物，才能估算採光；不可只根據平面圖給出準確日照結論。

驗證結果應以本次實際執行與 GitHub 對應 commit 為準，不沿用 PR 先前版本的 CI 綠燈。

資料與 UI 回歸位於 `apps/web/src/app/map/buildingPlans/*.test.*`；原本空間導覽的整合測試也涵蓋進入／離開建築預覽與地點撤回。`scripts/qa/campus-spatial/building-check.py` 在正式元件 fixture 中驗證真 WebGL、分層／鍵盤選房、閒置停止繪圖、320px 版面、context loss、跨校匯入拒絕，以及真 PNG 解碼、圖片點擊／鍵盤描點、比例校正、匯出重匯入、原生觸控垂直捲動與底圖清理。編輯檔與房間搜尋案例另涵蓋下載後重新載入頁面再續編、保留未完成房間與校正資料、壞檔不覆蓋，以及跨樓層同名候選的明確選取。圖片與圖面全為明確標示的虛構測試資料，不作為校園房間定位證據。

沒有可靠的尺寸標線或現場量測時，保留 `relative`；不使用平均教室坪數反推這些圖面的比例。正式教室定位仍需獨立完成現況、房號與通行資料核對。


## 平面圖 SVG 匯出（2026-11-09）

載入或描圖完成後，可按「下載平面圖 SVG」，將目前樓層篩選匯出成可縮放、可列印的向量圖。選擇「全部樓層」會縱向排列所有樓層；選擇個別樓層則只輸出該層。圖中包含已描外框、標記房間、牆線與使用者輸入的來源名稱；不包含原始圖片、外部網址與可執行內容。圖面會明顯標示「待核對」與比例狀態，不能拿來宣稱真實教室位置、通行路線或已確認尺寸。保存可繼續編輯的底圖仍應使用「下載編輯檔」，不是 SVG。

## 平面圖 PNG 匯出（2026-11-09）

需要放入簡報或分享圖片時，在預覽的「PNG 圖片匯出」選一般（1 倍）或清晰（2 倍），確認目前樓層與實際像素尺寸，再按「下載平面圖 PNG」。預設清晰；兩層範例為 1920 × 1676 px，單層為 1920 × 976 px。全部樓層縱向排列，單層只輸出目前選取樓層；圖面／樓層名稱沿用 SVG 的安全命名規則，副檔名為 .png。

PNG 保留淺色背景、中文標籤、來源名稱、未校正／待核對提醒；不包含底圖圖片、來源網址或可執行內容。整個轉檔在本機瀏覽器完成，不呼叫付費或外部圖片服務。它是供檢視分享的圖片，不能當作已驗證校園圖資，也不能回匯續編；續編仍使用模型 JSON 或編輯檔。

轉檔期間顯示進度並停用重複匯出，可按「取消 PNG 匯出」。切換圖面、樓層、開啟描圖或關閉預覽會取消尚未完成的工作；晚到結果不會下載。只有 PNG 編碼完成並送交瀏覽器後才顯示下載交接訊息，這不表示已確認使用者儲存到磁碟。失敗或逾時會顯示重試／單層／SVG 的替代操作。

為限制瀏覽器影像記憶體，PNG 長邊最多 4096 px、總像素最多 4,000,000；大圖會等比例縮小並明示實際尺寸。需看清多層文字時可改選單一樓層。匯出只將產品自行序列化的靜態 SVG 轉為 PNG，先調整解碼尺寸，不載入使用者 SVG、底圖或外部資源；成功、失敗、取消及15秒逾時都清理 Image、canvas 與暫存 URL。

對照 [draw.io 官方 PNG 匯出](https://www.drawio.com/docs/manual/export/export-to-png/) 與[高解析度指引](https://www.drawio.com/docs/manual/export/export-higher-resolution/)，本切片補上 PNG 與像素倍率，但尚無透明背景、任意寬高／裁切、任意圖形選取或內嵌續編資料。樓層篩選不同於 draw.io 的 Selection Only。沒有實測投影片軟體、列印、Safari／真機或相同任務的競品對測，不宣稱超越競品。

回歸分為 renderer／UI 的模擬故障單測，以及 png-download-check.py 的實際 Chromium 原生下載、PNG標頭與解碼尺寸、非空白／不透明像素、不同樓層及320px畫面。取消／晚到編碼與編碼失敗另標為注入故障。全部使用明示虛構的圖面與正式元件 fixture，結果須以對應 commit 的 CI 產物為準。
