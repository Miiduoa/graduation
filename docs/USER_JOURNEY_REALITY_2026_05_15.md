# 使用者旅程模擬：3 個角色，1 週真實使用節奏（2026-05-15）

> 目的：跳脫 demo 思維，誠實模擬「真實學期、真實一週」這個 app 會被打開幾次、打開哪些頁、什麼時候會被棄用。
>
> 假設：學期週次 W11（學期中），台灣大學部，靜宜資管系，週一到週日。
>
> 圖例：✅ 真實會用 / ⚠️ 部分會用 / ❌ 不會用 / 🆕 新需求未實作

### 週一 14:00-17:00 — 連續 3 堂課

| 時間 | 場景 | 真實會用 |
|------|------|---------|
| 18:30 | 打開 app 看「今天該做什麼」 | ✅ Today cockpit + focus CTA「下一個任務：機器學習 HW3、預估 90 分鐘」 |

**真實峰值在這個 timespan**：晚上 19-22 點是 app 唯一真實高頻使用窗口。所有「打開後想看到的」都該設計在這時段優先。

## 跨角色觀察

### 真實情境下「打開 app 的最大動機」按頻率排序

1. **被動推播打開**（老師 → 學生：50% / 學生 → 老師：20% / 餐廳：30%）  
   ✅ **這條最有戰略價值** — 因為我們已經建好 RoleEventBus
2. **晚上 19-22 點主動規劃**（學生 25%）  
   ✅ Today cockpit + focus CTA 是對的
3. **工作時段批量處理**（老師 60%）  
   ✅ TeacherCockpit 是對的
4. **用餐時段操作**（餐廳 95%）  
   ✅ VendorDashboard 是對的
5. **學期關鍵節點**（期中考前 / 學期末）  
   ✅ GradeWhatIf 對學生、批改密集對老師

### 真實情境下「絕對不會打開」的場景

- ❌ 上課中（學生）
- ❌ 上課中老師看手機（老師）
- ❌ 用餐尖峰看 dashboard 圖表（餐廳）
- ❌ 週末晚上（所有角色）

## 結論：5 個對應真實情境的 design adjustments

### Adj 1：把 quiet hours 從靜態時段改成「動態課表 + 用餐尖峰」
目前 `aiSkillApplicator` quiet hours 寫死 22:00-08:00。  
**真實需要**：根據每個 uid 的課表 + 角色行為模式動態計算「現在能不能推播」。  
**實作量**：低（讀課表 + 加 helper function）。

### Adj 2：把「即時求助」做成新核心功能
目前學伴配對是「學期初找隊友」（低頻）。  
**真實高頻情境**：晚上 21:00 卡關，想找「現在誰能解這題」。  
**實作**：matchStudyBuddies 加參數 `requireOnlineNow` + 串 roleEventBus 的 `help_requested` 事件。預估 1 天。  
**ROI**：把學伴配對的使用頻率從 1 次/學期 → 1 次/週。

### Adj 3：AI 起草評語接該老師過去評語風格學習
目前是 hard-coded template。  
**真實需要**：每位老師有自己的風格（嚴格 / 鼓勵 / 條列式）。  
**實作**：feedbackDrafter 加 input `pastDraftsByThisTeacher`，retrieve top-K 範本，prompt 加 few-shot。

### Adj 4：餐廳 AI 建議從「下一步」升級到「預測」
目前「該補貨」之類的建議老闆早就知道。  
**真實 ROI 來源**：「上週同時段你賣 X 份，今天目前少 30%、預計下午會回升到 Y」這種預測。  
**實作**：cafeteriaData 加 weeklyPattern 計算，AI 拿這個做 prediction-style 建議。

### Adj 5：刪除「上課中」/「用餐尖峰」推播
目前 proactive scan 每 15 分鐘掃 — 在上課 / 用餐尖峰會打擾。  
**實作**：scanForStudent / scanForVendor 加 `currentStatus` 判斷，這時段返回空陣列。

## 一句話總結

> Demo 看起來很豐富，但真實情境下**整個 app 的核心價值集中在 4 個動線**：
>
> 1. 老師動作 → 學生 inbox 即時聯動（RoleEventBus，**最大護城河**）
> 2. 學生 19-22 點 Today cockpit + focus CTA（**最高頻使用窗口**）
> 3. 老師 AI 起草評語 + 預測補交率（**老師端唯一不可取代**）
> 4. 餐廳訂單佇列推進（**餐廳端唯一不可取代**）
>
> 其他功能 80% 在學期內被打開次數 < 3 次，或是被 LINE / Google Maps / ChatGPT 取代。
>
> **下一步建議**：與其再加 N 個新功能，不如把這 4 個動線打磨到讓「使用者第一次用就回不去」。
