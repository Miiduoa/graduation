## 本 PR 已實作：Spec PR 1 的唯讀 UI（不含入社）

- Web 社團入口與手機既有「群組」入口提供「我的社團｜找社團」，搜尋自己的社團名稱（Web 也搜尋介紹），從真實會籍開啟社團頁。
- 「找社團」尚未有已串接、課外組核可的資料來源，固定顯示「學校還沒提供社團名單。」不把一般群組當成核可社團，也不顯示假資料或「本校社團」徽章。
- 社團頁依序呈現頁首、已加入狀態、近期活動區、真實公告、介紹。資料僅供原本有讀權的成員閱讀；公告取既有最近 20 則討論中的最新 3 則，不捏造未讀數、類別、社課時間或外連。
- 社團內部活動尚未接入可用的正式讀取服務，使用鎖定空態「目前沒有排定的活動。」並緊接說明尚未串接、實際排程須向幹部確認，避免誤認為已查完活動。此為呈現區塊，並非已確認沒有活動。
- 未加入顯示「還沒加入社團，可以到「找社團」看看。」；管理狀態顯示「這所學校還沒開放社團管理。」。不新增管理操作。

## 後續超越點與資料界線

學號入社、申請與邀請碼政策屬於身分及權限工作，隔離至後續 PR，必須取得 owner 的「上」。本次沒有實作或改動加入、角色、ACL、規則、migration，也不新增介紹寫入。既有一般群組流程保持原樣，不視為正式社團入社。

群組文件只有有效成員可以讀取；目前沒有可辨識來源並供學生讀取的課外組核可目錄契約，因此無法以現有群組查詢實作正式全校名錄。校方與平台人員不因本頁取得跨社團讀權，沒有假管理後台。資料串接後才可補學校類別、招新狀態與社課時間；現階段不自行定義核可欄位或推論正式身分。

社團內部活動 `groups/{id}/clubEvents` 和校級活動 `schools/{id}/clubEvents` 是分開的資料層；不得用校級活動填補內部活動。本 PR 不查詢、合併或寫入這兩層，也不做「發布到校園活動」。活動、簽到屬 Spec PR 2，交接、匯出與課外組屬 PR 3。

依使用者提供的 2026-11-14 正式環境查核：campus-one-tw 是 Spark，clubAdmin／clubRoster 兩個區域均回應 404，不能假定 Cloud Functions 可用。不更改試辦旗標、不部署或升級；本次新增頁面不呼叫這些服務。後續如需後端，應在 nuni-web 實作並另行審查。

競品提出的集中報名／簽到、權限交接與評鑑匯出仍是後續目標，本 PR 不宣稱已交付。

## 審查修正：保留既有操作

Web「我的社團」共用原有群組操作，保留邀請碼加入、確認退出、擁有權轉讓，以及既有旗標開啟時的社團後台入口。這些是原有功能的還原，沿用既有服務與驗證；本 PR 不新增入社政策、交接服務或後台權限。「找社團」仍只顯示校方名單未串接的空態。手機流程不變。
