# 助理直接回答資料與建立行程

## 這次解決的使用問題

課表頁能看到資料，助理卻要求再開課表；明確問未繳作業時，模型可能沒有查詢就結束；已指定日期、起訖時間與名稱的行程，還可能被當成一般讀書規劃，換成另一份作業。

這次從主線 `290266962992d5d776a952923c3327b78b1b2b57` 分支，補齊三條可核對的流程。

| 使用者說法 | 處理方式 | 完成依據 |
| --- | --- | --- |
| 我今天有什麼課／下一堂課在哪裡 | 先整理目前帳號、目前校園在此瀏覽器保存的課表、匯入紀錄與單次調整；本機沒有來源且已同意雲端查詢時，繼續讀取同步資料 | 回答課名、實際記錄的時間、教室及來源 |
| 今天還有什麼作業沒交 | 讀取目前可存取的課程作業與測驗；列出接下來七日的待繳、同期間已逾期與尚未填期限的項目 | 提供實際標題與截止時間；未查完的課程另行標示 |
| 明天有哪些行程 | 讀取裝置上的個人事件；沒有事件來源且已同意時，讀同步個人行事曆 | 列出事件名稱與時間，區分個人事件與上課時間 |
| 幫我明天 19:00 到 20:00 安排英文讀書 | 保留明確日期、時間與名稱，走原有行程衝突檢查與簽章確認卡 | 確認前沒有寫入；確認後由既有流程儲存、讀回並核對回執 |

## 執行方式

明確的課表、下一堂課、個人行程與待繳問題，先讀取對應來源，再直接整理回覆，不必讓模型再次選擇要不要查，也不會用「請開啟相關頁面」替代結果。這些明確查詢不呼叫模型；較複雜或不明確的需求仍交由原有流程處理。

明確單筆行程使用與手機相同的解析器。解析器移至 `packages/shared/src/assistantCalendarIntent.ts`，手機原路徑保留 re-export，既有呼叫端不需改動。只有完整的日期、起訖時間與單一事件符合這條直接處理流程；否定、引用、複合操作或缺少時間的需求不會被誤當成建立指令。

## 資料與操作範圍

- 裝置查詢使用既有帳號／校園儲存範圍。切換身分或校園會清除原本的裝置回答；本機讀取結果不加入後續雲端對話歷史。
- 課表仍是已保存的週課表與已記錄調整，不代表未記錄的停課或補課。答案會標示來源、學期、資料不足與裝置讀取時間。
- 未讀到課表、來源損壞、時段無法定位或部分課程讀取失敗，都不能當成「沒有課／沒有作業」。
- 雲端查詢保留 session、校園範圍、API 預算、取消訊號與原有同意流程。課程讀取只使用目前帳號本來就可存取的資料。
- 建立行程保留原寫入開關、HMAC 確認卡、身分／校園綁定、revision 檢查、衝突驗證及讀回回執。重送同一張確認卡不重複新增。
- Google 助理權限 PR #583 另有自己的合併與部署範圍。本修補不依賴其尚未合併的 API，並保留權限拒絕／權限服務不可用時的明確回覆。
- 圖書館目前接通的是既有入口與官方導覽來源；本次沒有新增即時開館時間來源。訂餐沿用原有下單與付款條件，本次沒有開放原本未啟用的訂單寫入。

## 驗證

新增回歸涵蓋實際資料回覆、下一堂與跨日日期、未繳／已繳／無期限作業、部分來源失敗、本機課表與補課、跨帳號／校園隔離、來源損壞、雲端歷史排除、本機無資料交回雲端、明確行程確認、回執、重送、取消、關閉寫入與權限錯誤。

以合成帳號與 fixture 執行操作驗證，不連正式學生帳號或送出真實訂單。實際執行結果與精確提交的 CI 狀態應以 PR 記錄為準；合併仍必須通過主線既有的 `nuni-merge-gate` 檢查。
