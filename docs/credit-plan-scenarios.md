# 學分修課方案比較

## 操作流程

在 Web 學分規劃與手機「未來學分規劃」的進度分析區，展開「換個修法，先看差多少」。以全部課程或「只修手動標示已選課」開始，逐門指定不排入或移到未來第 1–8 學期。畫面並排顯示原規劃與比較方案，包含總學分缺口、分類缺口、學期負擔及條件式總量達標學期。

搜尋和學期篩選只改顯示的課程，不改比較計算。每次先顯示 12 門，再按「顯示更多」。原規劃更新時，舊比較失效，需重新開始；不將舊版本套到新資料。

比較只留在畫面記憶體，不改已儲存規劃、正式成績或選課。要保存替代方案，可明確按「匯出此比較方案 JSON」，透過既有 JSON 匯入預覽及確認流程採用。這是手動備份移轉，不是雲端自動同步。離開頁面前須自行匯出想保留的比較內容。

## 計算邊界

- 已確認學分、總目標、其他預計學分、課程學分與狀態、分類門檻及非學分條件全部沿用原值；只有課程是否排入及未來學期不同。
- 已選課仍為手動標示且未取得；不排入不代表退選、停修或不及格。
- 達標學期只加總已排定課程，不把未指定學期的其他預計學分塞進時間軸。不代表已驗證的畢業日期。
- 不推定正式開課、先修、跨系抵免或重修採計。重複名稱保留警示，25 學分只作負擔提醒。
- 缺少目標時顯示未設定，不顯示 0 缺口；移除最後學期的課不會擅自縮短原規劃期間。
- 手機分享前再次檢查來源版本與元件有效性，A→B→A 不復活舊分享。分享程式不可用或寫檔失敗不回報成功；未交出去的暫存檔清除，交給接收端的檔案交由系統快取管理。

## 測試

新增共用核心 Vitest、Web 元件 Vitest 與手機元件 Jest；覆蓋排除／移動、分類與小數、未設定目標、無效學期、過期基準、JSON 相容性、篩選不改加總、資料不可變、分享中離頁及失敗重試。

本機對來源 SHA 已核對的 creditPlanner/creditPlanInsights 與新核心執行 strict TypeScript；另有 1,200 組固定種子資料、14,412 個 Node 斷言通過。這不是完整專案 typecheck、React 測試或原生驗收，完整 CI 必須核對本次提交，不能沿用 #299 的成功。

## 競品比較的驗收原則

2026-10-27 查核的 UniTable 官方介紹（https://unitableapp.com/）列出課程、作業提醒、桌面小工具、帳號跨裝置同步與同步衝突保留；這些是官方功能描述，不是本次實機測試。不可把個人 JSON 備份說成已超越其自動同步，也不能因官方頁面未提及某功能就斷定競品沒有。

本功能可驗收的是「同一份已儲存規劃在兩平台採用相同公式，比較移動與排除課程的差異，不破壞原資料」。全面競爭力仍須另行驗證真實校務資料接入、正式系所年度門檻、跨裝置同步、真機效能及使用者完成任務的成本。沒有以新增檔案或測試數宣稱全面超越。
